# Premise check of rows 447 to 450 (2026-11-13)

A read-only pass (Sonnet) over the four phase 0 rows that follow rows 446 and 509, against the tree that holds rows 446,
509, 451, 454, 511, the first half of 448 and the rest of 436. Nothing was built or run: every statement is read from
the source. The rows were written on 2026-10-26, before the decision kernel and the witness harness existed. A lane that
builds one of these rows reads its section here first; where this note and the row disagree, this note describes the
source and the row's intent stands unless the section says the construction changes.

## Facts all four rows share

- Row 446's page side is `primitives/ts-test/witness.ts`. Under `playwright/witness/` are the probes, the bindings
  (`input_otp.filter`, `executor.exit_wait`, `executor.watchdog`), `otp-filter.spec.ts` and
  `executor-internals.spec.ts`. Both specs call `witness(probe, site, effect)`.
- `primitives/src/ts/behaviours/sites.gen.json` does not exist; `playwright/witness/sites.ts` reads it as an empty
  list and names row 448 as the generator's owner. The pre-authored witnesses stay `test.fixme` until it exists.
- Rust has no `site!` macro, no `Site` type and no `site` field on `Behaviour`; in `ts/bridge.ts` a missing site falls
  back to the kind name.
- A file under `primitives/src/ts/` that is not in `lib/` or `types/` is a bundle entry, and five gates read all of
  `primitives/src/`. A module that never ships (a spike, a harness, a perf recorder) goes under `primitives/ts-test/`
  or `playwright/`.
- A grant needs a column per kind of growth: `js_file_bytes` for the bundle, `bytes` for TypeScript source the bridge
  budget counts (`ts/bridge.ts`, `ts/lib/*`, `types/bridge.d.ts`, a behaviour adapter), `js_lit` and `sink` for
  Rust-side counts, `gzip_bytes` for the decision kernel. The four rows carry `js_file_bytes` only.

## Row 447, the order runtime

True as written: `Epoch::next` is a process-global counter (`bridge/mod.rs`); the doc line that routes agents to
`MountedData::set_focus`; `FORBIDDEN_VERBS` in `scripts/check-bridge-behaviours.sh`, whose comment expects this row's
slot table; `playwright/hydration.ts` waits for `html[data-hydrated="true"]`; the scheduler form of
`__dxBridgeDelayFrames` in `ts/bridge.ts` is the order counterfactual this row expects from row 446.

False or moved:

- `lib.rs:205-218` is `use_unique_id` near `lib.rs:193-206`.
- There is no `data-dx-bridge`. `data-hydrated` is set by `preview/src/main.rs` through `document::eval`. The bridge
  boots lazily from `transport.rs` (the READY handshake and `kernel_load`), while the row says "no liveness
  handshake".
- `ts/bridge.ts` already has a function named `pump` (the page-side write channel); the inbound pump needs another
  name.
- Row 509 built part of the pump invariant: `Subscription` holds a `receiver` task that `Drop` cancels, and
  `use_behaviour` reads `Inbound<T>` and tears the install down on a stand-down.

The construction changes in three places:

1. The pump, the `(scope, nonce)` epochs and `based_on` replace `Epoch::next` in `use_behaviour` without undoing row
   509's rule that a stand-down tears down and is not resynced.
2. `scroll_classifier.ts` does not go under `primitives/src/ts/`.
3. The slot-write verdicts feed both `FORBIDDEN_VERBS` and the `APPLY` table of `ts/bridge.ts`.

Grant columns: `js_file_bytes` and `bytes`; `sink` or `js_lit` only if the boot stays an eval in
`preview/src/main.rs`. Size: about 20 h is still plausible, nearer 22 to 26 h with the reconciliation. The classifier
spike runs on Chromium only here.

## Row 448, second half: the `otpFilter` behaviour

False or moved:

- `ts/behaviours/otp_filter.ts` does not exist. S11 is an inline script string in `input_otp.rs` (`use_js_listeners`,
  a `beforeinput` capture listener and an `input` listener).
- `bridge/behaviours/mod.rs` and `bridge/behaviours/otp_filter.rs` do not exist; `bridge/behaviours.rs` is one file
  with one variant, `Fixture`.
- The registry macro is `kinds!` in `decision-kernel/src/kinds.rs`: a kind is `decision-kernel/src/<kind>.rs` plus
  one `kinds!` line.
- The vectors are one file, `primitives/conformance/behaviours.json`, run by `decision-kernel/tests/vectors.rs`.
- The dialog, alert-dialog, popover, menu and `lib.rs` entries of "files owned" belong to the finished first half.

The construction changes:

1. `Decision` has no value-write effect (`decision-kernel/src/decision.rs`: prevent, stop, attrs, send, remember) and
   `APPLY` has prevent, stop and attrs. The kernel, the wire and the adapter need a value-write effect (a range text
   and a re-dispatched `input`). It is a native-slot write, so it goes through row 447's value owner and slot table.
2. The adapter listens to `beforeinput` and `input`. `Behaviour` has one `event` per variant and a second install of a
   kind on one target replaces the first: two kinds, or one kind that handles both events.
3. `OtpPattern::ranges()` is closed and Rust-side, so the kernel's `Config` carries ranges, not a script regex.
4. The binding row 446 pre-authored is `input_otp.filter`; `insertFromPaste` and `insertReplacementText` belong in
   the `Event` fields.
5. The `site!` literal scan and the generator of `sites.gen.json` are this row's and are not built.

Grant columns: `js_file_bytes`, `bytes` (the bridge and the new adapter's budget row) and `gzip_bytes` (the kernel
grows). Lowering `js_lit` and the freeze rows of `input_otp.rs` needs no grant. Size: about 12 h is about right.

The construction changes: after row 509 the executor's attribute and `hidePopover` writes are named effects (`show`,
`hide`) behind the apply table, and the spread work is smaller than stated. Grant columns: `js_file_bytes` and
`bytes`. Size: about 16 h is plausible once the three missing owners are added.

## Row 450, the bridge stats and the latency session

True: `primitives/src/ts/perf/` and `__dxBridgeStats` do not exist. `preview/Cargo.toml` has a `desktop` feature.

The construction changes: "never ships" conflicts with reading the counters on a release webview through an
environment variable. The counters live in the shipped bridge (the `channel()` wrapper) and in `transport.rs`;
anything under `ts/perf/` would be a bundle entry. Grant columns: `js_file_bytes` and `bytes`. The code is about 6 h;
the session itself needs a desktop build, the owner's device and a quiet machine.

- `ts/bridge.ts` is edited by all four: row 447 the epoch, `stale` and the serve region; row 448 the apply table; row
  449 registration and boot; row 450 `channel()`.

lanes on top of row 447, each rebasing its `ts/bridge.ts` region: both need the epoch rule and row 448 needs the value
slot.

## The per-row `mounted` handle

`scripts/check-hot-events.allow.tsv` excuses `mounted` under row 451 with the reason that a container handle and a
batched observe replace the per-row ones. Row 451 kept the per-row `onmounted` of `collection.rs` for the roving hub's
focus writes. Row 462 is the only row that claims the removal, and it is conditional: it is built only if the
focus-write witness is red, it is last in order, and it counts about 28 focus writes, not the per-row handle. Row 447
builds the focus owner only. If the witness is green, the handle has no owner. Other `onmounted` sites exist
(`color_picker`, `checkbox`, `command`, `context_menu`, `nav_link`, the menu items).
