## The finding that matters most: placement

Cross-cutting item 1 of the overlay lane (Base UI positions in document coordinates, Radix uses `fixed`, ours is `fixed`
plus visualViewport-tracking JS) is the root cause of the iPhone drift class, and the owner's device runs of
2026-10-28 (iPhone, iOS 18.7 Safari, the temporary overlay lab) settled it. Method and numbers are in row 477; the lab's
reference implementation is `git show 63190af3:dev-docs/lab/overlay-lab.html`.

## Measured versus inferred

Measured on a device (the owner's iPhone, iOS 18.7 Safari, 2026-10-28): the old method drifts 176 px with the keyboard
up (visualViewport offsetTop up to 354 px); rule P drifts 0 px over 2,059 frames, and 0 px with the live height over
1,284 frames; Floating UI absolute (the Base UI mirror) is 0 px at about 1,095 position writes per session against P's
writes only on side flips; a popover with a field, a dropdown, a context menu and an item-aligned select are all smooth.

Measured in sources (both upstream trees read): everything tagged M above. Inferred: that a tap opens a tooltip on iOS
through the compat `mouseenter` (code read, no browser run), modal-menu outside-click swallowing, Combobox clearing a
single selection when the input empties, Select first-highlight on a pointer open.

## The main loop's check of the valued-boolean claim

Lane 2 claimed that `data-x="false"` matches a presence selector `[data-x]`, a live bug. It is not live: the only
presence-selector user (the questionnaire) already omits false values (`then_some`). It is a convention to enforce, which
is what row 481's helper and its gate do.

## Owner questions this produced

1. Select default: both shadcn variants default to item-aligned; ours defaults to popper (row 268). Base UI disables
   item-aligned for touch opens.
2. Menubar modal: Base UI's Menubar is modal (scroll lock plus backdrop while a menu is open); ours is unlocked, the Radix
   model (row 479).
3. `as` (Radix `asChild` semantics, row 395) against base-nova's `render` prop for badge, item, sidebar, breadcrumb,
   attachment, bubble and marker. The main loop recommends keeping `as`.

#### Cross-cutting
1. **Positioning strategy (the iPhone bug).** BU `useAnchorPositioning.mjs:59` `positionMethod='absolute'`, floating-ui `strategy: positionMethod` (`:322`), `autoUpdate` with ancestorScroll/elementResize/layoutShift (`:301-323`); falls back to `fixed` only until first position (`:334`). Radix popper hard-codes `strategy:"fixed"` (`popper dist:136`). Exceptions in BU: context menu = `fixed` (`MenuPositioner.mjs:97`), Select item-aligned = `fixed` + scroll lock. Ours: every anchored surface is a top-layer `position: fixed` element plus `visualViewport`-tracking JS (`top_layer/anchor_fallback.rs`, `anchor.css`). Affects popover, tooltip, hover_card, dropdown/context/menubar, nav menu, select, combobox. Carrier: `top_layer/anchor_fallback.rs` (+ `anchor.css`, `scroll_clamp.rs`). I: a top-layer element with `position: absolute` is placed against the initial containing block, so it would scroll with the document like BU's body portal; verify in WebKit before committing. Size L, one file family.
2. **Close-on-scroll is a consequence of `fixed`, not an upstream rule.** Radix only closes tooltips on scroll (`tooltip dist:327`); BU never closes, popups follow the anchor (`data-anchor-hidden` instead). Ours: `ScrollClose::AnyScroll` for tooltip, hover card, unlocked menus, nav menu, menubar, unlocked select; `AnchorLeavesViewport` for popover and combobox (`top_layer/scroll_clamp.rs:144-205`, row 193). With absolute positioning most of it can go. Carrier: `scroll_clamp.rs`.
3. **Scroll lock.** BU locks via `overflow:hidden` on the viewport scroller; touch-opened anchored popups do NOT lock unless full width (`useAnchoredPopupScrollLock.mjs:30`). Defaults: Menu `modal` true, Select true, Menubar true, Popover false, Combobox false, Dialog true. Ours: Radix-style interception, no touch carve-out, Menubar unlocked. Carrier: `scroll_lock.rs`, `ScrollLockGuard` call sites.
4. **Outside-press semantics.** BU intentional (click) for mouse, sloppy (touchend, not dragged) for touch; Radix pointerdown for mouse, click for touch. Ours: pointerdown + focusin in `lib.rs:381` for non-modal surfaces, click-with-press-origin for dialogs. Carrier: `lib.rs` `use_outside_dismiss`.
5. **Hover-open pointer-type gating.** Tooltip and hover card use `mouseenter`; nav/navbar already gate on the last pointer type (`hover_intent.rs:37-49`). Carrier: `hover_card.rs` `HoverTimers` (shared by tooltip).
6. **API names.** Ours lacks `align_offset`, `collision_padding`, `sticky`, `position_method`, `anchor`; `ContentSide` has no `inline-start/inline-end` (`lib.rs:1153`), which base-nova CSS targets. S each, in `lib.rs` + `anchor_fallback.rs`.
7. **Pointer-open on press.** BU/Radix menus and selects open on mousedown/pointerdown; ours on click (`dropdown_menu.rs:533`, `select/trigger.rs:238`). Carrier: `menu_root.rs`, `select/components/trigger.rs`.

#### Not verified (honest gaps)
Modal-menu outside-click swallowing, Combobox single-select clearing on empty input, Select first-highlight on pointer open, tooltip touch-open on iOS: all code-read only, no browser run. The absolute-in-top-layer idea is untested.

#### Cross-cutting
1. **Data-attribute vocabulary** (checkbox, radio, switch, toggle, tabs, progress, collapsible): we emit R `data-state=*` and CSS depends on it (29 preview CSS files / 94 `data-state` selectors, 88 playwright files). base-nova uses presence attrs `data-checked`, `data-unchecked`, `data-active`, `data-pressed`. Cheapest construction: emit both in the primitives (one helper beside `merge_attributes` in `primitives/src/lib.rs`), migrate CSS incrementally, drop `data-state` last. Gated by `tier3-radix` oracle and many specs.
2. **Valued booleans**: `data-x=true|false` is always present; B/shadcn presence selectors (`data-disabled:`, `data-open:`) would match the false case. A presence helper (emit `""` or omit) would fix the whole class; blocks pasting upstream Tailwind classes. Touches every `attributes!` site.
3. **Form participation / read-only**: B hidden input + `readOnly`. Ours has hidden inputs for checkbox/switch/radio but none for slider; no `read_only` anywhere. Shared files: `default_checked.rs`, `lib.rs` form-reset listener.
4. **Field integration**: B-only; shadcn does not use it. No change needed for parity.
5. **Controlled/uncontrolled naming**: B `value/defaultValue/onValueChange`, `checked/defaultChecked`, `open/defaultOpen` already mirrored through `use_controlled`; callbacks lack B's `eventDetails` (cancel/reason). Low value in Dioxus.
6. **Animation lifecycle**: B exposes `data-starting-style/ending-style` and `--*-panel-height`; ours uses `use_animated_open` + `data-closing`. Only matters if upstream class strings are pasted.
7. **Keyboard**: shared `collection.rs` roving focus already covers Home/End; radio_group differs from B (B has no Home/End) but matches R/APG: keep.

#### Verdict
Radix remnants are mostly vocabulary (`data-state`, part names `TabTrigger`/`SliderRange`), not behaviour. Behavioural gaps vs both upstreams are slider form participation, `read_only`, and `on_value_commit`. A wholesale move to Base UI semantics is not worth it; do the dual-emit data attributes and the slider/read-only additions.
