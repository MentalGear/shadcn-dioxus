## Amendment (DESIGN, simplification): the owner's own rsx handler is the vdom carrier; a port only where Dioxus has no event

Dioxus 0.7.9 already delivers, synchronously and in order, the events each owner needs on the element it already renders: `onbeforetoggle` (`dioxus-html-0.7.9/src/events/generated.rs:300`, non-bubbling, fires synchronously per HTML), `onfocusin`/`onfocusout` (`:55`), `oninput`, `onreset` (`:103`), `onscrollend` (`:285`), `oncancel`. The three focus instances the slot table cites are already rsx focus handlers (`tabs.rs:389`, `date_picker/segment.rs:536`, `virtual_list.rs:487`); `lib.rs:848` already prevents every dialog `cancel`. So:
- **Every discrete page transition on a page-written slot reaches Rust in vdom order** (whole-core F1: the "an rsx handler reads this slot" condition is ungateable and already wrong for Carousel's fact-fed `selected`, `nav.rs:109-113`, and Collapsible's `beforematch`-changed slot, `collapsible.rs:388-391`). The vehicle is the owner's own rsx handler on its own element. Because the transition and any decision that reads it are dispatched by the same Dioxus event loop, the ordering problem of document-level hooks running after the root handler (whole-core F2, `core.ts:117-121`) does not arise.
- **A port remains only for transitions Dioxus delivers no event for** (today `beforematch`; any other must be named in the slot table with its reason). It is fired from a window-capture listener so it precedes the Dioxus root handler, renders inside the owner, never re-dispatches into user handlers, and is not a form control (so desktop's whole-form serialization, `serialize.ts:432-446`, does not apply).
- For reset, restoration and the install-time level, the value owner re-dispatches a real `input` on the input itself (this also fixes row 468's user-visible defect). Each side counts the same events, so epochs need no payload for this carrier. Stream ends settle by dropping the per-gesture subscription (the Drop-registry rule).
- Removes the hidden port element as the general carrier, root `stopPropagation`, the no-form rule, the hydration-parity line, the liveness handshake and the `dispatchPort` effect with its witness (about 5-7 h). Residuals: desktop element-id reuse can misroute rarely; one blocking request per open/close on desktop; a dialog closing without `cancel` on Chrome <132, Firefox <133, Safari 18.x falls back to the fact path.
