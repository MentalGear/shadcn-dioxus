# Adversarial board on row 434 step 3: synthesis (2026-10-26)

Five independent members attacked the adopted plan (rules as data, one interpreter, no residue). Reports in this folder: `root-and-timing.md`, `simpler-alternative.md`, `block-mapping.md`, `gates-and-proof.md`, `ux-a11y-perf.md`. All five returned **HOLDS WITH CHANGES**; none returned BROKEN.

## What held

- The root: the browser commits an event's default action when dispatch ends and paints after layout, so a decision must be computable on the page's thread from data already there. Never ask Rust at commit time; publish beforehand, decide locally. Verified again in the Dioxus 0.7.9 sources (root-and-timing).
- Dioxus element handlers are synchronous on web and desktop/mobile, so `prevent_default()` in rsx works everywhere (code path verified; Android header transport and WebKit sync XHR inferred).
- A (platform first), G (paint-safe gate) and R (plain bridge plus Rust) are where the JavaScript actually leaves (simpler-alternative).
- One eval transport with no web-sys is the Dioxus idiom (best-practice review). Porting W8, C5, C1 last and one at a time matches the dependencies (block-mapping).

## What changes (by construction)

1. **The B layer: a closed registry of named behaviours, scoped, not a predicate DSL behind one delegated interpreter.** Four members independently broke the delegated capture-phase interpreter: `closest()` only finds rules on the target's ancestors, where a Dioxus element handler already decides synchronously with full Rust state; a capture listener makes `defaultPrevented` predicates vacuous (V22, L23) and its `stopPropagation` kills Dioxus handlers; a page-lifetime non-passive wheel/touch listener brings back rows 149/159 and fails `listener-inventory.spec.ts`; and the B families were a union of today's blocks (B3 one user, B5 three different programs). The construction is a three-way placement rule, decided per behaviour:
   - **Target inside a Dioxus element, event Dioxus supports** -> an rsx handler (L1, L2 via `oncancel`, element `onkeydown`, T4/T6). Synchronous on every renderer, Blitz included.
   - **Window, document or "outside" target, an event Dioxus lacks (`beforeinput`, `close`), or capture phase** -> one *named, typed behaviour* from a closed registry (`hotkey` for L6/O1/V22, `scrollLock{allowInside}` for L11/L10, `otpFilter`, `dropAnywhere`, `dialogKeyForward`, plus `pan` and `settle`). Each declares target, phase and passive explicitly; installation is owned by the Rust scope that needs it and ref-counted, so a blocking listener exists only while something needs it.
   - **Continuous streams** (scroll, resize, pointermove, wheel) -> bridge `subscribe`/`sample`, coalesced or flushed per event task, never vdom handlers (on desktop each vdom event is a blocking synchronous request, `native.ts:353-395, 568-593`).
   The Rust `Behaviour` enum and the TS registry stay one to one by generation (`cargo test` writes `behaviours.gen.ts`), each behaviour is a pure `decide()` plus a thin DOM adapter, JSON vectors run in `cargo test` and `bun test`, and every behaviour has a fail-open path (WCAG 2.1.2) and an epoch.
2. **Delete dead JS first.** About 16 eval sites sit in `#[cfg(not(feature = "web"))]` arms that every supported build compiles only for Blitz, where eval is a no-op: all three focus-trap evals plus `ts/focus-trap.ts`, 5 of 6 `use_global_escape_listener` calls, one context-menu scroll-block install. L23 (Label double-click) is already `user-select: none` in CSS. Gate: no eval or JS listener in a `not(web)` item.
3. **G, hardened.** Gate by `:popover-open:not([data-dx-placed])`, cleared synchronously in `beforetoggle`; pending style is `animation: none` (a running or paused animation outranks `opacity: 0` and keeps its 0% `scale`); fail open through the enter animation's `animation-delay` with `forwards` fill (no JS timer needed); a generation token from `open` drops stale answers. Split tiers: placement-critical (fallback engines, the iOS keyboard clamp) is gated; decoration (placed side, arrow, available height) is never gated, after the tooltip's `:not([data-placed-side])[data-side]` precedent. Otherwise every popup open pays 2 to 4 frames on desktop.
4. **W8 is a Rust invariant with A as the accelerator.** The scroll-anchoring spec picks no anchor at offset 0 and skips clipped nodes, so `overflow-anchor` alone never follows the first overflow. Rust keeps "end sentinel visible, else scroll to end" through IntersectionObserver plus resize on the bridge; CSS anchoring makes it frame-exact where it works.
5. **C5 stays a Rust attempt, measured.** It is passive, so lateness is lag. Flush per event task, not per rAF (trackpad wheel already arrives about once per frame), add a "Rust busy 30 ms" scenario, fix the replay harness's same-rAF phase. The owner measures it with an old/new switch; if Rust loses, it becomes an allowlisted TS module (simpler-alternative's position).
6. **The bridge surface is closed.** `call`/`get`/`set`/`listen` take closed Rust enums mapped through closed TS tables with a receiver kind per row; no `el[method](...)` (otherwise `call(window, "setTimeout", ["code"])` is an eval). `passive` derives from the behaviour. Pointer capture and focus at pointerdown cannot be async verbs: they are behaviour effects or rsx handlers. Desktop has a documented timing contract (edits applied in a rAF, at most one render per frame; an eval from a handler runs before its own render's edits; `commit()` is a no-op there); "show plus measure" is one transaction returning the rects.
7. **Enforcement closes sinks, not spellings.** One eval call site (`bridge/transport.rs`), a `git ls-files` universe, clippy `disallowed_methods` for `document::eval`/`Document::eval` outside the transport (aliasing and `concat!` cannot dodge it), an allowlist of `Script { src: asset!() }` constants, a file inventory for hand-written `.js`/`.ts`, no inline-marker escape. Shrink-only ratchets compare against the merge base (`scripts/lib/ratchet.py`); raises carry `# raised: row N` and print as `RATCHET RAISES`. The JS-volume ratchet lands before any port. A `check-hot-events.sh` gate keeps frame-rate events off vdom handlers.
8. **Proof that is honest about desktop.** The slow-channel harness is a bridge-latency harness, not a desktop model; a later desktop-cadence build of dioxus-web (rAF-bound edits, async eval and getters, jittered send) plus Playwright WebKit, and one WebKitGTK or real-desktop pass per batch recorded as `desktop-pass/<tree>.pass`. Until then rows say "web-verified; desktop inferred". Chromium is the only engine installed here, so A's Firefox/WebKit claims and Safari 27 `overflow-anchor` need those runs; T8 keeps its outcome check (Firefox once reported support and failed). Add `bridge-cost`, `g-latency` and registry-leak specs.
9. **Lane plan fixes.** Merge T11 into 3.PL (T9/T10 are `const` text spliced into T8, T11 and the select probe; both lanes owned `scroll_clamp.rs`, which also holds unmapped T12). One gate owner. Per-module bundle outputs so TS lanes do not all rewrite one `bridge.js` and manifest, and the build/check scripts glob `ts/**`. Add `top_layer/attributes.rs` to 3.PL. Map W4, W6 and the 43 (b) rows that have no lane. 3.CA keeps C4's bounce on `transform` until 3.WB lands (shared `transform` and pointerdown handoff, `wheel.rs:563`, `drag.rs:215`). Fill spec gaps: RTL for scroll-to, find, W8, S1, context menu, drawer drag; touch for toast swipe; L11's in-dialog, horizontal and touch paths.
10. **Measurement for the owner** (ux-a11y-perf section 3): `__dxPerf` (longtask, LoAF, event timing, layout shift, frame deltas), a bridge round-trip histogram, `?dx-bridge-delay=N` and `?dx-bridge-spin=ms` to emulate desktop latency on the owner's Mac, scripted scenarios and a manual checklist per port. W8 and C5 ship with the old path switchable for one deploy (`?dx-impl=`), the legacy JS moved into `ts/legacy/` behind a non-default `legacy-impl` feature only preview enables, with an expiring allowlist entry; `js_macros.rs` is deleted at the expiry deploy.

## Why 103 bespoke blocks existed (owner's question)

About 30 code comments called `document::eval` "this crate's established escape hatch" or "house pattern" (`carousel/drag.rs:76`, `top_layer/mod.rs:6`, `input_otp.rs:30`); the existing JS gates regulated the shape of the script string (check-js-listeners tells agents to write `listen(...)` inside it) rather than whether JS should exist; no interop doc existed; and upstream, which has none of these behaviours, offered only the same eval pattern. Lane 434-R (in flight) lands the ratchet, `dev-docs/js-interop.md`, the CLAUDE.md rule and the comment sweep.
