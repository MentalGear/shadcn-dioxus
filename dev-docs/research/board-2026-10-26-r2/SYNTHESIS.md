## The amendment (DESIGN)

The three-way rule (rsx handler / named behaviour / bridge stream) sorted by where a listener sits. The root sorts by which commit point a decision feeds and by when it must land. Evidence: the plan contradicted its own rule (arm 2 names `close`/`beforematch`, yet L2, W4, T12, L3/7/8/9 were mapped to bridge `listen`); arms overlapped with no precedence (C4 fits all three, L11 and S2/S3 two); "rsx handler, synchronous everywhere" holds only for `prevent_default` (on desktop `set_focus` is an async webview query, `dioxus-desktop-0.7.9/src/element.rs:137-160`, renders land in the next rAF, there is no pointer-capture API); drawer drag (R) and toast swipe (`pan`) are the same gesture placed differently; W8 follow-bottom is a same-frame layout write that the Rust invariant alone answers 1-2 frames late on WKWebView before Safari 27; and commands (`showPopover`/`hidePopover`, `showModal`/`close`, `indeterminate`, `defaultChecked`) were one-off bridge calls fired from effects.

**Amended placement rule: classify each decision by its deadline, then by its kind.**

| deadline (what a late answer costs) | placement |
|---|---|
| this event's default action (cancel or not) | rsx handler if Dioxus delivers the event and every field the decision reads (`ToggleData` is empty, so `ontoggle` decisions do not qualify); otherwise a named behaviour |
| this event's task (pointer capture, focus routing for the next input) | a named behaviour effect; never an async verb, never rsx `set_focus` on desktop |
| before paint (same-frame layout write) | A where the platform does it (behind per-feature floors and a boot probe); otherwise a named behaviour (`stickToEnd`, placement on fallback engines); G only for one-shot placement where an invisible pending state is acceptable |
| next frame (drag tracking, momentum) | bridge stream plus Rust, under a latency budget the owner sets from the row 442/443 measurements; a named behaviour only if the measured lag exceeds it |
| none | R: Rust over the bridge |

**Kinds.** A *listener* reacts to events. A *command* mirrors Rust state into the page: Rust publishes the desired state as a `data-dx-*` attribute and one page-side reconciler applies it (popover open, modal open, indeterminate, default checked), reporting only browser-initiated changes back. On desktop a MutationObserver callback runs before paint in the frame the edit lands, so an overlay open saves a frame; it removes the lost or early command class (#5919), the stale toggle echo (row 115) and the two-writer `<dialog open>` trap.

**Admission.** A named behaviour must contain a commit-sensitive effect (prevent, capture, focus, a same-frame write), checked from its generated effect set. Verbs are single member calls (a gate checks each verb row); a program such as L16's open-focus policy is a behaviour, not a verb. When Dioxus later delivers an event and its fields (0.8 `onbeforeinput`), the behaviour moves to an rsx handler.

## DETAIL findings to fold in

- **Bridge (lane 3.0, in flight):** the transport is still typed by `&str` (`transport::open(body: &str)`, `request(expression: &str)`, `pub(crate)`, already called by `js_listener.rs`): a renamed sink, not a closed one. Make it a `Program` enum plus args, `pub(in crate::bridge)`. `setPointerCapture`, `focus` and `commit` ship as verbs against plan 5.2. Line budgets carry slack (`bridge.ts` 1100 vs 874). The adapter supports one event per install and a `{prevent, stop, attrs, send}` decision; about 985 of 1,000 behaviour lines need a wider effect vocabulary and per-install state. Closed tables lack rows about 18 later rows need (`reset`, `beforematch`, `scrollend`, `dragend`, `invalid`, `reportValidity`, `getAnimations`, a property `set`, `observe` publish). Ordering belongs to the transport: one FIFO channel, element operations flushed after the render that issued them. Behaviours tear down when their element disconnects.
- **G:** pending `animation: none` kills a delay-based fail-open, and the theme's `[data-dx-motion-key] * { animation: none !important }` (`dx-components-theme.css:2421-2432`) defeats it for nested popups: use a separate fail-open animation name swapped on placed, plus a page-side watchdog. Clear the pending flag in the `show` verb's own JS turn, not `beforetoggle` (absent for `<dialog>` on Chrome <132, Firefox <133, Safari <=18.7, non-bubbling). The generation is page-owned (`data-dx-placed` had two writers). Tier predicate `:not([data-dx-anchored])` and a per-surface list (navbar, navigation menu, toast animate differently).
- **A:** "Baseline newly available" dates first releases that had placement bugs (Firefox 147 lacks `position-try-order`; Safari 26.0/26.1 fail to anchor on reopen, fixed 26.2; nested anchors fixed in Safari 27). Use per-feature floors plus a boot probe (edge shift, reopen x3, nested submenu); a failing engine is a fallback engine.
- **Desktop facts:** one `onpointermove`/`onwheel` anywhere makes that event a blocking request app-wide (one root listener per event name); `onmounted` is a synchronous request inside the edit application (113 sites); `check-hot-events` counts by event name (by clippy def-path, not grep) and includes `onmounted`. Add to the timing contract: the Blob hop before the rAF, stalls while the webview is hidden (Rust timers pause too), Android's IO thread and global mutex, Windows drag-drop replacement breaking `dropAnywhere` under the default config, release builds' document `contextmenu` preventDefault. Streams need latest-wins coalescing, one message in flight, caps on batched modes. Existing frame-rate vdom handlers (`virtual_list.rs:486`, `table_rows.rs:289`, `virtual_grid.rs:729,1360,1526`, Select `list.rs:503,591`, chart and context-menu `onpointermove`) need a lane.
- **Enforcement:** raises are self-service (`--allow-raise "row 1 x"` passes; lane 3.0 self-raised about 2.7k lines): a raise needs a grant row present at the merge base. Count the shipped bundle bytes and Rust-held JS, not tests, `.d.ts`, generated files or display snippets (false reds on `Bezier::eval`, `Script {` variants, code samples). Close the landed gate's holes: `/vendor/` and `.min.js` exclusions, unscanned `.md`/`.svg` reaching `dangerous_inner_html`, untracked files, `dd::eval` as a fn pointer, physical-line counting. "A new behaviour needs a row" is enforceable as: the row exists at the merge base, is open, and names the kind in front matter (`adds:`). The clippy sink ban needs per-file `expect` until the last eval line goes. No date-keyed expiry. `legacy-impl` unifies on under `--workspace`, so lint the shipped arm separately. A fate table retires `check-js-listeners`, the uncleared-interval and blocking-scroll halves and the `*-ok` markers as their allowlists empty. TS scans use the tsc API, not a spelling denylist.
