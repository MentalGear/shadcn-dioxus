# Row 448: Phase 0.3: proof port A (the not(web) focus trap's 3 eval sites, focus-trap.ts, and the otpFilter behaviour for S11)

## Item

The first listener port and the first named behaviour: lane 3.DJ (delete the focus trap in the `#[cfg(not(feature = "web"))]` arms of `dialog.rs`, `alert_dialog.rs` and `popover.rs`: its 3 `document::eval` installs, the 3 `focus_trap_script()` calls and the `focus_trap_script` / `FOCUS_TRAP_JS` pair in `lib.rs`, plus `ts/focus-trap.ts`, its `js/` output and manifest line and the allow-TSV entry. The sites are dead only where `web` is on for every browser-engine build: see Status / trigger and [row 511](./511-primitives-web-feature-contract.md), which lands first), then `otpFilter` for S11 (25 lines, an element target, `beforeinput` missing in 0.7.9: its `prevent` and `setValue` exercise `defaultAction` and `wrongPaint`, so its witnesses are red by construction; it also takes `insertFromPaste` and `insertReplacementText`, which fixes the live OTP paste defect of [row 474](./done/474-bug-input-otp-paste-loses-digits-to-maxlength.md)). It also builds the registry restructure (one Rust file and one vectors file per behaviour, a registry macro that collects the variants), explicit `site!("name")` ids (a `Site` only the macro can construct), the per-install effect set that the adapter refuses beyond (round 7 cut the per-site typestate), the checks over those artefacts that item 0.1 leaves to this row (the `site!` literal scan, the scenario binding, the witness-test presence check, the DOM-less behaviour program with the generated `Decision<E>`, the `decide` registration, the lease check on the generated file) and the adapter for `otpFilter`. The cancel counterfactual here is site-relative and also drops the cancel when Dioxus lacks the event or a field the decision reads, so `otpFilter`'s witnesses (no `onbeforeinput` in 0.7.9) are red by construction and not by accident. `hotkey` is not built here (round 6: L6's witness is expected green by construction for an in-app target and it most likely decomposes into a bridge `listen` plus an rsx `prevent_default`; `hotkey` is built by the first of 3.OV and 3.GS that needs it). L23 is not here (it keeps the primitive's behaviour, row 3.FC). Why: it proves the construct end to end on a real block and deletes the focus trap's JavaScript first, once that JavaScript is dead.

Part of the [row 434](./434-javascript-in-typescript-modules-not-rust-strings.md) step 3 plan; source: [`sync-js-root-2026-10-26.md`](../research/sync-js-root-2026-10-26.md) section 5.4 (phase 0).

**Correction, 2026-11-12 (read from the source on `bdb41d2a`, not run).** The 3.DJ half rested on "every supported build compiles the `not(web)` arms only for Blitz". That holds as wired in this repository's own apps and is not enforced:

- **The premise.** `web` (`primitives/Cargo.toml:47`) is the switch "a browser engine renders this", not "this is wasm" (`scripts/check-cfg-axis.sh:5-7`). `preview/Cargo.toml:38-41` turns `dioxus-primitives/web` on for `web`, `desktop` and `server` and not for `native`; `templates/starter/Cargo.toml.liquid:17-20` turns it on for `web`, `desktop` and `mobile`. So in the preview and in a starter app `not(web)` is Blitz only, where `document::eval` is a no-op (`platform-rationale.md`, Caveat 2).
- **What nothing enforces.** The CLI adds the primitives dependency as `cargo add --no-default-features` plus the component's own features (`cli/src/manifest.rs:110-115`) and never names `web`; `scripts/registry-install-smoke.sh:157-167` strips `dioxus-primitives/web` and builds without it. An app that installs components with the CLI and is not made from the starter therefore gets the `not(web)` arms on every renderer, the web and the webview included, where the three focus-trap evals run and are the modal focus trap. For such an app the "dead" sites are live; deleting them removes the trap there and leaves a modal `div` with `aria-modal` and no trap.
- **The site list.** The old count of 16 no longer matches the code. Escape and outside dismissal in these arms now go through `crate::dismiss::use_dismiss`, and `use_global_escape_listener` no longer exists. The `not(web)` arms hold today: three `document::eval` focus-trap installs, `dialog.rs:521`, `alert_dialog.rs:264` and `popover.rs:523` (arms at `dialog.rs:480`, `alert_dialog.rs:233`, `popover.rs:478`), loading `createFocusTrap` from the bundle that `focus_trap_script()` loads (calls at `dialog.rs:271`, `alert_dialog.rs:149`, `popover.rs:401`; the function and its asset at `lib.rs:129-153`). Four more installs are not eval but JS listeners through the shared dismiss core (`dismiss.rs:399`): `use_dismiss` at `dialog.rs:503`, `alert_dialog.rs:247`, `popover.rs:509` (modal) and `popover.rs:839` (non-modal). Those four are already ported (the core is Rust-decided), so 3.DJ does not delete them.
- **The webview.** No desktop build exists or has been exercised ([row 23](./023-preview-s-desktop-feature-lacks-dioxus.md), STATUS.md owner inputs), so the `web` arm on the webview (`<dialog>` with `showModal()` through eval) is unproven, not known good.
- **New precondition.** [Row 511](./511-primitives-web-feature-contract.md) lands first: the focus-trap deletion is safe only once every browser-engine build is guaranteed to enable `web`. The `otpFilter` half is unchanged.
