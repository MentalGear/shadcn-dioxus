Part of the [row 434](./434-javascript-in-typescript-modules-not-rust-strings.md) step 3 plan; source: [`sync-js-root-2026-10-26.md`](../research/sync-js-root-2026-10-26.md) section 5.4 (phase 0).

**The `otpFilter` half, as built (lane `lane/otp-filter-448`, 2026-11-15).**
- **The kind.** `decision-kernel/src/otp_filter.rs`, kind `otp-filter` (the module and bundle are named for the kind, `ts/behaviours/otp-filter.ts`; the row's `adds:` reads `[otp_filter]`). `Config` is `event`, `ranges` (the closed `OtpPattern::ranges()` as `(low, high)` pairs) and `max`; `Event` is `type`, `inputType`, `data`, `isComposing`, `value`, `selectionStart`, `selectionEnd`, the four fields of a cancellable `onbeforeinput` of a later Dioxus plus the selection, so that handler can feed `decide` and the bridge adapter can go without a kernel change. One kind is installed once per event (`beforeinput`: cancels and writes; `input`: filters an edit that carried no text; `compositionend`: decides again from the committed text); `use_behaviour`'s epoch key is `behaviour:<kind>:<event>` so the installs do not replace each other. 19 vectors in `primitives/conformance/behaviours.json`.
- **The value-write effect.** No new `Decision` field: it is the `value` entry of `slots` (`ValueWrite`: range in UTF-16 units, text, caret, whether to dispatch `input`), applied by the `value` owner of `SLOT_OWNERS` through the `value` setter; the apply marker names it `setValue` (and the focus slot `focus`) so the witness harness's members match. `wire_input!` reads `f64` and `Option<bool>` and allows a kind with no attribute reads; the closed field table gained `value`, `selectionStart`, `selectionEnd`.
- **Composition, as built (the answer to the open question of row 515).** Nothing is held. A decision made while an input method composes is empty (the write is dropped at once, in `decide`), and `compositionend` decides again from the committed text and dispatches `input`. A decision is made and applied inside one dispatch, so no later page transition can make it stale and the value owner needs no fence. The `dropped` reply exists only on the `write` op, which has no `value` row (`bridge/mod.rs` is not this row's and nothing consumes one).
- **Sites.** `site!("name")` builds a `Site` (field private, constructor hidden); `check-bridge-behaviours` scans the literals, requires `primitives/src/ts/behaviours/sites.gen.json` to equal them (`--update-baseline` writes it) and a binding and a `witness(...)` test for each.
- **Witnesses.** `setValue` is red as an expected failure (the binding types `1-2` into the alphanumeric field and a key one paint later, so a late write paints states the real arm never painted). `prevent` is green on Chromium: the next-best placement (a cancel in the bubble phase at the host) cancels the `beforeinput` all the same, so its witness is `test.fixme` and its admission is the owner's decision (a platform rule row, or the cancel moves to rsx when Dioxus delivers `onbeforeinput`). The row's earlier claim that both are red by construction does not hold.
- **Order spec.** `playwright/witness/order.spec.ts`, "the value slot": a paste, a form reset and a keystroke in one gesture end on the keystroke and the last `input` heard is the DOM value; with the value write delayed past the keystroke (the unfenced placement) the paste overwrites it and no `input` reports it. Not shown against the pre-change script (it needs the old script behind a bisect on the real page).
- **What row 515 keeps.** The value owner's `input` re-dispatch for form reset, restoration and the install-time level stays with `form_reset.rs`'s owner: `input_otp.rs` still calls `use_form_reset_listener` and `use_dom_value_restore`, whose files this row may not touch. **Correction, 2026-11-12 (read from the source on `bdb41d2a`, not run).** The 3.DJ half rested on "every supported build compiles the `not(web)` arms only for Blitz". That holds as wired in this repository's own apps and is not enforced:

- **The premise.** `web` (`primitives/Cargo.toml:47`) is the switch "a browser engine renders this", not "this is wasm" (`scripts/check-cfg-axis.sh:5-7`). `preview/Cargo.toml:38-41` turns `dioxus-primitives/web` on for `web`, `desktop` and `server` and not for `native`; `templates/starter/Cargo.toml.liquid:17-20` turns it on for `web`, `desktop` and `mobile`. So in the preview and in a starter app `not(web)` is Blitz only, where `document::eval` is a no-op (`platform-rationale.md`, Caveat 2).
- **What nothing enforces.** The CLI adds the primitives dependency as `cargo add --no-default-features` plus the component's own features (`cli/src/manifest.rs:110-115`) and never names `web`; `scripts/registry-install-smoke.sh:157-167` strips `dioxus-primitives/web` and builds without it. An app that installs components with the CLI and is not made from the starter therefore gets the `not(web)` arms on every renderer, the web and the webview included, where the three focus-trap evals run and are the modal focus trap. For such an app the "dead" sites are live; deleting them removes the trap there and leaves a modal `div` with `aria-modal` and no trap.
- **The site list.** The old count of 16 no longer matches the code. Escape and outside dismissal in these arms now go through `crate::dismiss::use_dismiss`, and `use_global_escape_listener` no longer exists. The `not(web)` arms hold today: three `document::eval` focus-trap installs, `dialog.rs:521`, `alert_dialog.rs:264` and `popover.rs:523` (arms at `dialog.rs:480`, `alert_dialog.rs:233`, `popover.rs:478`), loading `createFocusTrap` from the bundle that `focus_trap_script()` loads (calls at `dialog.rs:271`, `alert_dialog.rs:149`, `popover.rs:401`; the function and its asset at `lib.rs:129-153`). Four more installs are not eval but JS listeners through the shared dismiss core (`dismiss.rs:399`): `use_dismiss` at `dialog.rs:503`, `alert_dialog.rs:247`, `popover.rs:509` (modal) and `popover.rs:839` (non-modal). Those four are already ported (the core is Rust-decided), so 3.DJ does not delete them.
- **The webview.** No desktop build exists or has been exercised ([row 23](./023-preview-s-desktop-feature-lacks-dioxus.md), STATUS.md owner inputs), so the `web` arm on the webview (`<dialog>` with `showModal()` through eval) is unproven, not known good.
- **The precondition has landed.** [Row 511](./done/511-primitives-web-feature-contract.md) inverted the axis: the browser arm is the default, and the focus trap (`#[cfg(feature = "native")]` in `dialog.rs`, `alert_dialog.rs` and `popover.rs`, with `focus_trap_script()` and `FOCUS_TRAP_JS` in `lib.rs`) is compiled only where `dioxus-primitives/native` is on, which a compile-time assert holds equal to dioxus's own `native` renderer. Where this section says `not(web)`, read `feature = "native"`. The deletion therefore removes dead code by construction: those sites run only where dioxus launches Blitz and `document::eval` answers `Unsupported`. The `otpFilter` half is unchanged.
