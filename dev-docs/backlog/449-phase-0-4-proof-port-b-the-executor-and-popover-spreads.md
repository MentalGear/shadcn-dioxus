# Row 449: Phase 0.4: proof port B (the reconciled-kinds executor, the popover hooks that return the attribute to spread, the owners' onbeforetoggle handlers)

## Item

The one page executor (round 6 withdrew the per-kind choice between a page reconciler and a Rust `transaction`), built for the first four reconciled kinds (popover open, modal open, `indeterminate`, `defaultChecked`) on a table of kinds that the native slot kinds join later, and admitted as a whole by the reds of item 0.6's pre-authored witnesses: boot install, discovery by `childList`, the one epoch rule, the one show writer, the stale `placed` removal, the watchdog arming for declared pending states, the exit wait (an `AbortError` counts as done), a save and restore of scroll around `showModal()` in the open step (which replaces `scroll_lock.rs:267-298`'s restore, removed by 3.SL) and its own level-stamped reports; the executor is keyed by `(scope, nonce)` like slots (scope ids are reused), and one page executor serves every reconciled kind. The popover hooks (`use_popover_sync`, `use_popover_shown_while_mounted`) return the attribute to spread instead of `()`, and this item owns the one-line spreads and each owner's own rsx `onbeforetoggle`/`oncancel` handler (the vdom carrier of the order contract; no port element) at their 13 call sites in 11 files. Consumed by T4 to T7 here and by 3.OV and 3.FC later. Why: one executor per element is what removes the lost-command class, the stale toggle echo (row 115) and the two-writer `<dialog open>` trap.

Part of the [row 434](./434-javascript-in-typescript-modules-not-rust-strings.md) step 3 plan; source: [`sync-js-root-2026-10-26.md`](../research/sync-js-root-2026-10-26.md) section 5.4 (phase 0).

**Approved construction and scope (main loop, 2026-11-15, on the premise check below).** Ordering rides page-side: each executor command carries a per-element nonce that Rust mints (the owner's command count), the page echoes the nonce it had applied in its level-stamped report of a page-caused transition, and Rust drops a report older than its newest command. `oncancel` stays as the dialog family's carrier; `onbeforetoggle` leaves the row; `indeterminate` and `defaultChecked` leave it too (row 458 owns `checkbox.rs` and `default_checked.rs`; the executor's kind table takes them then); the scroll-lock restore stays. The row owns the `show` and `hide` rows of APPLY and the executor's `site!` names.

**Built on lane `lane/executor-449` (2026-11-15): the popover kind.** `ts/lib/executor.ts` (bundled into the bridge, installed with it) is the one writer of a registered popover's open level: `show` / `hide` through APPLY under the `executor.popover` site, a command older than the entry's nonce dropped, a page-caused `beforetoggle` reported as `{n, open}` (its own write's `beforetoggle` is not), a command for an element not rendered yet run by one `childList` observer. `bridge/executor.rs` (`use_popover_level`, `Command::Executor`, `Subscription::send`) mints the nonce and drops a stale report. `use_popover_sync` (menus) and `use_popover_shown_while_mounted` (tooltip, hover card, select, combobox, navbar, navigation menu, toast) run on it; their two eval show scripts and the menus' both-ways `toggle` listener are gone, so row 115's echo class is closed for the menu hosts too. Identity is the element's server-rendered `id`. Not built here, and why: the modal kind and the non-modal Popover's `<dialog popover>` show (`PanelSync::DialogPanel`, legacy) both run inside the legacy open-focus policy (`dxOpenFocus` of `OPEN_FOCUS_JS`, a set of page decisions: where focus lands per modality); the executor cannot call it and moving it into TypeScript would move decisions there, so they wait for that policy's Rust port (row 456). With the modal kind go the exit wait, the watchdog, the scroll save and restore around `showModal()`, the `oncancel` carrier and the Escape-then-Enter order spec; the `executor.exit_wait` and `executor.watchdog` witnesses stay `test.fixme`. No pre-install fact exists for a popover (an SSG page shows none before the bridge), so the early-fact hold is not built.

**Premise check at the lane's base (023bf92a, 2026-11-15): stopped before the first code edit.** Read against the source:

- *Holds (reduced):* row 519's `top_layer::use_anchored_panel` is the only caller of `use_popover_sync` (menus, `PanelSync::Immediate`) and `use_popover_shown_while_mounted` (seven panels, `WhileMounted`); Toast and the anchored modal popover are `check-anchor-marker` rule 4's two exceptions. The hook already returns the attribute list each site spreads, so "the hooks return the attribute to spread" and the 13 call-site spread lines are done. It is one call site, not one writer: the writers are still two legacy `document::eval` show/hide scripts and a `toggle` listener per element (`popover_sync.rs`). The `Immediate` listener forwards `newState === 'open'` too, so row 115's stale-echo class is still open for the three menu hosts.
- *False, changes the construction:* `onbeforetoggle` and `oncancel` are `dioxus-html` 0.7.9 events (non-bubbling, attached on the element by the interpreter), but `ToggleData` and `CancelData` carry nothing: no `newState`/`oldState`, no page sequence number; the only way in is a `web_sys::Event` downcast, which this crate does not depend on and which Blitz has no equivalent of. An rsx `onbeforetoggle` therefore cannot tell an own show from a light dismiss, nor learn the fence number the page minted for it (`watchTransitions` in `ts/bridge.ts` already mints `beforetoggle` and `cancel` page-side). It is not a carrier of the order contract. `oncancel` keeps a real job (`prevent_default()` plus `set_open(false)` in vdom order before the next key), but the row-223 Enter forwarding still reads the page-side `__dxCancelAt` it would replace.
- *False:* "keyed by `(scope, nonce)` like slots". Slots are keyed by element (a `WeakMap`) and by `Epoch {key, n}`; no `(scope, nonce)` identity and no SSR-stable scope id exist yet. It is new design work, not reuse.
- *Drifted:* `scroll_lock.rs`'s restore also serves Popover and ContextMenu locks (no `showModal()`), so a save and restore around `showModal()` does not replace it; the restore stays (its eval is tagged for row 459).
- *Blocked by another lane's files:* the executor's writes need `show`, `hide` and `setProp` rows in `APPLY` (the witness library already intercepts those members under `__dxApplying`), and `APPLY` is row 448's region this round. The `executor.exit_wait` and `executor.watchdog` witnesses go live only when their names appear in `primitives/src/ts/behaviours/sites.gen.json`, written by row 448's `site!` generator, which does not exist at the base.

Proposed construction (for the main loop): order rides page-side, not on the vdom carrier. Each executor command carries a per-element nonce (the owner's command count) and the page's report of a transition carries the last nonce it had applied (a level-stamped report), so Rust drops a report older than its newest command. That one rule removes the close-then-reopen, the stale echo (row 115, menus included) and the dismiss-then-`onclick` races without a toggle payload. Keep `oncancel` as the dialog family's carrier. Drop `onbeforetoggle` from the row. Build after row 448 lands its `APPLY` rows for `show`/`hide`/`setProp` and the site list, or give this row those rows explicitly.
