# Row 434: Cut JavaScript to what Rust cannot do

## Item

The owner's principle (2026-10-25): the point of Dioxus is to drive the UI from Rust/wasm, so JavaScript is the exception, not the default. The library has no `web-sys` dependency; every browser API Dioxus does not wrap goes through `document::eval`, the one route that works on web, desktop and mobile. 72 files carry eval. The owner chose **Rust first** over "Rust plus web-sys" (one code path per feature, every renderer) and over the original TypeScript move.

1. **Audit** every eval block and classify it: (a) Dioxus already has it in Rust (`MountedData::get_client_rect`, `scroll_to`, `set_focus`, event data, signals, `onvisible`/`onresize` where they exist), so move it; (b) Dioxus has no Rust API (`showPopover`/`showModal`, `matchMedia`, pointer capture, listener options such as passive/capture, `scrollend`, `getAnimations`), so it stays JS; (c) must run before wasm (`PREPAINT_JS`, the modality writer), so it stays JS; (d) JS on purpose for latency (one-frame measure-and-place in the anchor engine, scroll bridge, virtual find), so it stays only with a measured reason.
2. **Move** every (a) block to Rust, per cluster, with the components' specs on a release build as the proof (timing-sensitive paths compare long tasks before and after).
3. **What stays** (b, c, d) moves into typed `primitives/src/ts/` modules through the existing bundle chain (the original P9 construction), and the copies become one file.

## Step 3 design: one small generic JS bridge (owner 2026-10-26)

The owner asked for a uniform small JS glue layer to Rust instead of many bespoke scripts, which is also how Dioxus frames `document::eval` interop. So step 3 is no longer "every remaining block becomes a TypeScript module". Instead:

- **Lane 3.0 builds the bridge.** One small typed module (`primitives/src/ts/bridge.ts`, through the existing bundle chain) with generic verbs only and no component logic. It covers listen, call, get, observe and match:
  - `listen(target, type, options, fields)`: window, document or element; `capture`, `passive` and `once`; it streams the named event fields to Rust over the eval channel and grows out of `js_listener.rs`'s `listen`, which already owns removal.
  - `call(el, method, args)`: `showPopover`, `hidePopover`, `showModal`, `close`, `setPointerCapture`, `focus({preventScroll})`, `scrollIntoView(opts)`, `setSelectionRange`.
  - `get(el, props)`: computed style values, `offset*`, `activeElement`, `visualViewport`.
  - `observe(el, kind)`: ResizeObserver, IntersectionObserver (with rootMargin and threshold), MutationObserver.
  - `matchMedia(query)`: a subscription.
  On the Rust side these are typed hooks and extension traits (`use_window_listener`, `el.show_popover()`, `use_media_query`), so the logic of every (b) block moves into Rust.
- **What the bridge cannot carry stays as named JS modules, each with a measured reason.** Bridge messages reach Rust asynchronously, so two kinds of work can't go through it. The first is a decision that must happen inside the listener call, such as a conditional `preventDefault` (wheel band, drag, Escape inside nested layers, OTP filtering). The second is read-then-write in one frame (anchor placement, the virtual scroll bridge unless 2D shows otherwise, carousel drag and wheel). Those become TypeScript modules as originally planned. The audit's (d) rows say which apply.
- **Expected effect:** class (b), about 25% of the JS, becomes Rust plus generic verbs. Class (d) shrinks to the parts that are genuinely synchronous. Class (c), pre-wasm, stays as is. Lane 3.0 is sized again once the bridge exists, and the per-cluster lanes then remove blocks against it.
- **Gate:** besides `check-js-in-rust.sh`, any new `eval` must use a bridge verb, or be a named module listed with its (c) or (d) reason.

## Step 3 adopted: named behaviours, a three-way placement rule, hardened gates (owner 2026-10-26, after the adversarial board)

The owner asked whether the "synchronous" residue could be bridged too. Analysis: [`../research/sync-js-root-2026-10-26.md`](../research/sync-js-root-2026-10-26.md) (the plan, revised after the board) and [`../research/sync-js-residue-2026-10-26.md`](../research/sync-js-residue-2026-10-26.md) (W8, C5, C1). The owner chose **Adopt**; an adversarial board of five then attacked the plan and returned "holds with changes" five times ([`../research/board-2026-10-26/SYNTHESIS.md`](../research/board-2026-10-26/SYNTHESIS.md); the reports are in [`../research/board-2026-10-26/`](../research/board-2026-10-26/)). This section is the hardened plan. **Root:** the browser takes its irreversible decisions at fixed points (end of dispatch, gesture start, input routing, paint, compositor frame), so only code on the page's thread with data already there can affect them. Rule: never ask Rust at commit time; Rust publishes beforehand and the page decides locally. Dioxus element handlers are already synchronous on web and on desktop/mobile (133 Rust `prevent_default()` calls rely on it); only the bridge is async. **Every desktop claim is "web-verified; desktop inferred"** until a `desktop-pass/<tree>.pass` stamp exists (row 442).

- **Order per block:** delete what is dead, then an rsx handler, then A (the platform: anchor positioning, `overflow-anchor`, `scroll-padding`, `linear()`), then R (bridge verbs plus Rust), then G (paint-safe gate), then a named behaviour. "No residue" is withdrawn: about 880 lines of (d) JavaScript plus the (b) behaviours stay page-side, as a **closed** registry whose size is reported in `STATUS.md` and held down by the ratchet.
- **The three-way placement rule (B).** (1) A target inside a Dioxus element, an event Dioxus supports, no listener option: an **rsx handler** (L1 `onkeydown` on the `<dialog>`, L2 `oncancel`, T4/T6 `ontoggle`). (2) A window, document or "outside" target, an event Dioxus lacks (`beforeinput`, `close`, `beforematch`), or the capture phase: one **named, typed behaviour** (`hotkey` for L6/O1/V22, `scrollLock{allowInside}` for L11/L10, `otpFilter`, `dropAnywhere`, `pan`, `settle`, `scrollStep`, and `dialogKeyForward` only if the specs need it), each declaring target, phase and passivity, installed by the owning Rust scope and ref-counted, so a blocking listener exists only while something needs it. (3) A continuous stream (scroll, resize, pointermove, wheel): bridge `subscribe`/`sample`, coalesced or flushed per event task, never a vdom handler (on desktop each is a blocking synchronous request; `check-hot-events.sh`). The first version's delegated capture-phase predicate interpreter is dropped: four members broke it (`closest()` finds only ancestors, capture makes `defaultPrevented` vacuous, a page-lifetime non-passive wheel listener brings back rows 149/159 and fails `listener-inventory.spec.ts`, and its families were unions of today's blocks). The Rust `Behaviour` enum and the TypeScript table stay one to one by generation (`cargo test` writes `behaviours.gen.ts`), each behaviour is a pure `decide()` plus a thin DOM adapter run against JSON vectors by `bun test` and `cargo test`, and has a fail-open path (WCAG 2.1.2) and an epoch.
- **Delete dead JavaScript first.** About 16 eval sites sit in `#[cfg(not(feature = "web"))]` arms that every supported build compiles only for Blitz, where eval is a no-op: all three focus-trap evals plus `ts/focus-trap.ts`, 5 of 6 `use_global_escape_listener` calls, one context-menu scroll-block install. L23 (Label double-click) is already `user-select: none` in CSS. A gate rule: no eval or JS listener in a `not(web)` item.
- **G, hardened.** Gate by `:popover-open:not([data-dx-placed])` (and the `dialog[open]` twin), cleared synchronously in `beforetoggle`; the pending style leaves no animation running or paused (`animation: none` semantics: a running or paused animation outranks `opacity: 0` and keeps its 0% `scale`); fail open through the enter animation's `animation-delay` with `forwards` fill, no JavaScript timer; a generation token from `open` drops stale answers. **Two tiers:** placement-critical (fallback engines, the iOS keyboard clamp) is gated; decoration (placed side, arrow, available height) is never gated, after the tooltip's `:not([data-placed-side])[data-side]` precedent; otherwise every popup open pays 2 to 4 frames on desktop. Pending states are opacity-only. T8 keeps a Rust "verify the outcome" step (Firefox once reported anchor support and failed).
- **W8, C5, C1, in the owner's order.** W8 is a Rust invariant ("end sentinel visible, else scroll to end") with native `overflow-anchor` as the accelerator, because the anchoring spec picks no anchor at offset 0 and skips clipped nodes. C5 stays a Rust attempt: flush per event task, a "Rust busy 30 ms" scenario, the replay harness's phase fixed; the owner measures it with an old/new switch (`?dx-impl`), and **if Rust loses it becomes an allowlisted TypeScript module**. C1 dissolves. Both legacy paths are frozen into `ts/legacy/` behind a non-default `legacy-impl` feature that only preview enables, with an expiring allowlist entry; `js_macros.rs` is deleted at the expiry deploy.
- **Enforcement closes sinks, not spellings.** One `eval` call site (`bridge/transport.rs`); clippy `disallowed_methods` for `document::eval`/`Document::eval`/`Script` outside it (aliasing and `concat!` cannot dodge it); a `git ls-files` universe; an allowlist of `Script { src: asset!() }` constants; a file inventory of hand-written `.js`/`.ts`; no inline-marker escape. `call`/`get`/`set`/`listen` take closed Rust enums mapped through closed TypeScript tables with a receiver kind per row (no `el[method](...)`); `passive` derives from the behaviour; `commit()` is dropped. Shrink-only ratchets compare against the merge base (`scripts/lib/ratchet.py`; raises carry `# raised: row N` and print as `RATCHET RAISES`), and the JS-volume ratchet lands before any port (lane R). **One gate owner** (lane 3.0, or a 3.0b follow-up).
- **Proof and measurement.** The slow-channel mode is a bridge-latency harness, not a desktop model. A desktop-cadence web build, Playwright WebKit and Firefox, and one WebKitGTK or real-desktop pass per batch recorded as `desktop-pass/<tree>.pass` close the gap (row 442). New specs: `bridge-cost`, `g-latency`, registry leak, first-frame, open/close/open, the stuck-channel fail-open. The owner measures the three feel-critical ports with `__dxPerf`, a bridge round-trip histogram, `?dx-bridge-delay=N` / `?dx-bridge-spin=ms` and the `?dx-impl` switch (row 443).
- **Lane order and estimate** (root doc section 5.4). Lane 3.0 (bridge) and lane R (ratchet, `js-interop.md`, CLAUDE.md, comment sweep) are in flight. Then **3.DJ** dead JavaScript (3 h); **3.PL** placement with T11 merged in and `top_layer/attributes.rs` added (24 h); the behaviour lanes **3.OV** overlay core (17 h), **3.FC** form and input primitives (12 h), **3.VS** virtual settle (10 h), **3.OB** observers (9 h), **3.SL** scroll lock (8 h), **3.GS** gestures and toast (13 h), **3.PV** preview glue (8 h), **3.QH** height glide (3 h), **3.CA** carousel (14 h), with per-module bundle outputs and the 43 formerly unassigned (b) rows grouped into them. **Last, one at a time, the owner measuring after each:** **3.MS** message scroller (20 h), then **3.WB** wheel band (12 h), then the `js_macros.rs` removal at the legacy-switch expiry deploy (2 h). About **155 agent-hours** after 3.0 and R (inferred, not measured; the first adopted plan said about 86, the audit's step 3 about 66), plus rows 442 and 443.
- **Dioxus best-practice review** ([`../research/dioxus-best-practice-review-2026-10-26.md`](../research/dioxus-best-practice-review-2026-10-26.md)): an eval bridge with no web-sys is what the Dioxus docs prescribe and what upstream dioxus-primitives does; no 0.8 API makes it redundant. Folded into lane 3.0: one transport seam (hooks never call `document::eval`; it owns the delay hook, a Blitz "unsupported" answer and a future web-sys backend, PR #5194), loading via `asset!` + `document::Script` with a bounded ready handshake (#5919), teardown over the existing channel (#4064), G fail-open in CSS (the harness gets `N = never`, #5734), leptos-use/dioxus-sdk hook names without a dioxus-sdk dependency. Web eval uses `new Function`, so strict-CSP apps need `unsafe-eval`.
- **Risk:** desktop and mobile are not in CI; G and R latency there is inferred. WebKitGTK anchor-positioning support is unknown, so the Rust placement arm stays until probed. Chromium is the only engine installed here, so A's Firefox/WebKit claims wait for row 442.
