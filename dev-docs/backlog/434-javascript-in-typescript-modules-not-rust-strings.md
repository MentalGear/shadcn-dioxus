# Row 434: Cut JavaScript to what Rust cannot do

## Item

The owner's principle (2026-10-25): the point of Dioxus is to drive the UI from Rust/wasm, so JavaScript is the exception, not the default. The library has no `web-sys` dependency; every browser API Dioxus does not wrap goes through `document::eval`, the one route that works on web, desktop and mobile. 72 files carry eval. The owner chose **Rust first** over "Rust plus web-sys" (one code path per feature, every renderer) and over the original TypeScript move.

1. **Audit** every eval block and classify it: (a) Dioxus already has it in Rust (`MountedData::get_client_rect`, `scroll_to`, `set_focus`, event data, signals, `onvisible`/`onresize` where they exist), so move it; (b) Dioxus has no Rust API (`showPopover`/`showModal`, `matchMedia`, pointer capture, listener options such as passive/capture, `scrollend`, `getAnimations`), so it stays JS; (c) must run before wasm (`PREPAINT_JS`, the modality writer), so it stays JS; (d) JS on purpose for latency (one-frame measure-and-place in the anchor engine, scroll bridge, virtual find), so it stays only with a measured reason.
2. **Move** every (a) block to Rust, per cluster, with the components' specs on a release build as the proof (timing-sensitive paths compare long tasks before and after).
3. **What stays** (b, c, d) moves into typed `primitives/src/ts/` modules through the existing bundle chain (the original P9 construction), and the copies become one file.

## Step 3 design: one small generic JS bridge (owner 2026-10-26)

The owner asked for a uniform small JS glue layer to Rust instead of many bespoke scripts, which is also how Dioxus frames `document::eval` interop. So step 3 is no longer "every remaining block becomes a TypeScript module". Instead:

- **Lane 3.0 builds the bridge.** One small typed module (`primitives/src/ts/bridge.ts`, through the existing bundle chain) with generic verbs only and no component logic. It covers listen, call, get, observe and match:
  - `listen(target, type, options, fields)`: window, document or element; `capture`, `passive` and `once`; it streams the named event fields to Rust over the eval channel and grows out of `js_listener.rs`'s `listen`, which already owns removal.
  - `call(el, method, args)`: `showPopover`, `hidePopover`, `showModal`, `close`, `setPointerCapture`, `focus({preventScroll})`, `scrollIntoView(opts)`, `setSelectionRange`.
  - `get(el, props)`: computed style values, `offset*`, `activeElement`, `visualViewport`.
  - `observe(el, kind)`: ResizeObserver, IntersectionObserver (with rootMargin and threshold), MutationObserver.
  - `matchMedia(query)`: a subscription.
  On the Rust side these are typed hooks and extension traits (`use_window_listener`, `el.show_popover()`, `use_media_query`), so the logic of every (b) block moves into Rust.
- **What the bridge cannot carry stays as named JS modules, each with a measured reason.** Bridge messages reach Rust asynchronously, so two kinds of work can't go through it. The first is a decision that must happen inside the listener call, such as a conditional `preventDefault` (wheel band, drag, Escape inside nested layers, OTP filtering). The second is read-then-write in one frame (anchor placement, the virtual scroll bridge unless 2D shows otherwise, carousel drag and wheel). Those become TypeScript modules as originally planned. The audit's (d) rows say which apply.
- **Expected effect:** class (b), about 25% of the JS, becomes Rust plus generic verbs. Class (d) shrinks to the parts that are genuinely synchronous. Class (c), pre-wasm, stays as is. Lane 3.0 is sized again once the bridge exists, and the per-cluster lanes then remove blocks against it.
- **Gate:** besides `check-js-in-rust.sh`, any new `eval` must use a bridge verb, or be a named module listed with its (c) or (d) reason.

## Step 3 adopted: rules as data, one interpreter (owner 2026-10-26)

The owner asked whether the "synchronous" residue could be bridged too. Analysis: [`../research/sync-js-root-2026-10-26.md`](../research/sync-js-root-2026-10-26.md). Root: the browser commits an event's default action when dispatch ends and paints after layout, so only code on the page's thread with data already there can affect either. Dioxus handlers are already synchronous on web and desktop (133 Rust `prevent_default()` calls rely on it); only the bridge is async. Rule: never ask Rust at commit time; Rust publishes the rule and its state into the DOM beforehand and one local interpreter decides. The owner chose **Adopt**. This replaces the bullet above that kept every in-listener decision and one-frame read-write as a bespoke module.

- **Layers per block, in order:** R (never really sync: bridge verbs plus Rust) -> A (the platform: CSS anchor positioning, `scroll-padding`, `linear()`) -> G (paint-safe gate: the pending state is invisible or pinned until Rust answers) -> B (a closed Rust `Rule` enum applied by one TS interpreter: B1 event gates, B2 drag/swipe recogniser, B3 measurement publisher, B5 reveal/settle) -> no residue: the owner asked why the last three could not move, and the follow-up ([`../research/sync-js-residue-2026-10-26.md`](../research/sync-js-residue-2026-10-26.md)) moves them too: W8 message scroller to A (native `overflow-anchor`, Baseline newly available since 2026-09-14) + R, C5 wheel band to a pure Rust classifier (`wheel_band.rs`) fed by a batched per-frame `sample` and proven by `cargo test` replay of the committed trackpad recordings (C2, page-side wasm, only if a desktop measurement fails), C1 macros dissolve. The gate's residue allowlist ends empty.
- **Lane 3.0 adds** to listen/call/get/observe/match: `transaction(ops)`, `commit()` (rAF plus forced style flush), `rules.install/remove` (also `data-dx-rule-*`), `sample(el, fields, until)` (coalesced or batched per field), `set(el, var, value)`; the `Rule` enum skeleton with B1/B2/B3/B5 regions; the slow-channel test mode `window.__dxBridgeDelayFrames = N`; and `scripts/check-bridge-rules.sh` (enum and interpreter switch one to one, no default arm; no `preventDefault`/`stopPropagation`/rAF/observers in `ts/` outside the bridge, the interpreter and a shrink-only residue allowlist; a new rule kind needs a backlog row).
- **Lanes after 3.0** (analysis section 5.4, about 64 agent-hours): batch 1: 3.B1 event gates, 3.PL placement A+G, 3.B5 reveal/settle, 3.QH height glide; batch 2: 3.GS gestures and toast, 3.CM context menu, 3.SF scroll fade; batch 3: 3.CA carousel C2-C4 (13 h). **Last, one at a time (owner 2026-10-26: the most uncertain ports, so the owner measures the UI/UX effect after each):** 3.MS message scroller to A + R (16 h), then 3.WB wheel band to Rust (10 h), then deleting `js_macros.rs` (1 h); each is its own batch and deploy, and the next starts only after the owner's measurement. Total about 86 agent-hours.
- **Dioxus best-practice review** ([`../research/dioxus-best-practice-review-2026-10-26.md`](../research/dioxus-best-practice-review-2026-10-26.md)): an eval bridge with no web-sys is what the Dioxus docs prescribe (web-sys is not portable to desktop/mobile) and what upstream dioxus-primitives does; no 0.8 API makes it redundant. Folded into lane 3.0: one transport seam (hooks never call `document::eval`; it owns the delay, a Blitz "unsupported" answer and a future web-sys backend, PR #5194), loading via `asset!` + `document::Script` with a bounded ready handshake (#5919), teardown over the existing channel (#4064) with element-bound rules dying with the element, G gates fail open (a CSS-only timeout; the harness gets `N = never`, #5734), leptos-use/dioxus-sdk hook names without a dioxus-sdk dependency, `data-dx-rule*` read by one delegated capture-phase interpreter, JSON conformance vectors run by `cargo test` and `bun test`. Web eval uses `new Function`, so strict-CSP apps need `unsafe-eval`.
- **Risk:** desktop and mobile are not in CI; G and R latency there is inferred. The slow-channel mode runs G-mapped specs at N = 0 and N = 2; code under G takes reads through `get` or follows them with `commit()`. WebKitGTK anchor-positioning support is unknown, so the G fallback stays until probed.
