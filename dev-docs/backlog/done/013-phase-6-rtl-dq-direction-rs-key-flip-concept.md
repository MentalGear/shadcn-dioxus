## Detail

**New primitive `primitives/src/direction.rs`** (unit-tested): a `Direction` enum (`Ltr`/`Rtl`), `DirectionProvider`/`use_direction(local: Option<Direction>)` (a local prop wins, otherwise falls back to the nearest `DirectionProvider` context, defaulting to `Ltr`), and `Direction::resolve_horizontal(self, key: &Key)` as the **single key-resolution site** every per-family flip below routes through, so "which physical arrow key means forward" is answered in exactly one place. Ported the *key-flip concept* from `dq direction.rs` (83 ln), not a larger, bloated single-file port, matching this row's own original scope and `plan.md`'s own Phase 6 framing ("the key-flip concept, not the 708-line file"). Per-family flips, each citing the specific Radix source file/line range it mirrors (see `direction.rs`'s own module doc and each component's inline comment): roving-focus arrow keys in `tabs.rs`/`radio_group.rs`/`toggle_group.rs`/`toolbar.rs`/`menubar.rs`/`navbar.rs` now resolve through `Direction::resolve_horizontal`; `DropdownMenu`/`ContextMenu` submenu open/close key and side are direction-aware (`menu_sub.rs`'s shared `is_submenu_open`/`close_arrow_key`); `Slider` mirrors its horizontal pointer/keyboard/visual mapping (`mirror_horizontal`/`mirror_offset`); `Select`/`ScrollArea` carry a `dir` attribute only; `Resizable` gained a `text_direction` prop that negates the handle-drag delta in horizontal RTL mode — `flex-direction` stays unconditional, **retracting** an earlier CSS handoff that would have added a `[data-direction="rtl"] { flex-direction: row-reverse }` rule (verified directly in `resizable.rs`: no such rule exists on the branch — the delta negation alone is correct); `Calendar`/`RangeCalendar`'s day-grid `ArrowLeft`/`ArrowRight` flip via a new `horizontal_day_step`. **FIXTURE DECISION** (`playwright/oracle/tier3-radix/rtl.spec.ts`'s own header): one `rtl` variant page per RTL-aware component (`/component/?name=<x>&variant=rtl&`), 13 components (`calendar`, `context_menu`, `dropdown_menu`, `menubar`, `navbar`, `radio_group`, `resizable`, `scroll_area`, `select`, `slider`, `tabs`, `toggle_group`, `toolbar`) — each `Demo` sets `dir="rtl"` and wraps its primitives in `DirectionProvider { direction: Direction::Rtl, ... }`, exercising `use_direction`'s "falls back to context" half (the "local override wins" half is already covered by `direction.rs`'s own unit tests); every component keeps an unmodified `main`/LTR control variant. Filed **tier 3** (Radix-parity, labelled opinion), not tier 1/2: `@radix-ui/react-direction` and each component's `useDirection` consumption is Radix's own design, not a W3C/APG requirement. `Resizable`/`Calendar` have no Radix/shadcn-with-Radix-primitive original to cite (shadcn wraps `react-resizable-panels`/`react-day-picker`, neither a Radix primitive); their rules are labelled an extrapolation, not a citation. 25 rules, 25/25 on the lane's own server; scoped through `#component-preview-frame`/`#component-preview-frame-<variant>`, since every variant of a component now renders on the same page at once (the same architectural fact behind row 45's own menubar/navbar locator fix). **The CSS half** (rtl-css lane + this batch's integration): 29 stylesheets converted from physical to logical properties by category (accordion, alert_dialog, calendar, collapsible, color_picker, combobox, command, context_menu, dialog, drag_and_drop_list, dropdown_menu, hover_card, input_otp, item, menubar, native_select, navbar, pagination, popover, progress, select, sidebar, slider, switch, table, toast, toggle, toggle_group, tooltip) — reading-direction concepts (`text-align`, `margin-left`/`-right`, `left`/`right` anchors) converted to their logical equivalents; screen-geometry facts (`data-side`, a drawer/sheet's own `side` prop) and transform-paired centering (`left: 50%` + `translate(-50%, ...)`, no logical equivalent in any shipping engine) kept physical, marked `/* rtl-physical: <reason> */`; non-zero `translateX`/keyframe values needing a sign flip got a `[dir="rtl"]` counterpart instead (navbar mobile menu, switch thumb, progress sweep, sidebar indent). New gate **`scripts/check-css-logical-properties.sh`**: **99 hits against the pre-existing base tree (`cbae695`) → 0**, after this row's own conversions plus this batch's integration audit of the 8 stylesheets the gate script had deliberately excluded pending that audit (`drawer`, `tag_group`, `sheet`, `resizable`, `navigation_menu` from batch 2; `date_picker`, `data_table`, `top_layer` from this batch — the last three had zero hits). That audit (commit `3ce62f5`, 16 hits total): drawer/sheet's per-side slide keyframes and resizable's handle/grip self-centering allowlisted under the same transform-paired-centering exemption already used for Dialog/AlertDialog/Command; `navigation_menu`'s `.dx-navigation-menu-content` `left: 0` → `inset-inline-start: 0` (mirroring `navbar`'s identical rule); `tag_group`'s `.dx-tag-group-remove-button` `margin-left` → `margin-inline-start`. `EXCLUDE` is now an empty set (kept, not deleted, for a future deliberate exemption). Wired into `.github/workflows/main.yml`, `README.md`, and `CLAUDE.md`'s gate list this same round (confirmed already present on this branch by this docs pass — not duplicated). **LTR value-preservation proven, not assumed:** `computed-style-snapshot.spec.ts` before vs. after — **27/29 zero diffs**; the 2 non-zero diffs both explained as unrelated (a calendar selected-day colour from an unrelated theme-token move on `main`; a progress bar's width from that demo's own random seed).
