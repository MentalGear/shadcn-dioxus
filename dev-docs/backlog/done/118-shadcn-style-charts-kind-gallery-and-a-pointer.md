## Detail

**Measured spec first** (`dev-docs/research/chart-parity-2026-10-03/shadcn-ux-spec.md`; live site probed via curl-routed requests because Chromium cannot load ui.shadcn.com through the sandbox proxy). **Tooltip:** the old one snapped to a fixed anchor per category (no `pointermove`), polar tooltips pinned at the chart centre, nothing clamped to the card, a touch tap left it closed. Now: area/bar/line x snaps to the nearest category (switching at the midpoint), y follows the pointer, box +10px right/below, flips left/above on overflow and clamps inside the chart (pure `place_tooltip`); horizontal bars swap axes; hidden outside the plot; pie anchors at the slice centroid; radar and radial follow the pointer (polar hover resolves from pointer coordinates against resting geometry -- arc `pointerenter` blinked because the active arc's scale moved it under the pointer); 200ms ease-out between positions, no fly-in on (re)open (hidden until measured), off under reduced motion; touch: tap opens and stays, drag scrubs, blur/tap-away closes; keyboard: arrows hang the tooltip off the data point, keyboard focus (not pointer focus) opens the first point like Recharts' `accessibilityLayer`; `default_index` (shadcn `defaultIndex`) renders it open until the user interacts, used by every Tooltips demo; active dot (r=4, series color, card-surface ring) on area/line; a `PointerGate` epoch stops a pointer result that resolves after a close from reopening it (synthetic move+leave stuck open 30/30 before); correct placement under scaled/zoomed ancestors (pointer fraction of the screen rect mapped onto the layout box); `touch-action` keeps pinch-zoom. `fit_width` (opt-in, Cartesian; later superseded by row 119's `height` prop) gave shadcn's `h-[250px] w-full` hero. **Gallery:** `/charts/` and `/charts/<kind>/` (area, bar, line, pie, radar, radial, tooltip), all prerendered: hero with Browse charts / Documentation, a text tab row (`aria-current`, scrolls on phones, keeps its offset and focuses the active tab on switch -- the router scrolled to top and dropped focus to `<body>` before; per-tab document titles), 1/2/3-column grid, each card with shadcn's toolbar (type icon + label, **Copy** = full source to the clipboard, **View Code** = 700px `Sheet`, `Drawer` on phones; Esc/overlay/close return focus). One footer construction for every demo (`CardFooter.dx-chart-footer` > trend + caption; five divergent patterns before, radar's bare divs ran trend and caption together). `area_chart` links its own stylesheet via `AreaChartGallery` instead of a rule mirrored into `main.css`; line interactive's stylesheet was never linked and its ticks read "Apr Apr Apr"; bar interactive totals were black on the dark card (bare `<button>` UA color). **Three fixes that fell out of it:** (1) **client id collision breaking the command palette** -- `use_unique_id` allocated `dxc-{N}` from one process-global counter shared across concurrently rendered SSG pages, so server ids landed anywhere (e.g. `dxc-200..330`) while a client-mounted component counted from 0 in the same namespace; the home page shipped two `id="dxc-229"` and `getElementById` returned the checkbox, so the palette never opened (`command.spec.ts:114`, deterministic on that build, random across builds). **By construction:** client allocations use a disjoint `dxc-c{N}` namespace, server ids unchanged, hydrated components still take the server's exact id via `use_server_cached`; tests cover both shapes and that no client id equals a server id. (2) **scroll-lock horizontal gestures** -- the modal scroll lock's wheel/touchmove handlers looked for a scrollable ancestor on the vertical axis only, so a horizontal swipe in a locked dialog (a wide code block in a bottom drawer) was `preventDefault`ed; the lookup is now axis-aware (dominant of dx/dy, RTL-safe `scrollLeft`); a touch drag moves the code block 0 -> 249px. (3) **copied demo code compiles in a user's app** -- every chart kind's `component.rs` imported `crate::components::chart::component::*`, but after `dx components add` `component` is a private module, so installed charts failed to compile (the repo only compiled because `examples!` made it `pub(crate)`); `examples!` now declares it private like an installed tree, imports use `crate::components::<name>::*` (charts, dialog, popover, label, alert_dialog, command, toast, dashboard email client), proven with a throwaway crate in the installed layout (`cargo check` passes; old path fails); Copy / View Code / CODE tabs show the installed import via one transform that remaps highlight spans, unit-tested over every demo. **Guards by construction:** new gate **`scripts/check-installed-paths.sh`** blocks the `...::component::*` import pattern; the `dxc-c{N}` namespace tests; `charts_gallery.spec.ts` (19 tests incl. clipboard, sheet/drawer focus return, no overflow 1440-320, three axe scans); `chart_tooltip_follow.spec.ts` (22 browser tests) plus placement-math unit tests against shadcn's measured offsets. **Evidence:** 249 chart/gallery specs on an SSG build (tooltip commit), 361/362 targeted specs on the deploy build (the one failure, `navigation_menu.spec.ts:128`, also fails on the previous deploy -- row 121), hero chart box identical before/after hydration, all nine Tooltips demos open at load with no fly-in, tab row stays at 120px across Area->Pie->Radar->Area, deploy 88/88 routes carry their bootstrap script, 0 not-found shells, 0 `<style><!--node-id`; demo sources lost ~570 lines of internal research comments. **Deliberate differences from shadcn:** gallery cards are 0.95x shadcn's width at 1440 (400px vs 419px: the site container is 1280px, shadcn's 1336px, so every 16:9 chart is a uniform 0.95 scale); no "Open in v0" action in the View Code sheet; tooltip position motion is 200ms ease-out (shadcn: 400ms) and never flies in from (0,0); the palette (see row 119). **Left open:** rows 124-126 (pre-hydration jumps, small visual nits).
