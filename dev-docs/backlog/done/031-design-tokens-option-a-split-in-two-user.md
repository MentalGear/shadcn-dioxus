# Row 31: Design tokens (option A) — split in two (user decision 2026-09-03). 31a — LANDED 2026-09-04. Token set added…

## Item

**Design tokens (option A) — split in two (user decision 2026-09-03).** **31a — LANDED 2026-09-04.** Token set added to `preview/assets/dx-components-theme.css` (today colour + dark-mode only): type scale (9 steps), spacing scale (16 steps on the 4px grid, matching Tailwind v4's default), radius scale (8), elevation/shadow (5, dark-mode-off per existing convention), motion durations/easings, breakpoints (reference-only — `var()` does not resolve inside `@media`, stated in-file), z-index scale (9 steps, all 25 existing literals map 1:1) — as CSS custom properties, which survive any outcome of row 32 (Tailwind v4's `@theme` block *is* CSS variables). Every scale was derived from a literal survey of the 46 component stylesheets, not invented; `line-height`/`font-weight` were deliberately NOT tokenised (no clean clusters emerged). The touch floor (row 30) is folded into `--dx-text-base`; row 39's ≥4.5:1 contrast requirement is stated in-file as a rule for future token pairs. Also landed: a small **generated utility sheet** — new `scripts/generate-dx-utilities.js` emits 336 atomic `dx-`-prefixed classes (spacing, gap, flex/grid basics, text sizes, radius, shadow) to `preview/assets/dx-utilities.css` from the token file, with a `--check` staleness mode, so it cannot drift; variants (`hover:`, `md:`, `data-[state]:`) stay in component rules, not in the generator. A shared `:where([data-dx-interactive])` interaction-rules layer (hover opacity / focus-visible ring / disabled opacity / reduced-motion, driven by tokens) was also added but is **scaffolding only**: nothing renders the `data-dx-interactive` attribute yet (wiring it onto components is `primitives/src` work), so the hover-opacity and disabled-opacity rules are inert by design; reduced-motion IS live today, via the same tag/role selector list `main.css` already uses for `touch-action`. **31b — LANDED 2026-09-04.** 683 substitutions across 44 component stylesheets, EXACT-value matches only: a literal is replaced solely when it equals a token's value in the token's own unit (`8px` where a token says `0.5rem` is left alone and logged as an informational note, never auto-swapped — that would be a real behaviour change under a consumer overriding the root font-size, a design decision rather than a mechanical one). Verified value-preserving by measurement, not assertion: `playwright/computed-style-snapshot.spec.ts` (a TOOL, skipped unless `DX_SNAPSHOT` is set) captured 24 computed properties across all 7,774 `dx-` elements on the 46 component pages before and after the migration — the diff is exactly one entry, `dx-progress-indicator`'s width, which re-samples to 34/54/32/54px on a single *unchanged* build because that demo animates, so zero real differences. `scripts/check-css-literals.sh` (new lint) enforces this going forward: exact-unit matches only, property-family-aware token suggestions (so `gap: 1rem` is never suggested as `var(--dx-text-base)` just because `1rem` also happens to be a type-scale step), scoped to the root `component.json`'s `members` (excludes `top_layer`, an oracle fixture whose hand-tuned geometry is deliberately literal). Several traps were correctly declined rather than tokenised: `tabs`' dark-branch inset ring, `dialog`/`sheet`/`toast`'s shadows with no dark/light wrapper (tokenising would have silently dropped the shadow in dark mode), `999px` (not `9999px`), and non-`--dx-ring` focus rings (3px, `color-mix()`, or component-local). **Important correction, discovered mid-round, worth recording as a third instance of a known bug class:** a first attempt consolidated 11 components' `:focus-visible` rings into the shared interaction layer by naming their classes directly in the global theme sheet (`.dx-checkbox:focus-visible`, …). That cannot work: `#[css_module]` hashes each class in **both** the DOM and the component's own stylesheet, so an unhashed selector written in a *different*, global sheet never matches — confirmed against the built artifact (the wasm carries `dx-alert-dialog-cancel-e59ac016` while the theme sheet said `.dx-alert-dialog-cancel`). Shipping it would have silently removed the focus ring from 11 controls (WCAG 2.4.7), so it did not ship: each component instead keeps its own `:focus-visible` rule, rewritten against the new `--dx-ring` token. Consolidation becomes possible once row 32 drops `css_module` hashing, or once `data-dx-interactive` is wired onto components. This is the **third** instance of the `css_module` hashing/scoping class — after row 32's own originating instance (the shared anchor-positioning `@supports` workaround) and row 47's (`select/style.css`'s dead `@supports` block) — cross-reference all three
