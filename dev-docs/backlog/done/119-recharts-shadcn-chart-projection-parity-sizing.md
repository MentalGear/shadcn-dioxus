## Detail

**Measured against shadcn's rendered SVGs and registry source (`dev-docs/research/chart-parity-2026-10-03/parity-A.md` (deleted by row 266; `git show 3c584cc2:dev-docs/research/chart-parity-2026-10-03/parity-A.md`), `parity-B.md`): the causes were engine semantics, not just demo data.** **Sizing:** a fixed 600x300 viewBox with counter-scaled text shrank strokes, dots and radii and flattened small charts (2:1 vs shadcn's 16:9). Now Recharts `ResponsiveContainer` semantics (`dev-docs/research/chart-parity-2026-10-03/sizing-contract.md`): 1 unit = 1 CSS px, 16:9 for cartesian, a <=250px square for polar, `width`/`height`/`aspect`/`margin` props (`height` replaces `fit_width`); legends reserved inside the box (`legend_size`). **Cartesian:** point x-scale for area/line (first/last on the plot edges), Recharts `getNiceTickValues` (305 -> 0..320, not 0..350), `Curve::Natural` and midpoint `Step`, Recharts bar sizing (`getBarPosition`) with per-corner `BarRadius`, active bar = dashed outline, `cursor` option, `min_tick_gap`/`tick_margin` thinning with preserve-end, Recharts gridline thinning, stack order = JSX order. **Polar:** Recharts angles (degrees, 0 = 3 o'clock, counter-clockwise), `Radius::Px`/`Percent`, radial sweep = value / max x (end - start), background tracks, `RadialGrid` circle grid + spokes, annulus, active slice outer+10 with halo, `PieLabels::Outside` with leader lines, radar nice ticks / anchors / per-series opacity / radius axis / custom ticks, corner fillets fixed. **Load animation** (bars grow, lines/areas reveal, arcs sweep) once after hydration, none under reduced motion (about 169 animations at load, none running after 2.5s, none replayed by hover). **Demos ported from shadcn's registry:** every area/line/bar/pie/radar/radial/tooltip demo now matches its registry source -- the interactive charts use shadcn's fixed 91-row dataset (ours was a synthetic sine wave; totals 24,828 / 25,010), radial Text/Shape/Stacked are partial arcs with shadcn's values (200, 1,260, 1,830), plus datasets, orientation, curves, colors, radii, margins, labels, cursor and tooltip props across ~70 demos; interactive headers use shadcn's layout (bar/line: the card's `display: grid` won on equal specificity and stacked the toggles); gradient areas were painted flat by a CSS `fill` that overrode the `url(#..)` attribute; the legend cards, the tooltip box (128px border-box, was 152px) and the code view (line numbers, not copied) follow. **Root cause class and construction:** demo data/props were hand-typed or invented rather than derived (parity-A "P" items 1-5 were all one class), so by construction the demos are checked against **vendored registry fixtures** (`preview/tests/shadcn/*.json`, extracted by `scripts/extract-shadcn-*fixtures.mjs`) by `preview/src/{chart,polar,chart_tooltip}_parity.rs`, which compare demo data, props and rendered geometry to shadcn's: 24 cartesian charts within 0.006 px; golden tests reproduce shadcn's ticks, curve control points (<0.002 px), bar widths and a measured arc table. Any future change to chart geometry or a demo that drifts from the registry fails `cargo test -p preview`. **Evidence:** 373/374 targeted specs pass on the SSG build (the one failure, `navigation_menu.spec.ts:128`, is pre-existing -- row 121); axe clean on every chart; deploy `scripts/deploy-preview.sh` 88/88 routes carry their bootstrap script, 0 not-found shells, 0 `<style><!--node-id`; gates: 13 check scripts, fmt, clippy, 913 tests, stylelint green. Visual pass (`dev-docs/research/chart-parity-2026-10-03/visual-parity.md`, 1440 light and dark, 390): every card matches except the deliberate/open items below. **Deliberate differences (kept on purpose):** (1) **palette** -- `--dx-chart-1..5` are blue, orange, green, amber and pink while shadcn's current site uses five blues, so series 2+ read orange/green where shadcn's read a darker blue (geometry unaffected); this is the **one deliberate difference left in the gallery** and is resolved by row 111's role tokens (`--chart-1..5`) -- the parity tests must stay green through that migration (row 111's chart tie-in); (2) **stacked radial** splits by the stack total (mobile 0-56 degrees, 570/1830 of the half turn) where Recharts clamps to the largest single value (1260; mobile 0-81 degrees, which clips desktop); (3) **gallery cards 0.95x shadcn width** at 1440 (row 118); (4) **no "Open in v0"** (row 118); (5) **200ms tooltip motion without fly-in** (shadcn 400ms; row 118); (6) **no-JS axis text hidden on fit-height heroes before hydration** (it fades in once the width is measured; the SSR box already has the final height so the marks sit within ~6px of final); (7) interactive x-tick labels start at a different date than shadcn's ("Apr 4" vs "Apr 2", "Apr 6" vs "Apr 3") because the chart is 1230px wide vs 1334px and preserve-end thinning differs -- width-driven, not a bug; (8) Radar and RadialBar keep their full square instead of giving room to the legend (Recharts centres Radar on the whole box). **Left open:** rows 124-125.
