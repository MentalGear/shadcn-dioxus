## Detail

**User decision (row 86 closed):** build the chart engine in-repo, shadcn-shaped (`ChartConfig` -> `--color-<key>` CSS variables, data-driven props, no children-as-configuration, no new Cargo dependency) rather than adopt `charts-rs`/`dioxus-charts`/a JS-engine wrapper — see `dev-docs/archive/rounds/component-backlog.md`'s Chart row for the full alternatives table. **Engine/layer seam (upstream-shaped by construction):** `primitives/src/chart/engine/{scale,curve,stack,geometry,table,data}.rs` is pure Rust with no `dioxus` types and no `use crate::` of this crate's other modules — a deliberate upstream candidate for `dioxus-community/dioxus-charts` (row 6 addendum below) — while `context.rs` (`ChartContext`/`use_chart`) bridges that plain data into this crate's own reactivity and `components/{container,chart,tooltip,legend}.rs` are the Dioxus-facing pieces. **d3-derived math, ISC attribution, ported not copied:** `LinearScale::ticks`/`nice_domain` are built against `d3-array/src/ticks.js`'s actual `tickSpec` magnitude-threshold arithmetic (`e10=sqrt(50)`/`e5=sqrt(10)`/`e2=sqrt(2)` cutoffs), and the `Monotone` curve against `d3-shape/src/curve/monotone.js`'s Steffen (1990) tangent formula — both ISC-licensed (Mike Bostock), cited by file+SHA in `engine/scale.rs`'s and `engine/curve.rs`'s own module docs, algorithm ports (JS to Rust) with commit-message/doc attribution, never verbatim text (see `dev-docs/archive/fork-research/lifting-from-forks.md` §1's new ISC note). **The Steffen three-way-min precision finding** (`dev-docs/archive/fork-research/chart-forks-2026-09-19.md` §4.1, the single most load-bearing finding in that survey): d3-shape's real tangent formula clamps against *both* neighboring slopes, `(sign(s0)+sign(s1)) * min(abs(s0), abs(s1), 0.5*abs(p))` — a three-way min. `feral-dot-io/leptos-chartistry`'s own MPL-2.0 Rust port of the same 1990 paper silently drops the `abs(s1)` term (a two-way min), which can overshoot near a local extremum; this repo's `engine/curve.rs` implements the correct three-way-min directly against d3-shape's own source, not a from-memory/secondary-source version, for genuine shadcn/Recharts visual parity — a caution recorded for the next person tempted to port from a *sibling* library's Rust code instead of the *canonical* JS source. **A11y contract** (`dev-docs/archive/research/chart-2026-09-19.md` §2.5, ahead of the field: the forks survey found ZERO accessibility semantics — no ARIA/role/tabindex at all — in every non-shadcn/Recharts-lineage chart library surveyed, `leptos-chartistry`/`yew-chart`/`dioxus-charts`/`rust-ui/dioxus-ui`'s ApexCharts DOM all included): `svg[role="img"]` + required `aria-label` + `<title>`/`<desc>` (WAI-ARIA Graphics Module 1.0's own `img` definition — a single indivisible graphic, no claim of internal navigability); a real, visually-hidden `<table>` mirroring the exact series/category/value data as the actual, free, natively-keyboard-navigable screen-reader path; legend swatches `role="graphics-symbol"` (the Graphics Module's atomic-repeated-glyph role) + `aria-label`; optional (default on) arrow-key/Home/End/Escape stepping of the active index, cited to Recharts' `accessibilityLayer` as a tier-3 opinion, additive only, never `role="application"` (which would strip screen-reader browse-mode navigation the hidden table makes unnecessary to sacrifice). Oracle: `playwright/oracle/tier3-radix/chart.spec.ts` (folder name deliberately KEPT, not generalized to `tier3-opinion/`, per the research's own §6.5b decision point — its header names Recharts' `accessibilityLayer` as the behavior/keyboard opinion source and the WAI-ARIA Graphics Module 1.0 as the role source, since Chart has no Radix primitive to calibrate against at all, confirmed by cloning `radix-ui/primitives` and finding zero chart files) plus `playwright/chart.spec.ts`'s own smoke+axe tests — 13/13 (8 rules across 10 tests in the oracle file, 3 in the smoke file), verified live against the integration server. **The `<title>` SVG-namespace note:** `dioxus-html` 0.7.9 has no SVG-namespaced `<title>` element, so `Chart`'s `<title>` (inside its `<svg>`) is built without the SVG namespace when Dioxus creates the DOM directly (confirmed by reading `dioxus-web`'s `create_template_node`) — a CSR-only-page-load discrepancy that does NOT affect this repo's actual deployed site (SSR + hydrate: the browser's own HTML parser correctly parses a `<title>` nested in `<svg>` *source text* as an SVG title per the HTML5 foreign-content spec regardless of Dioxus's per-element namespace table, and hydration reuses that already-correct node) — confirmed to NOT produce a hydration error in this round's own SSG execution (`hydration-parity.spec.ts` Rule 2/2-extended: PASS, part of an overall 11/11 against a real 72-route release build); documented in `Chart`'s own module doc, not fixed (not fixable from inside a primitive component). **Two integration-owned fixes, found live against a running server (neither caught by compilation):** (1) the hidden table's corner `<th>` was empty (`th {}`), which axe's `empty-table-header` rule correctly failed on every scan and regressed `preview.spec.ts`'s homepage a11y scan (the homepage renders every component's `main` demo) — fixed with a new `x_label: String` prop (default `"Category"`) rendered as the corner `<th scope="col">`; (2) the `main` demo's 90-datum view drew 90 overlapping one-per-day x-axis tick labels — fixed with a new `max_x_ticks: usize` prop (default 12), a pure `x_tick_step` stride function labeling only every `ceil(n / max_x_ticks)`-th datum (always the first), documented as MVP count-based thinning with the forks survey's width-aware alternative (`leptos-chartistry/src/ticks/gen/aligned_floats.rs`) cited as the stage-2 follow-up. **A third integration fix, found by direct inspection while writing this docs pass, not by any spec:** the themed `preview/src/components/chart/component.rs` wrapper reconstructs its inner primitive call field-by-field rather than spreading its own `ChartProps`, and that manual list predated `x_label`/`max_x_ticks` -- a caller's override of either compiled fine but was silently dropped before ever reaching the primitive (no spec asserts the corner header's specific text, and the primitive's own unit tests construct `Chart` directly, bypassing this wrapper). Fixed by adding the two fields to the forwarding list; verified live (`main`'s corner header now reads its own "Date" override, `bar`'s reads the default "Category"). **Out of scope, deliberately:** Pie/Radar/Radial (deferred to future lanes; `engine`'s file split leaves room for a `polar.rs` alongside `curve.rs` without disturbing this round's files — research's own §6.8 stages 3-5); tunable margins (`MARGIN_*`/`BAND_PADDING`/`GROUP_PADDING` in `chart.rs` are fixed MVP constants, not props — a themed-CSS-first precedent this repo's other multi-part primitives, e.g. Resizable, already follow); memoization (`Chart`'s scale/tick/geometry pipeline is plain, unmemoized Rust computed fresh on every render — confirmed by reading the component, no `use_memo` anywhere in `chart.rs`/`context.rs` — and since `active_index` is read at `Chart`'s own top level rather than behind a memo boundary, every hover-driven cursor move re-triggers the FULL pipeline, not just the cursor's own position; a real, not-yet-measured performance question for a future round, not a correctness gap).
