## Detail

**2026-09-26 (audit batch): Navbar sub-item FIXED** in `7a2f68e` -- confirmed dead by in-page rAF sampling (open→closed in one frame, unmounted the next); the ENTRANCE was dead too. Fixed by the Navigation Menu construction: `use_popover_shown_while_mounted` instead of `use_popover_sync`, and `@keyframes ... forwards` instead of transitions (beats the inline `transform: none`). `navbar.spec.ts` regression test red 3/3 on main, green 3/3 fixed. Known, accepted limit: a close forced by the browser's own `popover="auto"` light dismiss still skips the animation. **Six user reports, each root-caused and fixed independently; the batch-2 lane hand-backs and its integration report are this row's source, cited here as session scratchpad, not as a repo artifact.** **Command palette first-open focus** (`1e6ae0f`): `command.rs` keeps its existing `autofocus` on the input and adds an `onmounted` → `spawn(set_focus(true))` backstop, mirroring the pattern `toggle`/`slider`/`dropdown_menu` already use, plus a forwarding `onmounted` prop. Root cause unconfirmed — the defect never reproduced on the CSR `dx serve` dev server across 40+ trials; the original report was against the deployed SSG+hydration build, so the backstop covers the class regardless. Follow-up: execute the SSG lane (row 22) to confirm against the build shape that actually showed it — batch 3. **Data Table filter question:** no defect — the existing predicate already matches shadcn's TanStack `includesString` (trimmed, case-insensitive substring). `0c0f627` gives the existing behaviour a name (`state.rs`'s `includes_string`, exported from `component.rs`) and 8 unit tests, changing nothing about how it matches; the dashboard email client's `filters.rs` has the identical shape, left untouched as a candidate for a future shared helper. **Closed 2026-09-19 (batch 3 integration, `b22a222`):** `filters.rs`'s `message_matches_search` now routes its five `.to_lowercase().contains(&query)` sites through `crate::components::data_table::includes_string` instead of its own manual trim+lowercase local, dropping the duplication this row's own text flagged — and fixing a latent bug along the way, found by the leftovers lane while proposing the refactor: `tag.label().contains(&query)` never lowercased the label side, so a mixed-case tag search silently under-matched. **Tag Group sizing** (`090d9f1`): confirmed NOT a token-migration regression (row 31b) — an audit of all 41 stylesheets row 31b touched found 363 exact-value matches and 130 equal-value unit rewrites, 0 mismatches, and upstream `bf007c1` renders the identical 20px tag today; the real, pre-existing gap is `text-sm` sizing plus `padding-block: var(--dx-space-1)` and `min-height: var(--dx-space-7)` under `border-box`, now rendering a 28px-tall tag (was 20px). **Sheet** (`12a8f86`): a shadcn/ui v4 translation pass — overlay tint moved onto the `<dialog>`'s own `::backdrop` on the web arm (the UA's `dialog::backdrop` opacity was stacking with the root tint, measuring ~55% instead of shadcn's 50%), `--dx-shadow-lg`, `sm:max-w-sm` gated to `@media (width >= 40rem)`, a 500/300ms slide, close-button `size-4`/`rounded-xs` — plus the Drawer-class centering fix, see row 78. **Resizable** (`47c6291`): the handle/grip were reading the wrong token pair (`--secondary-color-3/4`, a foreground-ish gray) instead of the border pair every other divider in this app uses (`--primary-color-6/7`); handle width corrected 4px → 1px (with a 4px `after:` hit area), grip 16×24px → 12×16px, demo container gained `max-w-md md:min-w-[450px]` (was unconstrained at ~269px against shadcn's 450px reference). Deliberate deviation, not a gap: shadcn's `h-[200px]` fixed content height is NOT translated, because this primitive's panels are pure-CSS flex-basis percentages over `overflow: hidden`, not react-resizable-panels' JS-measured layout — a fixed height clipped the nested 25% panel, caught by screenshot before it shipped. **Navigation Menu "width reflow"** (`08a14d8`): not a width transition — rAF sampling showed a constant width throughout; the panel-swap animation was dead, so switching between differently sized panels popped instantly, read by the reporter as a layout reflow. Two independent causes: (1) the `transition` rule, at the normal cascade tier, can never outrank the INLINE `transform: none` that `use_anchor_position_fallback` sets on every render (Navigation Menu sets no `data-side`/`data-align`, so the JS positioning fallback always engages, even on engines with native CSS Anchor Positioning); (2) the web arm's `use_popover_sync` calls `hidePopover()` synchronously on close, removing the content before any exit animation gets a frame. Fixed with `@keyframes`/`animation` (outranks an inline style) plus `use_popover_shown_while_mounted` (the same hook Tooltip/HoverCard/Popover/`SelectList`/`ComboboxList` already use for this exact reason, row 19) and `width: max-content`, gated by `prefers-reduced-motion`. The same commit adds the keyboard surface row 72 had deliberately left out (Home/End, panel Up/Down stopping at the ends, ArrowDown opening a closed trigger and focusing its first item) and fixes three latent bugs the keyboard work surfaced: content children mounting in reverse source order (now an explicit caller-supplied `content_index` prop), native Tab focus never syncing into the roving-focus collection (`collection.set_focus`, matching toolbar/tabs), and a stale-value no-op in the Escape-refocus handler. **Follow-up, outside this row's ownership:** `navbar.rs` pairs the identical `use_animated_open` + `use_popover_sync` combination, so it likely carries the same dead exit-animation defect (cause 2 above) — not investigated or fixed here. **Drawer, ×3 fixes, one shared construction** (`7310b89` + `2bf6489`): (1) the native `dialog`/`dialog:modal` UA stylesheet centers the panel as a floating card instead of anchoring it to its edge — the SAME class as Sheet's centering bug above, see row 78 for the shared construction and the sweep of the rest of `dialog.rs`'s consumers; the overdrag gap the fix leaves is covered by a solid `filter: drop-shadow` extension 40px past the edge (a `box-shadow`/`::after` would be clipped by the panel's own `overflow`). (2) `user-select: none` on the drag handle and on content while dragging, and the handle's `touch-action` corrected from `none` to a per-side `pan-*` value. (3) `DrawerClose` had no styling at all, so dark mode rendered the UA `ButtonFace` background at a measured 1.28:1 contrast — now styled like `.dx-button[data-style="outline"]`. `2bf6489` additionally makes the drag-continuation effect read `active_pointer_id` with `.peek()` (row 79) while keeping `dragging` under a tracked read as the effect's own wake switch. All six were verified live against the shared `:8080` server during batch-2 integration (per-lane table in the integration report, cited here only as session scratchpad, not re-run by this docs pass)
