Owner condition (2026-10-21): change only what a measurement shows holds up. Result of the audit (`/mnt/project-files/test-speed/row-331-sweep-audit.md`) and of this lane: **no sweep was deletable by a gate** (each gate scans sources or one namespace, each spec reads a browser-computed or served result), so nothing was deleted; five sweeps were shrunk to a set that provably carries every case the old sweep carried, and the golden half of `theme-all-reset` was kept.

**Stale claims in the original text, corrected.** (1) `stylesheets-present` was listed for deletion; it is already a sample of route types, not a sweep, and with the 6 retained `dx-class-migration` pages is the browser proof that delivery works: kept as it is. (2) "`demo-forms-no-navigation` is covered by `check-demo-forms.sh`": the gate scans `preview/src` only and cannot see the rendered `method` attribute or the served HTML (attribute merge, row 224; a form from a dependency). (3) The `rtl-toggle` overflow probe is not vacuous: measured, `html`/`body` are `overflow-x: hidden/clip`, so an in-flow 2000 px element adds nothing (`scrollWidth - clientWidth` = -15, the scrollbar gutter) but an absolutely positioned element that escapes `body` (`right: -2000px`) adds 1985-2000, in LTR and under the RTL toggle alike; it catches a positioned element sticking out of the page, not an in-flow demo that is too wide. (4) `user-select`, `touch-double-tap` and `theme-all-reset` were "once row 330 lands": they read browser-computed values the row 330 gates cannot see, so they shrink, they do not go. (5) `check-press-under.sh` exists on main since batch A (row 295); `check-touch-action.sh` never existed (`touch-action` is arm 1 of `check-theme-baseline.sh`). (6) the audit's mutation probe 4 (add `touch-action: auto` to a raw element) could never go red: `main.css` carries the `!important` backstop (`button, [role=button], a[href], input, ...{touch-action: manipulation !important}`), so the real defect is the backstop list losing a family; probed that instead. (7) `dx-class-migration` "still guards the `dx serve` copy-out path": it runs on the SSG build where the bundle covers every sheet, so it does not exercise that path.

**`theme-all-reset` golden half: kept, row 258 fixed.** The owner's test was whether a re-baselined golden catches something `check-theme-baseline.sh`, the per-control computed-style tests, `check-popup-root-reset.sh` and the slimmed `popup-style-isolation` do not. Against today's build the four golden records are unchanged (all four passed unmodified, so there was nothing to re-baseline). Probe: appending `cursor: default; text-indent; appearance: auto` (Switch), `transition-property: none; cursor: default` (Slider thumb), `letter-spacing; border-width: 3px` (ColorPicker slider thumb) and `text-shadow; word-spacing` (area thumb) to the shipped sheet went red in 4 of 4 golden tests and in none of `switch`, `slider`, `slider-thumb-clip`, `color-picker`, `color-picker-touch`, `overlay-switch` or the file's own per-control tests (47 passed, 4 failed, all four the golden). The two gates scan sources for the `all:` ban and the two theme rules and read no computed value, and `popup-style-isolation` compares a popup with its own clone so a sheet-level change reaches both sides (reasoned from their construction, not run on the probe). So it uniquely catches a dropped or altered reset line (appearance, cursor, text-indent, letter-spacing, transition-property, border widths) on the four controls, which is exactly what row 239's `all: unset` removal risked. Cost: 8.5 s of 721. Row 258 (the cp-area-thumb `20x19.99999` sub-pixel flake) is fixed in the same file by rounding `rect` to 2 decimals in the record and the reader (Switch `32x18.39`); not closed as obsolete.
