**Open owner question:** should Popover be non-modal by default (shadcn / Radix parity)?

## Status / trigger

Modal-dependent tests (focus trap, scrim, fade-out, axe-open, native-dialog Rule 8, scroll-lock, main-thread, top-layer-ink, listener-inventory) moved to the new explicit `popover/variants/modal`; new `playwright/popover-non-modal.spec.ts` (wheel/PageDown scroll with the popover open, no lock marker or overflow change, outside click reaches its target, Tab not trapped). **Breaking change:** code relying on the old default must pass `is_modal: true` (noted in `popover/docs.md`). ## Detail

**Today:** `PopoverRoot`'s `is_modal` defaults to `true` (`primitives/src/popover.rs:114`): focus is trapped, the page behind is inert, a click outside dismisses, and the scroll lock is taken while it is open (`is_modal() && open()`, `:399`); `overlay` (default `false`, like shadcn) controls the scrim separately. shadcn's Popover (Radix underneath) is non-modal by default: the page stays interactive and light dismiss closes it. **What depends on modal (the theme lane's list; not re-verified here):** 8 popover tests, the native-dialog oracle's Rules 6 and 8 (`playwright/oracle/tier2-html/native-dialog.spec.ts`), the main-thread and top-layer-ink entries, and the scroll lock. **Cost of flipping:** every modal-dependent test and demo must pass `is_modal: true` explicitly or be rewritten for the non-modal arm, and it is a behaviour change for existing users (a breaking-change note). **Cost of not flipping:** a shadcn Popover example pasted into a Dioxus app behaves differently (page inert, scroll locked), the surprise parity work exists to remove. **No recommendation recorded: the owner decides.** If yes, it joins the parity wave (row 155) as a tenth group, after 145's floating-surface lane; if no, record the reason here and close the row. **2026-10-05 (round 3):** the scrim half landed separately and does not answer this question: Popover has an `overlay` prop (default false, like shadcn) and a `variants/overlay` demo, through the theme's `data-dx-overlay="off"` rule (row 141). Modality (focus trap, inert page, scroll lock, light dismiss) is untouched, and the modal Popover's web arm now calls the shared dialog driver, so a flip of the default would not need its own close logic. **OWNER DECISION 2026-10-10: APPROVED.** Make Popover non-modal by default, like shadcn/Radix/Base UI. The target behaviour: (1) focus moves in on open and returns to the trigger on Escape; (2) the page stays interactive and scrollable (no inert, no scroll lock); (3) one outside click closes it AND reaches its target (no swallowed first click); (4) modal stays available as `is_modal: true`. **Consequences to do with the flip:** the ~8 popover tests, and the native-dialog oracle's Rule 6/8, main-thread and top-layer-ink entries that assume modal, move to an explicit modal demo variant (`is_modal: true`), and the non-modal default gets its own coverage for 1-3; add a breaking-change note for existing users. The "No recommendation recorded" sentence above is superseded by this decision. **OWNER ITEM 2026-10-11 (page scroll):** original shadcn's Popover does not block page scroll while it is open; ours does, because the default is modal and the modal path takes the scroll lock (`use_scroll_lock(is_modal() && open())`, `primitives/src/popover.rs:399-400`). The scroll lock is therefore part of this flip, not a separate fix: the **non-modal default must not engage the scroll lock** (and must not add the scrollbar-gutter compensation or `overflow: hidden` on the body/root), and **only `is_modal: true` may** engage it. The gating already exists (`scroll_lock_active` is false unless `is_modal()`), so flipping the default is what removes the lock; what is missing is coverage. Add a non-modal spec (open a Popover on a page taller than the viewport, `mouse.wheel` / `scrollTo` moves `scrollY`, `getComputedStyle(documentElement).overflow` and the body's are not `hidden`, no scroll-lock marker attribute; close it, nothing to undo) and keep the modal arm's existing lock/unlock assertions on the explicit `is_modal: true` variant, so the class (a non-modal overlay holding the page) cannot come back unnoticed.
