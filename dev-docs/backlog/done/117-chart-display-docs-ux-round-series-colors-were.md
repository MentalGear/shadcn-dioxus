# Row 117: Chart display + docs UX round: series colors were black/grey/invisible on every SSG page, plus a docs-site UX…

## Item

Chart display + docs UX round: series colors were black/grey/invisible on every SSG page, plus a docs-site UX sweep (PR #79)

## Status / trigger

**LANDED 2026-10-03 -- MentalGear/dioxus-components#79 (merged `98c430f`).** Reported by the owner against the deployed site: every chart drew black bars, grey areas and invisible lines

## Size

M

## Detail

**Root cause (the headline defect):** `ChartContainer` emitted its `--color-<key>` rule as dynamic text inside a `<style>` element; Dioxus SSR prefixes dynamic text with a hydration marker, so the shipped CSS was `<style><!--node-id444-->[data-chart="dxc-394"]{...}` and Chromium parsed it as the selector `node-id444-- > [data-chart=...]` (confirmed via `sheet.cssRules`), which never matches -- `--series-color` was invalid and marks fell back to `fill: black; stroke: none`. Second live instance of the same class: `virtual_list`'s `random_heights` demo lost its first CSS rule the same way. **By construction:** the colors are an inline `style` attribute on the container's own element (attribute values never get hydration markers; caller style folded in after, so it can still override); the four demos that did `style { {CONST} }` use a string-literal child; new gate **`scripts/check-raw-text-interpolation.sh`** fails on any rsx `style {}`/`script {}` (also `noscript`, RCDATA `textarea`, path-qualified names) with an interpolated child -- reports all 5 sites on the old tree, passes now. **Also fixed in the same round:** pie/radial arcs were one near-black (a `chart-arc` rule's `fill: var(--series-color, currentColor)` overrode the per-arc fill attribute; rule removed); the visually hidden data table is wrapped in a clamped `chart-data-wrapper` (a table box cannot shrink below min-content and widened phone pages to 418-727px); tooltip values were invisible (color was `--primary-color`, the page background: 1.00:1 light / 1.06:1 dark; now 18.9:1 / 13.4:1); axis ticks had no `text-anchor` (x = middle, y = end + central baseline, offsets within 0.5px; `direction="ltr"` pinned on the svg root); SVG text had no fill rule and computed black in both themes (a zero-specificity `:where()` base rule themes it; arc labels get a paint-order stroke halo, 12.5:1 dark / 18.9:1 light); chart-id fragments (`safe_fragment_id`, now injective -- `'a%'` and `'a_25'` collided). **Intermediate constructions that were wrong and replaced (kept as the record, superseded by row 119):** a measured-width logical size, then a fixed viewBox with a counter-scaled `--dx-chart-text-scale` (clamp 1..2, then 0.5..2.5) -- an independent review showed caller-authored lengths (radii, bar radius, label insets) stayed in props units and donuts collapsed to 1px hairlines at 390; row 119's 1-unit-equals-1-CSS-px sizing removed the whole class. **Docs UX (same PR):** new `ComponentCategory::Charts` sidebar group (all 8 chart pages; most used to hide in the Data display fallback), chart docs rewritten for library users (real props/defaults, stale claims corrected against the code, samples that did not compile fixed), `build.rs` enables pulldown-cmark tables/strikethrough/task lists (only `ENABLE_GFM` was set, so pipe tables shipped as raw `\|` text; tables wrapped in a scroll container); **base-path-safe links** (docs.md used root-absolute `/component/?name=x`, which 404s on Pages; now canonical `/component/<name>/` prefixed with `router().prefix()`) guarded by new gate **`scripts/check-internal-hrefs.sh`** (fails on root-absolute `href` literals in preview `.rs` and the legacy `?name=` form; navigation_menu's demo hrefs were the second instance); phone header one 54px row at 390 (was 3 rows, 151px) and 16px gutter (was 0 at <=760px), `<=340px` header steps (0 pairwise overlaps at 300-390), footer stacks at <=760px, Resizable thumbnail clipped on phones, demo frames use 12px at <=480px (the rule never applied: `tabs/style.css` loaded later at equal specificity), `minmax(0,1fr)` page-header grid so the inline command ellipsizes, `scrollbar-gutter: stable` set statically on `html` (CLS 0.115 -> 0.0003 on `/component/chart/` at 390), dark link blue `#0065ff` -> `#4d94ff` (3.8-4.3:1 -> 6.2-7.0:1), six chart pages no longer repeat the template's "Variants" `h2` (a test fails if any docs.md reuses a template-rendered `h2`), main demo x-axis read "Apr Apr Apr" (default tick format kept 3 chars of "Apr 1"). **Evidence:** SSR tests in pre-render mode (no `<style>`, colors in the style attribute); a real SSG build has 0 files matching `<style><!--node-id`; every bar/area/line/arc computes a real color in light and dark; 183 then 209 chart specs green on the SSG build; 294/294 specs on the final tree (8 chart specs, sidebar, navbar, navigation_menu, command, dx-class-migration) with 91/91 navigation_menu links resolving 200; 9 pages x 1280/390 x light/dark with `scrollWidth <= clientWidth`; deploy smoke 80/80 routes carry their hydration script, 0 not-found shells, 0 black/invisible marks. 13 check scripts, fmt, clippy, stylelint green. (Also `8076526`: a clippy `unnecessary_cast` in a carousel test under rustc 1.97, and `.gitignore` now covers every `target-*/`.) **Left open:** rows 120-128 (found in this round; **2026-10-05: 122, 123 and 128 have since LANDED, the rest are open or in this round, see their own rows**). The two classes found here -- dynamic text in raw-text elements, root-absolute internal links -- are closed by their new gates, not by instance fixes.
