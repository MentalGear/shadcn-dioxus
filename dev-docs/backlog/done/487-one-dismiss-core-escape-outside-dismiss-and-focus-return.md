# Row 487: One dismiss core: Escape, outside dismiss and focus return for every overlay

## Item

Every overlay closes the same three ways (Escape, a press outside, focus handed back to the trigger), yet each does it by its own code: placement and top-layer sync are shared already, dismissal is not. Construction: one dismiss core that takes a per-overlay policy (which keys, which outside presses, whether focus returns, whether a nested layer owns the Escape), so a rule such as "a touch press outside is a tap, not a touch" lands once and reaches every overlay.

## Status / trigger

Phase 1 merged in PR #159 and deployed in `1ea333fa`; the Escape-gap rule merged in PR #164; phase 2 (the menu family on the core, row [435](./435-one-menu-family-behind-three-hosts.md)'s hosts) landed in PRs #165 and #166 (2026-11-06). Phase 2 items 5 and 6 done (the dialog backdrop press and the Combobox touch tap, see "Phase 2 items 5 and 6" below); item 7 is row 456's (the `DISMISS_JS` port), so this row is done. Prioritised with row 435 (owner 2026-10-31): the single overlay engine is finished before the Rust ports. [Row 456](../456-port-3-ov-overlay-core-escape-dismiss-open-focus.md) then ports one core instead of the scattered handlers.

**Phase 1, what exists.** `primitives/src/dismiss.rs` is the core: an overlay passes a `Policy` (`escape`: `Ignore` / `Close` / `Native`; `press`; `focus`) and a root (an element id, or the nearest `closest` ancestor of it) to `use_dismiss`, and gets an `on_dismiss(Cause)` call (`EscapeWithin`, `Escape`, `OutsidePress`, `FocusLeft`). The page half is one legacy script (`DISMISS_JS`, `lib.rs`) that replaces three: the global Escape listener, the outside-press listener and NavigationMenu's own. Layers register on one page-side list (`window.__dxDismissLayers`) ordered by when they opened, so the topmost layer takes Escape and the decision is made inside the key's dispatch; a `Close` layer cancels the key's default action, a `Native` layer (a modal `<dialog>`, a `popover="auto"`) stays in the order and leaves the key to the browser. A mouse press dismisses on `pointerdown`; a touch or pen press is a tap (row 477's rule), for every surface that has a press arm. `use_outside_dismiss` keeps its signature (it is `Policy::OUTSIDE` on the core), and `RefocusTrigger` / `use_refocus_on_close_unless` are unchanged for the menu hosts.

**Moved onto the core (policy per surface, also the table in `dismiss.rs`).**

| surface | Escape | press outside | focus leaving | Escape sites removed |
|---|---|---|---|---|
| Tooltip | close | no | no (blur closes it) | trigger `onkeydown` |
| HoverCard | close | no | no (blur closes it) | trigger and content `onkeydown` (web and native arms) |
| NavigationMenu | close, focus back to the trigger when it was inside the nav | yes, hover and click activation (the tap rule now reaches it) | no (its own blur debounce) | trigger and content `onkeydown` (both arms), `NavigationMenuOutsidePressDismiss` and its listener |
| Navbar | close, focus back to the trigger when it was inside the content | native `popover="auto"` light dismiss, measured equivalent (spec) | no | the root `onkeydown` Escape arm |
| Select | close (also from the trigger after Alt+ArrowDown) | yes | yes | list and trigger arms (kept on the arm without script only) |
| Combobox | close | press outside the input, list and clear button: yes, a mouse press at once and a touch or pen press as a tap (Base UI's `outsidePressEvent: { mouse: 'sloppy', touch: 'intentional' }`; owner rule 2026-11-06: align with Base UI unless ours is better); the input's blur closes it too | no | the input's open-list arm (kept on the arm without script only) |
| Popover, Dialog, AlertDialog (web) | `Native`: the browser's `cancel` / light dismiss, in the order | native (`popover="auto"`; modal Dialog and Popover: the backdrop press, `Press::Backdrop` of the core, tap rule for touch and pen; AlertDialog: none) | no | none (`use_global_escape_listener` is gone from the native arms) |
| Popover, Dialog (arms without script) | close | yes | yes | `use_global_escape_listener` |
| AlertDialog (arm without script) | close | no | no | `use_global_escape_listener` |

Escape is now document-wide for Tooltip and HoverCard (WAI-ARIA tooltip: "Escape dismisses the tooltip" wherever focus is) and nested: a Select, a Popover or a Tooltip inside a Dialog takes the first Escape, the Dialog the second.

On the pre-change build (`pub-docs422`, no nested fixture) 47 passed and 7 failed: the four nested cases (fixture absent), the Combobox and DropdownMenu table rows that the spec now records as measured policy, and NavigationMenu click activation, whose touch scroll that starts outside closed the panel (its own `pointerdown` listener); on the phase 1 build all 52 pass. JS volume: `js_lit` 3,866 -> 3,860 and `JsListeners::install` sites 44 -> 42.

**The gap before a layer is on the page (2026-11-03).** A layer registers on the page after its panel has mounted, a pointer open runs one task after the press, and a hover surface opens after a delay; an Escape in that window reached no layer and the overlay opened and stayed open. Select had it (its trigger arm, `select-escape-race.spec.ts`), and the same shape was in Combobox (the input's web Escape arm had been removed in favour of the layer), Tooltip and HoverCard (focus open, and a running hover delay) and DropdownMenu (Enter, Escape in one task: the web arm left Escape to `popover="auto"`, which is not shown yet). Construction in `dismiss.rs`: `escape_in_gap` is the one trigger-side rule (Escape while the overlay is open or its open is pending closes or cancels it and consumes the key as a `close` layer does), `OpenGap` is the open that waits a task (Select's pointer open), and the hover surfaces register their layer on the root while open or pending (`use_hover_dismiss`), so an Escape with focus elsewhere cancels a hover delay. Menubar and ContextMenu have no gap (Menubar closes unconditionally on the trigger, ContextMenu's panel is `manual` and its root closes on `open()`). Proof: `playwright/escape-gap.spec.ts` (Combobox, Tooltip, HoverCard, DropdownMenu), `select-escape-race.spec.ts`.

**Phase 2, what exists (2026-11-06, `lane/menu-dismiss-489`, not yet merged).** Items 1-4 below are done; item 5 (the dialog backdrop press) is still open, because it is `dialog.rs` / `popover.rs` / `use_dialog_backdrop_dismiss`, outside the menu lane; item 6 stays open (owner decision); item 7 is row 456's.

- DropdownMenu, ContextMenu and each `MenubarMenu` register one `use_dismiss` layer on their root, active while open, with `Policy::MENU` (Escape `Close`, press outside, focus leaving); a submenu registers `use_dismiss_within` over its content and its sub-trigger with `Policy::MENU_SUB` (Escape and focus, no press: a press outside closes the whole tree). A submenu registers after its menu, so it takes the first Escape and only it closes. The hosts' Escape arms (Dropdown root, ContextMenu root and content, Menubar root, the submenu's `onkeydown`) are gone. What stays is the one trigger-side arm per host for the gap before the layer is on the page (`escape_in_gap` on the DropdownMenu, ContextMenu and Menubar trigger: `escape-gap.spec.ts`), which calls the same close body as the layer. `use_outside_dismiss` and `use_sub_outside_dismiss` are deleted; `Policy::OUTSIDE` and `EscapeKey::Ignore` with them (no surface ignores Escape any more, so the page script's `ignore` branch went).
- `Cause` replaces the hand-set `interacted_outside` writes: the layer's body sets it from `cause.interacted_outside()` (`DropdownMenuContext::dismiss`, `ContextMenuCtx::dismiss`, the Menubar's `dismiss` callback); the signal stays because `use_refocus_on_close_unless` is an effect on `open` and reads it then. The two `RefocusTrigger` impls keep the touch/pen rule. Escape is `Close` (not `Native`) for the `popover="auto"` panels: the browser's close echo cannot say Escape caused it (`on_native_toggle` marks every native close as an outside one), and the `Cause` is what hands focus back to the trigger. The only native close left is the outside-press light dismiss, which is an outside close either way.
- **Item 4, one focus-out policy.** Focus moving to another element closes the menu and focus stays where the user put it, for DropdownMenu, ContextMenu and Menubar alike (`Policy::MENU`, `focus: true`); a submenu closes on focus leaving it. This is Base UI's, which shadcn `base-nova` wraps: `Menu.Popup` renders `FloatingFocusManager` (`@base-ui/react` 1.9.0, `menu/popup/MenuPopup.mjs:154`) with `closeOnFocusOut` left at its default `true` (`floating-ui-react/components/FloatingFocusManager.mjs:124`), for a menubar's menus as for a dropdown. Recorded in the table in `dismiss.rs`. **Root cause of the recorded gap:** both hosts already had `focus: true`; DropdownMenu did not close in `dismiss-parity.spec.ts` because the fixture gives the root its own `id`, a caller `id` wins over the generated one in `merge_attributes`, and the layer looked up the generated id, found nothing and never dismissed on a press or focus outside (ContextMenu and `MenubarMenu` had the same hole). Construction: `menu_root::use_root_id` writes a caller's `id` into the root signal (as `use_id_or` does for triggers), used by all three roots; the spec now expects DropdownMenu `focusOutside: true`. Left as it was: the Dropdown item's own `blur` path (`interacted_outside` plus `use_open_focus_sync`) still closes on focus going to nothing (window blur); the Menubar has no blur path, so it leaves that case alone.
- Escape is now document-wide for the menus: with focus on the page body an open menu still closes on Escape (`menu-family-parity.spec.ts`).
- `DISMISS_JS` is still the last core script, row 456's to port (item 7).
- JS volume (`check-js-volume.sh`): `js_lit` 3,837 -> 3,830, `install` sites 40 -> 39, total `js_lit + js_file` 7,088 -> 7,081; baseline updated (the `menu_sub.rs` row is gone). `DISMISS_JS` gained the second root (`o.also`) the submenu needs.

## Phase 2 items 5 and 6 (2026-11-06, `lane/dismiss-487-56`)

- **Item 5.** `Policy.press` is now `Press` (`Ignore`, `Outside`, `Tap`, `Backdrop`). `Backdrop` is the press mode for a modal `<dialog>` root: a pointer counts when its target is the dialog itself and it is outside the dialog's rect (the old hook's rect test), the press must have begun there too (a drag from inside the panel to the backdrop never closes), and the dismissal comes on release: a mouse press with no distance limit (as the old `click` rule), a touch or pen press under the tap rule (`pointerup` within 10 px, `pointercancel` drops it). A press that began before the layer opened has no record, so the opening tap never closes it (this replaces the old one-frame `requestAnimationFrame` deferral). `Policy::NATIVE_BACKDROP` (`Native` Escape, `Backdrop` press) is used by the web Dialog (honouring `disable_pointer_dismissal`) and the modal Popover; AlertDialog keeps `Policy::NATIVE`. `use_dialog_backdrop_dismiss` and its listener script are deleted from `lib.rs`; its guards (`detail === 0`, `target === dialog`, drag false positive, nested dialogs) are the `target === root` and press-record rules of `DISMISS_JS`.
- **Item 6 (owner decision).** `Policy::ESCAPE_AND_TAP` (`Press::Tap`: touch and pen only) on the Combobox list layer, whose inside is the list and the input (`use_dismiss_within`). The `dynamic` case of `combobox.spec.ts` is driven by mouse clicks (`page.getByRole("button", { name: "Toggle SvelteKit" }).click()`), so it is unaffected; on a touch device the demo's Toggle buttons are outside the input and the list, so a tap on one closes the list (the owner's rule), which that spec does not exercise. Base UI's Combobox (`@base-ui/react` 1.9.0, `combobox/root/AriaCombobox.mjs:1052`) passes `outsidePressEvent: { mouse: 'sloppy', touch: 'intentional' }` to `useDismiss`, so it also closes on a mouse press outside; our mouse policy stays as it was (blur closes it, a page control may act on the options). Its inside is also the trigger, clear button, chips and input group; ours is the input and the list (the clear button of an open list is outside).

- **Proof (lane build `d48756`, chromium, `PW_BUILD_PROFILE=debug`).** Red on a build of the base `d040554a` with only the new `dismiss-parity.spec.ts` copied in: 2 of 16 selected cases red, 14 green (parity). The red ones are `Combobox: a touch scroll leaves it open, a tap outside closes it` (the list stayed open after the tap) and `Dialog: a touch that moves past the tap distance and lifts on the backdrop leaves it open` (the 12 px drag closed the dialog). Green on the lane build: `dismiss-parity`, `escape-gap`, `alert-dialog`, `combobox*`, `dialog*`, `drawer*`, `popover*`, `sheet` and the `native-dialog` oracle spec: 373 passed, 1 skipped, 1 red. The red one, `oracle/tier2-html/native-dialog.spec.ts` Rule 8 construction check, observed the deleted hook's `click` listener on the `<dialog>` being attached inside a `requestAnimationFrame` callback; it now asserts the present construction (a bare `pointerup` on the backdrop with no recorded press leaves the popover open, a `pointerdown` + `pointerup` pair closes it), 18/18 on the file. `scripts/run-gates.sh --fast`: 95 of 103 gates, 0 red. `test:changed` (`d040554a...HEAD`, 214 spec files, 3,434 tests, chromium, debug SSG): the first pass was stopped by the 30-minute tool limit at 1,281 passed and 0 red; the 142 files it had not reached then ran as one pass: 2,173 passed, 18 skipped, 4 red under load (`input-otp-pattern` x2 never hydrated within 90 s, `layout-stability` light/dark timed out at 4 min), and those two files rerun alone: 31 passed.
- **Combobox follows Base UI (2026-11-06, `lane/combobox-baseui`).** `Press::Tap` and `Policy::ESCAPE_AND_TAP` are gone: the Combobox list layer is `Policy::ESCAPE_AND_PRESS`, so a mouse press outside closes the list (the `dynamic` case of `combobox.spec.ts` now expects the page control to act and the list to close, reopening shows the updated options) and the clear button joins the inside set (`Spec.also` is a list of ids; the clear button has the id `<input id>-clear`). Specs: `dismiss-parity.spec.ts` "Combobox: a press outside closes the list, the clear button is inside".

## Detail

State measured 2026-10-31 on `248f35cb`, after rows 477-479 (PR #156).

- **Outside dismiss, today.** `use_outside_dismiss` (`primitives/src/lib.rs:391`) is used by Popover, DropdownMenu, ContextMenu, Menubar, Select and Dialog, and carries row 477's touch tap rule (a mouse press dismisses on `pointerdown`; a touch or pen press is a tap, `pointerup` within 10 px, `pointercancel` drops it). `use_sub_outside_dismiss` (`menu_sub.rs:420`) is the submenu variant. Not on it: Tooltip, HoverCard, Combobox, NavigationMenu (its own document `pointerdown` listener, `navigation_menu.rs:~947-955`, so the tap rule does not reach it: a scroll that starts outside a NavigationMenu panel closes it on a phone) and Navbar (native `popover=auto` light dismiss).
- **Escape, today.** Handled by hand in 12+ places: `tooltip.rs`, `hover_card.rs` (3), `navigation_menu.rs` (3), `navbar.rs`, `combobox/components/input.rs`, Select's trigger and list, `dropdown_menu.rs` (3), `context_menu.rs` (5), `menubar.rs`, `menu_sub.rs`, `menu_item.rs`, plus the dialog and popover roots (`use_global_escape_listener`, `lib.rs:334`). Which layer takes the Escape of a nested stack is decided per host.
- **Focus return, today.** `RefocusTrigger` (`lib.rs:455`; `Signal<String>` for Select, `TriggerHandle` for the menus) is wired per host, with the touch/pen "never refocus by script" rule living in the trait impls only.
- **Construction.** One core in `primitives/src/` (module name chosen by the lane) owning: the Escape key (layer-aware, so the innermost open layer closes first), the outside press (the tap rule of row 477, mouse versus touch/pen) with an "inside" predicate (root, trigger, nested layers) and a focus-leaves arm where the surface wants it, and the focus return (`RefocusTrigger`, modality rule). Each overlay passes a policy value; nothing else is per-host.
- **Brings under the tap rule:** NavigationMenu first (its own listener is deleted), then Tooltip, HoverCard and Combobox where an outside press applies (Tooltip and HoverCard are hover surfaces, so the policy may say "Escape and focus only"; the lane records the choice per surface). **Navbar** keeps its native light dismiss only if the lane shows it equivalent (Escape, outside mouse press, outside tap versus scroll, focus return); otherwise it joins the core.
- **Subsumes:** the 12+ Escape handlers, the NavigationMenu listener, `use_sub_outside_dismiss` as a separate function, the per-host `RefocusTrigger` wiring. **Does not subsume:** the scroll lock (row 459/479), open focus (`OPEN_FOCUS_JS`, row 456), hover intent and its delays (row 478 item 4), the menu item and submenu code (row 435; the two rows touch the same host files, so land 435 step 1 first or coordinate the files per lane).
- **Row 456 follows.** 456 ports JavaScript; it does not unify. After this row it ports one dismiss core (L3/L6/L7/L8/L9) instead of the scattered sites.
- **Proof:** one dismiss parity spec iterating every overlay (Popover, Dialog, AlertDialog, Sheet/Drawer where they dismiss, DropdownMenu, ContextMenu, Menubar, Select, Combobox, NavigationMenu, Navbar, Tooltip, HoverCard, DatePicker): Escape (nested stack closes innermost first), outside mouse press, outside tap versus scroll on touch, focus return to the trigger (and none after touch/pen). The existing `playwright/anchored-placement.spec.ts` touch cases stay green. A release-build run, since it touches every overlay.

**Combobox open and the 50 ms long task (2026-11-01, measured; no regression from this row).** The release suite on main `c16027cc` failed `main-thread.spec.ts` "combobox: open is responsive" (maxTask 52 ms best of 3) after the previous deploy (`7d50e068`) passed it. Three RELEASE validation builds served side by side on one box (`7d50e068`, `2e171ed2` = before this row, `c16027cc`), `ArrowDown` on the focused input, 30 gestures each through a CDP probe: the main-thread task of the keypress has median 49.7 / 47.8 / 50.1 ms, style recalculation 23.9 / 24.6 / 25.6 ms, script 14.3 / 13.9 / 14.0 ms, and 9 / 5 / 8 of 30 gestures end in a long task over 50 ms. The same distribution before and after this row, so the open sits on the 50 ms line on this box in all three trees and the failed run is a draw from it (the spec's best-of-3 fails when all three attempts land on the wrong side, and a deploy runs three workers at once). Where the time goes: `data-dx-modality` flips from `mouse` to `keyboard` on the first key press of a page (`MODALITY_JS`), and `dx-components-theme.css` "Focus modality" redefines `--dx-ring`, `--dx-ring-focus` and `--dx-ring-focus-inset` on `:root` for every non-keyboard value, so the flip restyles the 933 rendered elements of the docs shell: 17.9-27 ms of forced style recalculation, measured with the rule deleted at 0 ms and with the override moved onto `:focus-visible` elements at 10-18 ms. That is about half of the combobox open and a one-time cost on the first keyboard input of any page. This row's `use_dismiss` registration is a small script cost and is not the cause. A lasting margin needs the focus-modality tokens changed in the theme (an owner/theme-lane change; the threshold stays 50 ms).

## Phase 2 (items 1-6 done; 7 is row 456's)

1. DropdownMenu, ContextMenu, Menubar, `menu_sub.rs`, `menu_item.rs`: each host's hand-written Escape arms (3, 5, 1, 1, 1) become one `use_dismiss` layer per open panel (`Close` for a `manual` popover, `Native` for a `popover="auto"` one), a submenu a layer above its parent so only the submenu closes first.
2. `use_sub_outside_dismiss` (`menu_sub.rs:420`) becomes `use_dismiss` with a root that includes the sub-trigger; its script goes. `use_outside_dismiss` calls in the three hosts become `use_dismiss` calls with the policy of the surface (the wrapper then goes).
3. The per-host `RefocusTrigger` wiring (`interacted_outside` signals set by hand in the hosts) becomes the `Cause` the core hands to `on_dismiss`; `use_refocus_on_close_unless` takes it. The touch/pen "never refocus by script" rule stays in the two `RefocusTrigger` impls.
4. Parity gap the spec recorded: Menubar closes when focus moves to a control outside, DropdownMenu does not (`dismiss-parity.spec.ts`, `focusOutside`); phase 2 gives them one policy.
5. Not moved in phase 1: the backdrop-click dismiss of a modal `<dialog>` (`use_dialog_backdrop_dismiss`: the target is the dialog itself, so a rect test and a press-started-on-the-backdrop rule stand in for "outside"); it becomes a press mode of the core with the tap rule (DONE, see below). The `cancel` route of `use_dialog_close_sync` (Escape through state, the opener hand-back of row 223) joins the `Native` mode with row 456.
6. A Combobox tap on plain page does not close its list (the input does not blur on a touch tap, and the `dynamic` demo needs a press elsewhere not to close it): owner decision 2026-11-06: yes, a touch or pen tap outside closes it (DONE, see below).
7. Row 456 ports `DISMISS_JS`, the last script of the core, together with the open-focus and `cancel` scripts.
