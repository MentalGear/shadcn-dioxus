## Detail

**The distinguishing factor is not "a literal attribute beside a spread" but "a literal attribute beside a spread where the props struct has no typed field claiming that name":** a typed field reconciles the collision before it ever reaches `attributes` — `popover.rs`'s `PopoverRoot` `id: root_id` is not an instance because `PopoverRootProps` has a typed `id` field; `context_menu.rs`'s identical root shape was already fixed by `b35d671`; `carousel.rs` (landed this round) has no `id`-literal-beside-spread shape anywhere. On that criterion, `f2be1d7`'s own sweep found **five more real, currently-unexercised `id` instances** (verified directly against source for this row): `alert_dialog.rs`'s `AlertDialogTitle`/`AlertDialogDescription` (`h2`/`p { id: ctx.labelledby` / `ctx.describedby, ..props.attributes }`; neither props struct has a typed `id`); `virtual_list.rs`'s container (`id: container_id`, plus `role`/`tabindex`, all beside `..attributes`; `VirtualListProps` has none of the three); `resizable.rs`'s `ResizablePanel` (`id: id()`, plus `data-panel`/`data-collapsed`, beside `..attributes`); `toast.rs`'s `ToastTitle`/`ToastDescription` (`id: ctx.label_id` / the toast's own `description_id`, beside `..props.attributes` — not this same file's `ToastRegionRendered`, which is already fixed: it explicitly strips any caller `id` from `attributes` before merging, the construction `dev-docs/conformance-harness.md`'s Rule 4 section cites as the fix pattern); and `drag_and_drop_list.rs`'s `DragAndDropInstructions` (a hardcoded `id: "dnd-instructions"` literal, beside `..props.attributes`). **None fails today only because no demo page exercises the collision yet** — precisely the state `3ba793b`'s own bug was in until the `top_layer` fixture's caller-supplied `id` exercised it (row 85's extended Notes above). Beyond those five, a wider version of the same shape — a literal `class:`/`role:`/`data-*`/`type:`/`tabindex:` beside an unmerged spread, no typed field claiming the name — recurs across dozens of themed wrappers in `preview/src/components/**` and several more primitives, including `Menubar`'s own outer root (`role`/`data-disabled`/`data-direction`/`tabindex`, confirmed against source), `calendar.rs`'s `CalendarGridRoot` (`role`/`dir`/`data-direction` — its own `id` is fine, typed), all five of `carousel.rs`'s components (`Carousel`/`CarouselContent`/`CarouselItem`/`CarouselPrevious`/`CarouselNext`, each mixing some of `role`/`data-orientation`/`data-direction`/`data-selected`/`tabindex`/`type` beside its own unmerged spread), `popover.rs`'s `PopoverRoot` `data-state` (its own `id` is likewise fine, typed), and `DropdownMenuContentRendered`'s `role`/`popover`. **This is a class needing a fix by construction, not a fourth reactive pass:** `b35d671` (5 sites), `5fc1439` (`label.rs`'s `class`), and now `f2be1d7` each caught only the instances some page happened to exercise — three successive manual sweeps, three different survivors, each found only by whichever demo page happened to get built and exercised first. **Proposed construction:** a new `scripts/check-*.sh` static gate flagging a literal attribute name rendered beside a raw props spread where no typed field of that name exists, joining the seven guards `CLAUDE.md` already lists (`check-preview-composition.sh`, `check-cfg-axis.sh`, `check-dx-class-prefix.sh`, `check-css-literals.sh`, `check-hooks-in-closures.sh`, `check-self-subscribing-effects.sh`, `check-css-logical-properties.sh`) — not attempted this round, per the Trigger column, since it touches dozens of files across `primitives/src/**` and `preview/src/components/**` rather than the handful this round's own PR already carries  **ROOT CAUSE, 2026-09-20 (lane `deconstruct-attr-dup`, read-only; every load-bearing claim below re-verified in the main loop against the vendored crate sources, not taken on the lane's word):** the class lives two layers below where the three reactive passes were patching. `dioxus-core`'s VNode data model defines a dynamic-attribute slot as an ordered, concatenated `Box<[Attribute]>` with no per-name uniqueness invariant — `dioxus-core-0.7.9/src/nodes.rs:57-88`'s own doc comment states the contract verbatim (`[static named attributes, remaining dynamically named attributes]`, i.e. literal first, spread second, duplicates permitted) — and the one mount path every renderer funnels through (`diff/node.rs:822-825`) replays every entry with an unconditional `write_attribute`, no dedup, for every renderer, always. Everything else follows from that single absent step: `rsx!` is *structurally* incapable of fixing it (a spread's runtime contents are unknowable at expansion time, so `dioxus-rsx-0.7.9/src/element.rs:228-301`'s own `Element::merge_attributes` can only merge literal-vs-literal pairs it sees in the token stream, never literal-vs-spread), and `dioxus-ssr-0.7.9/src/renderer.rs:146-159` special-cases exactly three things (`dangerous_inner_html`, `namespace == Some("style")`, and `BOOL_ATTRS`) and writes everything else straight through — a `grep '"class"' dioxus-ssr-0.7.9/src/` returns zero hits, so there is no class-joining anywhere. This also closes `dev-docs/issues/drafts/dioxus-ssr-duplicate-attributes.md`'s own unchecked "confirm the exact function/file before filing" TODO: it is `render_template`'s `Segment::Attr` arm plus `write_attribute` (`renderer.rs:146-159`/`:482-498`), now traced by source rather than by observation. **New finding that raises the severity:** hydration does NOT repair the SSR'd value either — `dioxus-web-0.7.9/src/mutations.rs:181` gates `set_attribute` behind `skip_mutations()`, which is `true` throughout hydration (`lib.rs:100`, `hydration/hydrate.rs:162`), and `hydrate.ts` never touches attributes at all. Chaining that with the slot ordering, the two renderer modes resolve a collision to **opposite values**: local non-hydrating `dx serve --web` calls `setAttribute` literal-then-spread so the *caller's* value wins, while production SSG+hydrate leaves the browser's HTML-parse resolution (first occurrence = the *library's literal*) in place permanently. So a consumer writing `Alert { class: "mine" }` sees their class applied in dev and silently dropped in production. That is the full reason three separate authors each missed this locally — not "no demo page happened to collide" but "the dev loop's own renderer mode structurally cannot show it"; only the SSG-backed hydration-parity oracle can. **Size of the class:** a guard prototype (`$S/round4/deconstruct/check-attr-spread-collision.py`, iterated live with two real scanner bugs found and fixed mid-run — multi-line fn signatures, and non-`pub` Props structs — each confirmed to have caused a genuine false positive) found **623 sites across 66 files** (543 primitives / 80 preview): `role` 92, `data-state` 48, `data-disabled` 48, `tabindex` 36, `class` 29, `aria_label` 24, `data-direction` 23, `type` 19, `data-slot` 18, … `id` 8 (the five named above plus the three `b35d671`/`f2be1d7` already fixed). CSS shorthands are excluded via a 407-ident denylist extracted mechanically from this lockfile's own `dioxus-html-0.7.9/src/attribute_groups.rs` — those genuinely do fold into one `style="…"`. Disclosed false-negative: single-line element bodies are invisible to the indentation heuristic, so 623 is a floor, not a ceiling. **Recommendation put to the repo owner 2026-09-20, awaiting the call:** harden the prototype into a `syn`-based `scripts/check-*.sh` gate **paired with** extending `hydration-parity.spec.ts` to synthesize the collision per component rather than waiting for an incidental demo (the static check catches authoring, the oracle catches the dev-vs-prod divergence); file the already-drafted upstream issue regardless, now that it has the missing file:line trace; treat the API-level construction (make post-merge the only expressible form for a spread) as the follow-up once the hardened guard's output sizes the cleanup. **What none of that subsumes:** a typed field per name cannot reach the 223 string-literal `data-*`/`aria-*` findings at all (Rust field names cannot contain hyphens), and the `5fc1439`-shaped entry point (an ad-hoc `#[props(extends)]` key plus a separately-threaded `attributes:` forwarded to a *child* component, not a same-element `..spread`) is outside the prototype's literal-scan pattern.
