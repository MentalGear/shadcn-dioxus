# Row 59: Block-demo iframe's row-58 min-width: 820px fix itself broke real mobile viewports; homepage nav now closed…

## Item

**Block-demo iframe's row-58 `min-width: 820px` fix itself broke real mobile viewports; homepage nav now closed by default; homepage checkbox+label gap fixed to match convention — LANDED 2026-09-17, user-reported (×3) + user-requested (×1).** Row 58's flat, always-on `min-width: 820px` on `BlockComponentVariantHighlight`'s iframe fixed the desktop-squeeze case but fired unconditionally, so a genuinely narrow real device/window (390px) also got forced to an 822px-wide iframe — confirmed live on production (`getBoundingClientRect()`: iframe `width: 822` inside a 390px viewport, clipped rather than scrolled since `overflow-x: clip` on `html`/`body` hides the escape). **Fixed by construction:** moved the rule out of the iframe's own inline style/document into a new `.dx-block-demo-iframe` class in `preview/assets/main.css` — a stylesheet loaded by the OUTER top-level page, not the iframe's — gated behind `@media (min-width: 768px)` there. A media query written inside the iframe's own document can only ever see the iframe's own (possibly-squeezed) width, the exact ambiguity at the root of both this bug and row 58's original one; evaluating the query in the outer page's stylesheet instead reads the real visitor viewport, correctly telling apart "outer page's own nav squeezed an otherwise-wide desktop viewport" (>=768px outer: still force 820px, reachable via the wrapper's existing `overflow-x: auto`) from "this is a genuinely narrow device" (<768px outer: no forced min-width, iframe sizes to its real container, embedded `Sidebar`'s own `MOBILE_BREAKPOINT` check sees the true narrow width and renders its real mobile Sheet-trigger layout). One shared construction point, so it covers every current and future `ComponentType::Block` iframe, not just Sidebar's (currently the only one). **Second report, diagnosed as a false positive, not a real bug:** "homepage sidebar config does not work" — the homepage card's Side/Collapse buttons write straight to the same signals `DocsLayout` passes into the real `Sidebar`, confirmed still correct; on mobile the `Sidebar`'s Sheet branch simply isn't mounted until opened, so a card click has nothing visible to update and reasonably read as broken. No code bug found here; see the next item for what mobile actually needed. (One true incidental finding, not itself a bug: the mobile Sheet branch never reads the `collapsible` prop at all, so Offcanvas/Icon/None render identically on mobile — pre-existing, correct, unchanged.) **Third, user-requested: hide the homepage's own site nav by default.** `SidebarProvider`'s existing `default_open: bool` prop (previously unused by `DocsLayout`) is now threaded through a new `DocsLayout { default_open: Option<bool> }` prop; every call site but `Home()` passes `None` and keeps the previous open-by-default behavior, `Home()` alone passes `Some(false)` — the homepage's hero + gallery get full width on first load, the topbar `SidebarTrigger` still opens it identically to before. **Fourth, user-requested: checkbox+label gap.** The homepage's `BlockFilters` dashboard-mockup tag-checkbox row used an inline, inconsistent `gap: 0.55rem` (8.8px) instead of this codebase's established checkbox/radio-to-label spacing token, `var(--dx-space-3)` (12px, already used consistently by `Field`'s horizontal orientation and `RadioGroupItem`) — the other, unrelated `checkbox`/`field` component stylesheets were audited and found already correct, so this was the one actual instance. Fixed at that one row; every other unrelated `0.55rem` use in the same mockup section was deliberately left untouched. **Verified by execution, independently re-checked by the orchestrating session (not just the subagent's own claims), matching this backlog's standing rule after rows 58's two mis-attributions:** `cargo check --workspace`/`cargo fmt --check` clean (only the two pre-existing unrelated warnings); `check-preview-composition.sh`/`check-dx-class-prefix.sh`/`check-css-literals.sh` all clean; `preview.spec.ts` + `sidebar.spec.ts` (9/9 passed on Chromium; the suite's separate mobile-tap case is out of scope here — `playwright.config.ts` deliberately `grepInvert`s "mobile"-titled tests for all three desktop projects, a pre-existing config gap unrelated to this change, confirmed by inspecting the config itself). Independent, targeted re-measurement against a live `dx serve` instance: mobile (390×844) iframe width now 313px (was 822px), no page overflow; desktop (1280×900) iframe width still 822px (unchanged, >=820 preserved); homepage `data-state` now `collapsed` on load, flips to `expanded` on trigger click; `/docs` still defaults `expanded` (unaffected); homepage card's "Right" button still flips the real sidebar's `data-side` live; tag-checkbox row's computed `gap` now `12px` (was `8.8px`)
