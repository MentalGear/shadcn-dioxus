# Row 422: Component pages: group the shared sections under one header

## Item

The owner's ask (2026-10-25, backlog thread): on every component page, group the sections that every component has
under one header, for example Usage Notes (expanded by default), Props Reference, Installation and Component Structure.
Put the component-specific accordion sections under another header.

## Status / trigger

BACKLOG, outline approved by the owner 2026-10-25 (backlog thread): build it as below. Docs stage of the adopted order: after row 394 (the "Coming from shadcn / Radix / TanStack" table
also adds a shared section on every page, so both decide the same layout once).

## Size

M

## Detail

The page is generated by `preview/build.rs` from each component's `docs.md`, plus the generated props table
(`preview/props_scan.rs`) and the Installation section. `check-docs-own-components.sh` requires the docs to use the
library's own Accordion. `check-docs-no-demo-list.sh` already keeps demo lists out of `docs.md`. The grouping is decided
once in the generator, not per `docs.md`.

**Approved outline (owner 2026-10-25).** Two headers on every component page, then the demos:

- **Basic** (shared, the same order on every page): Usage notes (open by default), Installation, Component structure,
  Props reference.
- **Component-Specific**: the page's own `docs.md` sections in their authored order, then a fixed tail for the
  recurring topics when a page has them: Keyboard, Accessibility, Motion, Direction / RTL, Styling (slot variables).
- **Examples**: the demos, unchanged.

Decide the grouping once in `preview/build.rs` / `site/component_page.rs`; a `docs.md` names no group. A gate or test
should pin that every page renders the Basic group in that order and that the recurring-topic tail keeps its order.
