# Row 186: shadcn utilities: scroll-fade and shimmer are built but not shipped as documented, public utilities

## Item

**shadcn utilities: `scroll-fade` and `shimmer` are built but not shipped as documented, public utilities**

## Status / trigger

**PART LANDED 2026-10-15 (the scroll-fade `fade` prop, owner-approved 2026-10-14); BACKLOG: the `/docs` Utilities page, a `dx components add` path for `dx-effects.css`, the shimmer `use_motion` recipe** -- owner item 2026-10-11; **correction to the premise found while scoping it: both already exist** (`preview/assets/dx-effects.css`, row 85 of `component-backlog.md`, built 2026-10-04 with the chat kit, ported from `packages/shadcn/src/tailwind.css`), so this row is documentation, packaging and tests, not a build.

## Size

M

## Detail

**What shadcn ships** (https://ui.shadcn.com/docs/utils/scroll-fade, fetched 2026-10-11): `scroll-fade` / `scroll-fade-y` (top and bottom edges of an `overflow-y` box), `scroll-fade-x`, one edge (`-t -b -l -r`, logical `-s -e` mirroring in RTL), depth on the spacing scale or arbitrary (`scroll-fade-24`, `scroll-fade-[15%]`, per-edge `-t-<n>`), `scroll-fade-none`; variables `--scroll-fade-reveal` (scroll distance of the ease, default 96px) and `--scroll-fade-mask`; default depth 12% capped at 40px; the fade is a `mask-image` on the scroller itself, driven by CSS scroll-driven animations (`animation-timeline: scroll()`), no JavaScript; no overflow means no fade; static edge fade where scroll timelines are unsupported; pair with `no-scrollbar`. shimmer is only linked from that page (its own page was not fetched). **What we have:** `.dx-scroll-fade[-x\|-y\|-t\|-b\|-l\|-r\|-s\|-e\|-none]` with `--dx-scroll-fade-size`, `-{t,b,s,e}-size` and `-reveal`, and `.dx-shimmer[-once\|-reverse\|-none]` with `--dx-shimmer-color\|-duration\|-spread\|-angle`; Tailwind's numeric `@utility` families become custom properties. Already gated by construction: the shimmer is paused by `use_motion` where a component applies it (MarkerContent, AttachmentTitle: `scripts/check-motion-gating.sh`, `scripts/check-infinite-animations.sh` allowlists `dx-shimmer-sweep` as the one paint-only loop, `dev-docs/motion.md`), carries its own `prefers-reduced-motion` block, and scroll-fade has a static fallback in `@supports not`. **The gap:** (1) no public documentation: the only description is the file's header comment and two component docs pages; there is no Utilities section on `/docs` or the sidebar, and no standalone demo of either (scroll-fade is only visible inside `AttachmentGroup`/`message_scroller`); (2) the file is shipped only as a `globalAssets` entry of `attachment`, `marker` and `message_scroller`, so a user who wants the utility alone has no `shadcn-dioxus add` path for it (the CLI and `dx components add` copy components, and the file is not a component); (3) a bare `.dx-shimmer` on any other element has nothing to pause it: `use_motion` is applied by the host, not by the class, so the doc must give the recipe (a `use_motion`-gated `data-dx-motion` ancestor, or the `.dx-shimmer-none` switch) rather than let users ship an always-running loop; (4) tests reach the utilities only through Attachment and Marker (`playwright/attachment.spec.ts`, `playwright/marker.spec.ts`): no spec asserts the mask appears only when content overflows, the start edge fades in after scrolling, the end edge sharpens at the end, RTL mirroring, or the reduced-motion and `-none` switches. **Proposal:** (a) a `Utilities` docs section with a page per utility (class table, variable table, one demo each: a long list with `dx-scroll-fade`, a horizontal strip with `dx-scroll-fade-x`, a streaming status line with `dx-shimmer` gated by `use_motion`), in the shadcn page's own order; (b) a way to install the stylesheet alone (a registry entry or a documented `globalAssets` line in the CLI's `init`, whichever the CLI already supports for non-component files); (c) a Playwright spec per utility on the cases in (4); (d) **no hook unless the spec finds a need**: scroll-fade is `mask-image` plus CSS scroll-driven animation, which is the shadcn design and needs no scroll listener; a Rust hook would only be justified for a browser without `animation-timeline: scroll()`, where the static edge fade is the documented fallback, and it would have to be cleared on drop and listed in `check-js-listeners.sh`; (e) keep the motion rules: reduced motion turns the shimmer off, the gate sentence in `CLAUDE.md` stays true, and a new `infinite` animation would need the infinite-animations allowlist. See also `dev-docs/research/shadcn-catalog-2026-10-04.md` (the "ADD NOW" line for these two) and `dev-docs/component-backlog.md` line 85. **Update 2026-10-15 (scroll-fade part LANDED, lane `scrollfade` 3ba8d59):** a `ScrollFade` enum (`primitives/src/scroll_area.rs`: `None` default, `Y`, `X`, `Top`, `Bottom`, `Start`, `End`) as a `fade` prop on ScrollArea, VirtualList and MessageScrollerViewport (default `Bottom` there, which preserves its existing look), always applied on the scrolling element; `dx-effects.css` is now in `globalAssets` of `scroll_area` and `virtual_list`; the utility is documented in `scroll_area/docs.md` ("Edge fade"). It also fixed a utility bug: a scroller that stopped overflowing after being scrolled kept its start edge faded (`animation-fill-mode: both` on an inactive scroll timeline), now reveal and hold animations without fill. `scroll-fade.spec` 14/14. **Owner Q&A:** no general content scroller and no wrapper component (the mask must sit on the scrolling element; a wrapper would mask chrome and need `timeline-scope`). **What remains on this row:** (a) the `Utilities` docs section on `/docs` with a page per utility; (b) a way to install `dx-effects.css` alone (the `dx components add` path; today it ships only as a `globalAssets` entry of the components that use it); (c) the shimmer recipe: a bare `.dx-shimmer` on another element has nothing to pause it, so document the `use_motion`-gated `data-dx-motion` ancestor (or `.dx-shimmer-none`); (d) specs for shimmer and the standalone-class cases not covered by `scroll-fade.spec`.
