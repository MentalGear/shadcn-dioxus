# Gates

Generated by `scripts/gates-doc.py` from the gate list in `scripts/run-gates.sh` and the headers of
`scripts/check-*.sh`; `scripts/check-gates-doc.sh` fails when this page differs from the generated text. **Do not edit
it by hand.** Each gate's header is the full account (allowlists, escape-hatch markers, self-tests); this page prints
its first paragraph and links the script.

## Running them

`CARGO_TARGET_DIR=<absolute isolated dir> scripts/run-gates.sh` runs every gate, in the order below, with timings.
Green is **`ALL GREEN` with exit 0** and quotes only the tree it ran on (the summary prints HEAD plus a diff hash).
Exit 1 is a red gate, exit 2 bad usage or environment, exit 3 a green but partial run (`--only REGEX`,
`--skip REGEX`, `--fast`, `--stop-on-fail`): none of them is the full gate. `--list` prints the names.

- **Lanes** run the fast gates, everything except the cargo ones (every static check, `fmt` and `stylelint`, in
  seconds, no build lock): `scripts/run-gates.sh --fast` (exit 3 is expected). The main loop runs the one full run per merge batch
  ([`lane-rules.md`](./lane-rules.md), "Gate procedure").
- **Cargo-gate reuse (row 320).** A cargo gate stores its PASS under a key made of `scripts/cargo-inputs-hash.sh`
  (every file the cargo gates can read: the cargo crates by content, asset-only `css`, `svg`, images and fonts by path,
  `Cargo.toml` and `Cargo.lock`, every `include_str!`/`include_bytes!` target, the toolchain, `RUSTFLAGS` and the gate
  command lines). A later run with a byte-identical key prints `reused from tree <sha>` and the summary names every
  reused gate and the tree it really ran on. Only a PASS is stored, `fmt` is never reused, `--no-reuse` (or
  `GATE_REUSE=0`) forces the real run. A CSS-only tree went from 1,209 s to 127 s.
- **A new gate**: write the script's header (its first paragraph is the summary below), add one line to the gate list
  in `scripts/run-gates.sh` under its group, run `scripts/gates-doc.py --write`. A `scripts/check-*.sh` that is not in
  the list fails the run. Nothing else names a gate, so no other doc needs an edit.
- Other checks outside the gate run: `scripts/registry-install-smoke.sh` (the install check, run when a
  `component.json` or a component's `component.rs`/`mod.rs`/`style.css` changes), the Playwright suite
  ([`lane-rules.md`](./lane-rules.md), "Running the suite"), `scripts/check-comment-refs.sh`
  and `scripts/check-history-comments.sh` ([`history-in-comments.md`](./history-in-comments.md)).

## Rust and rsx source rules

**`check-preview-composition`** ([`scripts/check-preview-composition.sh`](../scripts/check-preview-composition.sh)): Preview markup composes only themed wrappers from `crate::components::*`: a raw `dioxus_primitives::` component or module import is allowed only inside the wrapper's own `preview/src/components/<name>/component.rs` and, elsewhere in `preview/src`, for a small allowlist of non-markup items (hooks such as `use_toast`, plain value types and enums such as `CheckboxState` or `DateRange`). Composing a raw primitive in a demo skips the theme wrapper's classes. Rationale: dev-docs/preview-composition.md.

**`check-cfg-axis`** ([`scripts/check-cfg-axis.sh`](../scripts/check-cfg-axis.sh)): Rendered markup, component structure and attribute choice split on the `web` Cargo feature (`#[cfg(feature = "web")]` / `#[cfg(not(feature = "web"))]`), never on `target_family = "wasm"`: `web` is a renderer question, true for the wasm client and for a host fullstack SSG server build alike, while `target_family` is an execution-target question the SSG server build answers wrongly, so the prerendered markup would differ structurally from what the client hydrates. `target_family = "wasm"` stays legitimate only for genuinely wasm-only execution internals, inside a hook's body, on the gate's allowlist.

**`check-hooks-in-closures`** ([`scripts/check-hooks-in-closures.sh`](../scripts/check-hooks-in-closures.sh)): Enforces Dioxus's Rules of Hooks against the one shape that's easy to write by accident and impossible to catch at compile time: calling a hook from inside the closure passed to ANOTHER hook. Dioxus tracks each component's hooks in a per-scope, call-order-indexed list guarded by a `RefCell`; a hook call inside another hook's own initializer closure re-enters that list while the outer hook is already borrowing it, panicking at runtime ("BorrowMutError: The hook list is already borrowed ... hook inside a hook", dioxus-core's `scope_context.rs`) the first time the component renders -- `cargo check`, clippy, and `cargo test` all stay green, since nothing about this is a type error.

**`check-self-subscribing-effects`** ([`scripts/check-self-subscribing-effects.sh`](../scripts/check-self-subscribing-effects.sh)): Enforces a Dioxus reactivity invariant that, like the hook-inside-hook shape check-hooks-in-closures.sh guards against, is easy to write by accident and invisible to `cargo check`/clippy/`cargo test`: inside a `use_effect(move || { ... })` body, reading a signal with tracked syntax (`x()` or `x.read()`) and then writing that same signal (`x.set(...)`, `x.write()`, `*x.write()`) in the same run subscribes the effect to a value it just changed itself. Dioxus reschedules the effect whenever a signal it read changes, so this can re-trigger the effect from its own write -- forever, if nothing else in that same run breaks the cycle.

**`check-component-call`** ([`scripts/check-component-call.sh`](../scripts/check-component-call.sh)): A component is MOUNTED (`Block {}` in rsx), never CALLED. Calling one as a plain function -- `component.call(())` on a `Callback<(), Element>`, `(entry.thumb)()` on a `fn() -> Element` field, or `Calendar(props)` on a `#[component] fn` -- runs its hooks in the CALLER's scope: `Callback::call` pushes the scope the callback was CREATED in, so a `use_signal`/`use_effect`/`use_interval` inside lands on that scope's hook list, whose index resets only when that scope re-renders. Every later re-render of the caller then allocates a FRESH set beside the old, unreachable one. Example (row 150): `MasonryCard` calling `component.call(())` grows a never-cleared interval in `BlockPlayer` every ~1.2 s (128 live intervals after ~100 s). It compiles, clippy and cargo test stay green, and a hook inside is invisible to grep.

**`check-attr-spread-collision`** *(cargo gate)* ([`scripts/check-attr-spread-collision.sh`](../scripts/check-attr-spread-collision.sh)): A literal attribute rendered beside a raw `..attributes` spread on the same element, where the component's props have no typed field claiming that name, is flagged. If a caller passes the same attribute, SSR emits both and the browser's HTML parser keeps the first (the component's own), client rendering keeps the last (the caller's) and hydration does not reconcile them, so a caller's override works under `dx serve` and is silently dropped in the SSR plus hydrate deployment; a typed prop field of that name is the discriminator, because it merges into one literal. Existing sites are a debt register in two shrink-only baselines (`scripts/check-attr-spread-collision*.baseline.tsv`): the gate fails only on a site that is not in them. Root cause: dev-docs/issues/duplicate-attribute-root-cause.md.

**`check-direction-keys`** ([`scripts/check-direction-keys.sh`](../scripts/check-direction-keys.sh)): Horizontal keyboard and gesture handling in `primitives/` is direction-aware by construction: `primitives/src/direction.rs` owns the one mirroring rule (`Direction::resolve_horizontal`, and `ltr_equivalent` built on it), so a non-test, non-comment line under `primitives/src` that names `Key::ArrowLeft`, `Key::ArrowRight` or `delta_x` puts its file on the hook: the file must also call `resolve_horizontal`, `ltr_equivalent` or `use_direction`, or sit on the reasoned ALLOWLIST (nothing to flip; a stale entry fails). Context structs hold the `ReadSignal<Direction>`, never a mount-time copy, so the RTL toggle reaches mounted descendants. Browser half: `playwright/oracle/tier3-radix/rtl.spec.ts` and `playwright/oracle/tier3-radix/rtl-toggle.spec.ts`. Backlog row 137.

**`check-render-keys`** ([`scripts/check-render-keys.sh`](../scripts/check-render-keys.sh)): A windowed renderer says who is at an index ONCE: the optional `item_key` prop, made into a DOM key by `render_key(item_key, idx)` (primitives/src/virtual/identity.rs). A hand-written positional key -- `key: "{idx}"`, `"{row.index()}"`, `"{item.key()}"` -- ties the DOM node, and with it focus and any state inside the row, to the slot, so after a sort or a reorder focus stays on a slot while the item moves (row 361; the same class applies to VirtualList, TableRows and the grids). By construction no renderer spells a key itself.

**`check-render-clock`** ([`scripts/check-render-clock.sh`](../scripts/check-render-clock.sh)): A component that reads the clock while rendering, or in a prop default, bakes the day the page was prerendered into the static HTML, and hydration keeps it: the calendar's "today", the month it opens on, a date picker's default segment values and every demo built on them show the build day (backlog row 380). So the clock is read in one place, `dioxus_primitives::calendar::use_today`, which renders the server's date during hydration and reads the visitor's clock after mount.

**`check-collection-derive`** ([`scripts/check-collection-derive.sh`](../scripts/check-collection-derive.sh)): Every view of rows derives from one model, `primitives/src/data_view/`: in `preview/src/components/**/*.rs` there is no `.to_lowercase().contains(` (call `contains_query`), no `HashSet<usize>`, `Vec<bool>` or `[bool; N]` as a selection (selection is a `HashSet<String>` of row keys in `ViewState`) and no ad-hoc `.sort_by(` / `.sort_by_key(` (a `Field::sortable` through `derive`). Reasoned allowlist (ToggleGroup's deprecated index props, the catalogue sort); a stale entry fails. Backlog row 360.

**`check-raw-text-interpolation`** ([`scripts/check-raw-text-interpolation.sh`](../scripts/check-raw-text-interpolation.sh)): No interpolation inside the children of an rsx `style { }`, `script { }`, `noscript { }` or `textarea { }` element (the `style:` attribute is fine): Dioxus SSR/SSG emits a hydration marker comment before every dynamic text node, which inside a raw-text element turns the first CSS rule or script statement into garbage and inside `<textarea>`/`<noscript>` ships as visible text. Put dynamic CSS in an inline `style:` attribute or a stylesheet asset, set a textarea's `value:` attribute, or use a string literal child with `{{`/`}}` escapes.

**`check-dynamic-style-shorthand`** ([`scripts/check-dynamic-style-shorthand.sh`](../scripts/check-dynamic-style-shorthand.sh)): An rsx `style:` string with an interpolation may not declare a shorthand whose value holds a `var()` (`border`, `background`, `border-radius`, ...), and a `style:` chosen by `if`/`match` is banned: Dioxus's web renderer drops a `var()`-valued shorthand from an inline `style` the first time the string is re-set (the server markup is right, the hydrated page loses the border) and keeps stale longhands when one string is swapped for another. Declare the shorthand in a stylesheet or `style {}` rule keyed by a class or data attribute and keep only computed numbers inline, spell the longhands, or paint by `data-state`. Reasoned allowlists, stale entries fail.

**`check-as-child`** ([`scripts/check-as-child.sh`](../scripts/check-as-child.sh)): Every `as` render prop is `Option<Callback<AsChild, Element>>` (row 395): the callback gets the component's merged attributes, its handler props included, AND the children given to the component (`dioxus_primitives::AsChild`), so the caller's element keeps both, as Radix `asChild` does. A render callback typed `Callback<Vec<Attribute>, Element>` gets the attributes alone, and the component's children vanish when the caller picks the element. So no Rust source and no component docs.md may declare that shape, or pass `as` a closure that takes a bare `Vec<Attribute>`.

**`check-wrapper-props`** ([`scripts/check-wrapper-props.sh`](../scripts/check-wrapper-props.sh)): A themed wrapper forwards every prop of the primitive it renders (row 391). The component docs page prints the primitive's props table next to the wrapper's (`preview/build.rs`, `preview/props_scan.rs`), so a prop the wrapper never passes is documented and does nothing: with no field of that name the value falls into the attribute spread. The scanner (`scripts/wrapper-props/main.rs`, sharing `preview/props_scan.rs`) finds every call of a primitive component in `preview/src/components/*/component.rs` (`module::Name { .. }`, a name imported from a primitive module, or a local component that takes a primitive's props struct) and lists each prop of that primitive the call does not pass by name or through a `..props` spread. Every listed prop must be forwarded or named, with its reason, in `scripts/check-wrapper-props.allow.tsv` (`path<TAB>module::Name.prop<TAB>reason`, or `*` for a whole fixture file). An allowlist entry that no longer matches a dropped prop fails too, so the list only shrinks.

## Timers, listeners, motion and focus

**`check-uncleared-intervals`** ([`scripts/check-uncleared-intervals.sh`](../scripts/check-uncleared-intervals.sh)): Keeps a repeating timer from being written in a shape that nothing can ever clear. A JS `setInterval` started through `document::eval` (or from any script) is owned by the PAGE, not by the Dioxus scope that evaluated it: dropping the component drops the task that listens to it, but the interval itself keeps firing for the life of the page. Written from a `use_effect`, it is also re-created every time that effect re-runs, and every visit to the route adds another. Nothing in `cargo check`, clippy or `cargo test` can see it.

**`check-blocking-scroll-listeners`** ([`scripts/check-blocking-scroll-listeners.sh`](../scripts/check-blocking-scroll-listeners.sh)): Keeps a blocking (non-passive) wheel / touch listener from being added to the page by accident. cargo, clippy and `cargo test` cannot see it, and it looks like a harmless one-line event handler.

**`check-js-listeners`** ([`scripts/check-js-listeners.sh`](../scripts/check-js-listeners.sh)): Keeps a JS event listener from being added in a shape that nothing ties to the scope that owns it. cargo, clippy and `cargo test` cannot see it, and it looks like a harmless one-liner inside a `document::eval` string.

**`check-motion-gating`** ([`scripts/check-motion-gating.sh`](../scripts/check-motion-gating.sh)): Motion nobody can see must not run, by construction. `primitives/src/activity.rs` answers "is this visible" once for the whole page, so a bare `use_interval` or a hand-rolled `loop` plus `sleep` tick must be the visibility-gated `use_interval_while` / `use_timeout_while` (or sit after a `use_motion` gate), or carry `// motion-ok: <reason>`; and every component `style.css` with an `infinite` animation needs a component or primitive that applies `use_motion`, whose one `[data-dx-motion="paused"]` theme rule then pauses it, or a reasoned allowlist entry. Utility loops (`.dx-shimmer`) are gated at their host.

**`check-infinite-animations`** ([`scripts/check-infinite-animations.sh`](../scripts/check-infinite-animations.sh)): An `infinite` CSS animation may only animate COMPOSITOR properties -- `transform`, `translate`, `scale`, `rotate`, `opacity` -- unless its @keyframes is allowlisted below with a reason. Invisible to cargo and clippy, and with CI frozen (dev-docs/backlog.md row 33) nothing else would notice.

**`check-open-focus`** ([`scripts/check-open-focus.sh`](../scripts/check-open-focus.sh)): Where focus goes when an overlay opens, and whether it rings, is decided in ONE place (dev-docs/backlog.md rows 206 and 226): `primitives/src/modality.rs` writes the interaction modality (keyboard | mouse | touch | pen) to `<html data-dx-modality>` once, `dxOpenFocus` there is the one open-focus policy (`use_dialog_open_driver`, the non-modal Popover's show script, and the Command palette through `data-dx-autofocus`), and `dx-components-theme.css` ("Focus modality") draws a ring only for the keyboard. An overlay that picks its own focus target is its own instance of the same bug on iOS: a ring around the panel, a text field focused while the panel was still being placed, so the software keyboard rises and moves the layout.

**`check-theme-mode-writer`** ([`scripts/check-theme-mode-writer.sh`](../scripts/check-theme-mode-writer.sh)): The light/dark MODE has exactly one writer: `apply_mode` inside `PREPAINT_JS` (preview/src/theme.rs), embedded byte-identically in preview/index.html's <head>. Any other code that writes `data-theme` or the `dark` class on <html> fails here. Invisible to cargo and clippy, and with CI frozen (dev-docs/backlog.md row 33) nothing else would notice.

## Theme and component CSS

**`check-dx-class-prefix`** ([`scripts/check-dx-class-prefix.sh`](../scripts/check-dx-class-prefix.sh)): Every class selector in a component's own `preview/src/components/<name>/style.css` is spelled `dx-<name>` or `dx-<name>-...` (the folder name with `_` written as `-`), so classes stay collision-safe without a hash suffix. Selectors are read in selector position inside every at-rule; declaration bodies and comments are never scanned. Demo-only stylesheets under `variants/` are out of scope.

**`check-cross-component-overrides`** ([`scripts/check-cross-component-overrides.sh`](../scripts/check-cross-component-overrides.sh)): A component's stylesheet must not declare a non-custom property on an element that is really another component's: one element wearing both `dx-Y` and `dx-X-...`, or a bare `> button`/`input`/`select`/`textarea`/`label` selector. Two sheets declaring one property are decided by per-route stylesheet order, so compose through slot variables instead (the base reads `font-size: var(--dx-label-font-size, var(--dx-text-sm))`, the parent sets the variable). Existing sites are a shrink-only baseline, `scripts/check-cross-component-overrides.baseline.tsv`; the gate fails on a site that is not in it.

**`check-css-literals`** ([`scripts/check-css-literals.sh`](../scripts/check-css-literals.sh)): Enforces dev-docs/backlog.md row 31b: a themed component stylesheet must not hard-code a value that the design-token set (dev-docs/backlog.md row 31a, `preview/assets/dx-components-theme.css`) already names.

**`check-css-logical-properties`** ([`scripts/check-css-logical-properties.sh`](../scripts/check-css-logical-properties.sh)): Enforces dev-docs/backlog.md row 13 (RTL, styling half): a themed component stylesheet must not hard-code an inline-axis PHYSICAL property (one that means "left" or "right" no matter what direction the page reads) where a logical property (`margin-inline-start`, `inset-inline-end`, `border-start-start-radius`, `text-align: start`, ...) would express the same rule and mirror correctly under `dir="rtl"`.

**`check-css-vars-defined`** ([`scripts/check-css-vars-defined.sh`](../scripts/check-css-vars-defined.sh)): Enforces dev-docs/backlog.md row 111: every CSS custom property a component reads with `var(--name)` must be declared somewhere in the scanned source, or be on the explicit allowlist below. A fallback in the `var()` does NOT excuse the name.

**`check-hover-mix-space`** ([`scripts/check-hover-mix-space.sh`](../scripts/check-hover-mix-space.sh)): shadcn base-nova writes its hover step as `color-mix(in oklch, var(--secondary), var(--foreground) 5%)`. The theme carries that space once as `--dx-hover-mix-space` (dx-components-theme.css), and every hover / pressed / active fill that steps a colour toward the ink or the page reads it: `color-mix(in var(--dx-hover-mix-space), <fill>, var(--dx-foreground) N%)`. Hand-writing the space (`in oklab` is 3 levels off on a grey) is how components drift from Button (rows 243, 260).

**`check-coarse-sizing`** ([`scripts/check-coarse-sizing.sh`](../scripts/check-coarse-sizing.sh)): Touch sizing is ONE switch, `data-dx-coarse="auto|on|off"` on <html> or any container, and every size that differs by pointer is a theme variable (`--dx-coarse-*`, `--dx-menu-item-*`, `--dx-menu-trigger-*`) that the switch flips (dx-components-theme.css, "Coarse sizing"). A component sheet that says `@media (pointer: coarse)` (or `any-pointer: coarse`) itself would follow the device and ignore the attribute: a forced-on container would keep the desktop size in it (row 349).

**`check-press-under`** ([`scripts/check-press-under.sh`](../scripts/check-press-under.sh)): A pressed `dx-` control gets the theme's press wash (`dx-components-theme.css`, "Press feedback"), a `background-image` layer that out-ranks every component rule so the wash paints on a control whose sheet writes a `background` shorthand. That rule REPLACES the element's own `background-image`: a pressable card with a gradient (Navigation Menu's featured card) loses it while pressed. The wash therefore ends with `var(--dx-press-under, none)`, and a control that paints an image or gradient hands it over by declaring it once in that slot: `--dx-press-under: <image>; background-image: var(--dx-press-under);`.

**`check-anchored-keyframes`** ([`scripts/check-anchored-keyframes.sh`](../scripts/check-anchored-keyframes.sh)): No `transform` inside ANY `@keyframes` of a preview stylesheet, unless that keyframe is allowlisted below with a reason: animate `translate` / `scale` / `rotate` instead. Invisible to cargo and clippy, and with CI frozen (dev-docs/backlog.md row 33) nothing else would notice.

**`check-duplicate-keyframes`** ([`scripts/check-duplicate-keyframes.sh`](../scripts/check-duplicate-keyframes.sh)): Two `@keyframes` blocks with a byte-identical body (comments and whitespace stripped, `0%` read as `from`, `100%` as `to`) are one animation written twice. Fails when a stylesheet defines a body that another stylesheet (or the same one, under another name) already defines, unless the duplicate is allowlisted below with a reason. Invisible to cargo and clippy, and with CI frozen (dev-docs/backlog.md row 33) nothing else would notice.

**`check-theme-baseline`** ([`scripts/check-theme-baseline.sh`](../scripts/check-theme-baseline.sh)): What the theme owns once is not declared per component. No component `style.css` may declare `touch-action: manipulation` (the theme's one zero-specificity rule covers every `dx-` button, link, form control, `tabindex` and interactive ARIA role; a drag surface may still declare `none` or `pan-*`), paint a `::backdrop` (the modal scrim is the theme's one rule on `dialog[class^="dx-"]`, retuned by the `--dx-overlay-*` tokens), reset with `all:` (it outranks every zero-specificity theme rule), or re-declare `user-select: none` for an element the theme's one control rule already covers (every other use sits on the gate's reasoned `USER_SELECT_ALLOW`). The theme's `:where(dialog[class^="dx-"]) { padding: 0 }` reset means every dialog sheet declares its own inset. All these theme rules must still exist, and the vendor-prefixed line carries the one scoped `property-no-vendor-prefix` disable.

**`check-theme-preset-axes`** ([`scripts/check-theme-preset-axes.sh`](../scripts/check-theme-preset-axes.sh)): The theme picker has two colour axes that own DISJOINT variables, so picking one never moves what the other owns: the base preset (`[data-theme-base]`) writes only the neutral palette and the base-owned slots of the no-accent primary, the accent preset (`[data-theme-accent]`) writes only primary, charts and sidebar-primary. The ownership table is written once, in `OWNERSHIP` of scripts/gen-theme-presets.mjs (this gate reads it with `--print-ownership`). A base block that sets a chart colour, an accent block that sets `--secondary`, a base block that sets a bare `--primary`, a variable in a block of the wrong axis, a slot the theme never reads, or a committed preview/assets/theme-presets.css that differs by one byte from the generator's output (a hand edit, or data that changed without a regeneration) all fail. The gate runs its own mutation self-test on every run; each mutation must turn it red.

**`check-cursor-baseline`** ([`scripts/check-cursor-baseline.sh`](../scripts/check-cursor-baseline.sh)): The cursor of an interactive element is decided ONCE, by the theme, so every pressable element shows the same cursor and an app chooses it in one place (backlog row 381 records the decision). Per-sheet `cursor: pointer` / `cursor: default` declarations make one press look different in each component.

**`check-popup-boundary`** ([`scripts/check-popup-boundary.sh`](../scripts/check-popup-boundary.sh)): A popover or dialog stays a DOM descendant of its trigger, so a component sheet's descendant selector on a generic element (`.dx-x svg`, `.dx-x a`, `.dx-x button`, `.dx-x [role=...]`, `*`) also styles the panel of any popup rendered inside it. End such a selector with the zero-specificity `:not(:where([popover], dialog) *)` or select the component's own part by class; otherwise a reasoned allowlist entry says why no popup can sit inside the ancestor (stale entries fail). Browser half: `playwright/popup-style-isolation.spec.ts` opens one representative popup per popup component, alone and under a hostile parent, and requires the same computed style.

**`check-variant-scope`** ([`scripts/check-variant-scope.sh`](../scripts/check-variant-scope.sh)): A component's VARIANT rule must style the component's own parts through slot variables its root re-declares, never by a descendant selector from the variant attribute (backlog row 218, item 1).

**`check-popup-root-reset`** ([`scripts/check-popup-root-reset.sh`](../scripts/check-popup-root-reset.sh)): A popover or dialog is painted in the top layer but stays a DOM descendant of its trigger, so every INHERITED CSS property still flows from the host (a 14px card, a muted or monospace block, a button that is not selectable text) into the panel. Descendant selectors are closed by check-popup-boundary.sh; this gate is the other half, by construction: the theme (preview/assets/dx-components-theme.css, "Popup root") carries ONE zero-specificity rule over every `dx-` popup root,

**`check-component-root-reset`** ([`scripts/check-component-root-reset.sh`](../scripts/check-component-root-reset.sh)): An in-flow component must not inherit its host's typography, once and by construction: every namesake component root (`dx-<dir>`, read from `component.rs`; the four `<dialog>`-panel roots are left to the popup-root rule) carries `"data-dx-root": ""`, or a reasoned `typography-inherit(dx-<dir>): <reason>` comment for a wrapper around the caller's content, and the theme's one zero-specificity `:where([data-dx-root]:not([data-dx-root] *, button, input, select, textarea))` rule resets the inherited text properties (line-height, weight, style, spacing, transform, alignment, white-space, ...) to the theme base on the outermost root. Font family, colour, direction, cursor, pointer-events, visibility, user-select, form controls and `font-size` keep inheriting. The gate checks the rule is single, zero-specificity and complete against mdn-data's inherited properties; its self-test mutations must turn red.

**`check-destructive-text`** ([`scripts/check-destructive-text.sh`](../scripts/check-destructive-text.sh)): Destructive text is the theme's one clamped role `--dx-destructive-text` (at least 4.5:1 on every surface in both modes): no `color`, `caret-color`, `text-decoration-color` or `*-ink`/`*-color` custom property in `preview/src` or `primitives/src` (`*.css`, `*.rs`, inline `style:` strings) may read the fill-grade `var(--dx-destructive)`, bare or inside `color-mix`. Borders, backgrounds, fills, rings and shadows keep it. Reasoned allowlist, stale entries fail.

**`check-css-state-recipes`** ([`scripts/check-css-state-recipes.sh`](../scripts/check-css-state-recipes.sh)): Focus, invalid and disabled are shared tokens in the theme's "State recipes" section, so a component sheet may say where a ring paints but not what it is: a disabled `opacity` other than `var(--dx-opacity-disabled)`, a hand-written focus `box-shadow`, `outline` or `border-color`, a focus ring on a text-entry control that is transparent outside keyboard modality, the 2px `--dx-ring`, a hand-mixed destructive invalid ring, or a `cursor: not-allowed` beside `pointer-events: none` fails, with a reasoned allowlist. New control states compose through the tokens and slot variables.

**`check-merge-drivers`** ([`scripts/check-merge-drivers.sh`](../scripts/check-merge-drivers.sh)): The generated backlog indexes and the durations table never conflict textually on a merge of lane branches: `.gitattributes` maps `dev-docs/backlog.md`, `dev-docs/backlog-done.md` and `playwright/durations.json` to merge drivers (scripts/merge-driver-backlog-index.py, playwright/tools/durations-merge.mjs) that merge by row id and by spec entry, registered per clone by scripts/setup-merge-drivers.sh from the SessionStart hook. This gate checks the attributes, the driver scripts, the registration command and the hook wiring exist, runs both drivers' self-tests, and does a real merge in a throwaway git repo (two branches each adding a backlog row file and a durations entry, registered through setup-merge-drivers.sh itself) that must finish with no conflict and a valid index and table.

## Rust build, lint, test and style

**`fmt`**: Every Rust file is rustfmt-formatted (`cargo fmt --all -- --check`). Never reused from the store: it takes under a second.

**`check-primitives-features`** *(cargo gate)* ([`scripts/check-primitives-features.sh`](../scripts/check-primitives-features.sh)): `dioxus-primitives` has optional features so that an app compiles only what its components use (dev-docs/backlog.md row 217): `router` (Navbar; dioxus-router and its dependency tree), `calendar` (Calendar + DatePicker; `time`), `color-picker` (ColorPicker; `palette` and its companions). Inside this workspace every build unifies ALL of them (preview turns them on), so a gated module that quietly depends on another gated crate -- or a non-gated module that grew a `use time::` -- compiles here and breaks in a user's tree that enabled only the feature its component.json asks for. This gate builds the crate ON ITS OWN, outside that unification: - no default features and no optional feature at all (the Button-only app), including tests and benches; - each optional feature alone (+ `web`, the browser arm, which must not drag `time` in on its own); - every optional feature together with `web`. Which features a COMPONENT must ask for is `scripts/check-cargo-dep-versions.sh`; the whole install is `scripts/registry-install-smoke.sh`.

**`clippy-default`** *(cargo gate)*: Clippy, default arm: `cargo clippy --workspace --all-targets -- -D warnings` lints the `not(feature = "web")` arm of primitives and every workspace member. A plain `cargo clippy --workspace` never enables primitives' `web` feature or preview's `server` feature, and those two are what ships (`dx build --ssg` compiles the browser client with `web` and the prerender server with `server`), so each arm is its own gate; `--all-features` cannot replace them (preview's `desktop` needs gtk and webkit2gtk, the renderers are alternatives, and it would stop linting the `not(web)` arm). Every clippy gate is also red when its log holds a `generated N warning(s)` line although cargo exited 0.

**`clippy-web`** *(cargo gate)*: Clippy, `web` arm: primitives and preview with their `web` features, the code the wasm client compiles (over 100 `feature = "web"` cfg sites in primitives alone).

**`clippy-server`** *(cargo gate)*: Clippy, `server` arm: preview with `server` (the SSG prerender server; implies fullstack and the primitives `web` feature).

**`test`** *(cargo gate)*: `cargo test --workspace`: every unit and integration test of the workspace on the plain arm (no `web` or `server` feature); the server arm is `test-server`.

**`test-server`** *(cargo gate)*: `cargo test -p preview --features server`: the arm `dx build --ssg` ships, where `ssr_parity` and the web-only effects differ from the plain arm.

**`check-rustdoc`** *(cargo gate)* ([`scripts/check-rustdoc.sh`](../scripts/check-rustdoc.sh)): Rustdoc builds without a new warning: `cargo doc --no-deps --document-private-items` on the default arm of the whole workspace and on the `web` arm of primitives and preview, so a broken intra-doc link, an unclosed HTML tag, a bare URL or a public doc comment that links a private item is red before docs.rs shows it. The warnings that exist are a shrink-only debt register, `scripts/check-rustdoc.baseline.tsv` (`file<TAB>message`, no line numbers, so an edit above a site does not disturb it, a multiset): the gate fails on a warning that is not in it, on any rustdoc error, and on a baseline entry that no longer fires (delete the line, or run `--update-baseline`, which refuses to add one unless `--allow-grow` is given and the commit says why). Fix a site by rewriting the doc comment: link only items that are public, use a plain code span for a private one, escape or fence a literal `<tag>`, write a URL as `<url>`.

**`stylelint`**: Stylelint over every stylesheet under `preview/src` and `preview/assets` (run with `pnpm exec`, which never downloads: a worktree without `node_modules` fails loudly).
