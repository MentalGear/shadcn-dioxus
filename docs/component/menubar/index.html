menubar

Install

A menubar component for a collection of menu items.

Basic

The same sections, in the same order, on every component page.

The Menubar component can be used to display a menu bar with collapsible menus.

shadcn-dioxus add menubar

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

/// Themed wrapper for [`menubar::MenubarCheckboxItem`] -- shadcn's
/// `MenubarCheckboxItem`. Carries `dx-menubar-item` (the same hover/focus/
/// disabled chrome every plain item gets) and `dx-menubar-checkable-item`
/// (the reserved indicator slot, see `style.css`), and appends a `Check` icon
/// after the caller's own content. Unlike the dropdown and context menus,
/// shadcn's menubar puts the check at the inline **start** (Nova's
/// `.cn-menubar-checkbox-item`: `pl-7`, indicator `left-1.5`), so this item
/// reserves `padding-inline-start`; the three
/// `--dx-menu-item-indicator-*` tokens and the construction are the same.
/// The icon carries `dx-menubar-item-indicator`; it is drawn only while the
/// primitive reports `data-checked`.
#[component]
pub fn MenubarCheckboxItem(props: MenubarCheckboxItemProps) -> Element {
    let base = attributes!(div {
        class: "dx-menubar-item dx-menubar-checkable-item",
        "data-dx-menu-item": "true",
    });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    let children = props.children.clone();
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/menubar/style.css") }
        menubar::MenubarCheckboxItem {
            attributes: merged,
            ..props,
            {children}
            Check {
                class: "dx-menubar-item-indicator",
                "data-dx-menu-item-indicator": "start",
                size: "16px",
            }
        }
    }
}

/// A non-interactive heading for a group of items -- shadcn's
/// `MenubarLabel`. Pure presentation (the primitive has no label component):
/// give it an `id` and point a [`MenubarRadioGroup`]'s `aria-labelledby` at
/// it so the group is named.
#[component]
pub fn MenubarLabel(
    /// Reserves the leading indicator slot -- shadcn's `inset` -- so the heading
    /// lines up with inset items. Carries `data-inset="true"`.
    #[props(default)]
    inset: bool,
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// The heading text.
    children: Element,
) -> Element {
    let base = attributes!(div {
        class: "dx-menubar-label",
        "data-dx-menu-label": "true",
    });
    let inset_attr = attributes!(div {
        "data-inset": inset.then_some("true"),
    });
    let merged = merge_attributes(vec![base, attributes, inset_attr]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/menubar/style.css") }
        div { ..merged, {children} }
    }
}

// The Menubar component wraps the entire menu bar and contains the individual menus, in document order.
Menubar {
    // The MenubarMenu contains the individual menus that can be opened.
    MenubarMenu {
        // The menubar trigger is the element that will display the menu when activated.
        MenubarTrigger {
            // The content of the trigger button
            "File"
        }
        // The menubar content contains all the items that will be displayed in the menu when it is opened.
        MenubarContent {
            // Each menubar item represents an individual items in the menu.
            MenubarItem {
                // The value of the item which will be passed to the on_select callback when the item is selected.
                value: "open".to_string(),
                on_select: |value: String| {
                    // This callback is triggered when the item is selected.
                    // The value parameter contains the value of the selected item.
                },
                "Open"
            }
        }
    }
}

The heading text.

Plus the global attributes.

MenubarProps Primitive

The props for the Menubar component.

PropTypeDefaultDescription
disabledboolfalse

Whether the menubar is disabled.

roving_loopbooltrue

Whether focus should loop around when reaching the end.

dirDirectionNone

The text direction for ArrowLeft/ArrowRight roving focus between top-level menus. Defaults to the nearest crate::direction::DirectionProvider, or LTR if there is none.

open_on_hoverbooltrue

Whether, once one menu is open, hovering another MenubarTrigger switches to that menu without a click. Defaults to true (the native menubar convention, and what Radix does unconditionally). Set it to false for click activation: moving the pointer across the triggers while a menu is open does nothing -- another menu opens only on click, Enter, Space or the arrow keys.

A Menubar never opens a menu from a hover alone (the first menu always takes a click), so this switch only governs the "hover-switch while one is open" half. Keyboard behaviour (ArrowLeft/ ArrowRight moving to and opening the neighbouring menu) is identical in both modes. Same name as Base UI's Menu.Trigger openOnHover prop, which Base UI's Menubar has no equivalent of.

childrenElementempty

The children of the menubar component.

Plus the global attributes.

MenubarMenuProps Primitive

The props for the MenubarMenu component.

PropTypeDefaultDescription
indexusizeNone

The menu's place in the menubar's keyboard order. Leave it unset: menus are ordered as they are created, which is tree order. Set it on every menu only when one is inserted between menus that are already mounted, or a keyed list reorders them.

disabledboolfalse

Whether this menu is disabled.

childrenElementempty

The children of the menu component.

Plus the global attributes.

The props for the MenubarTrigger component.

PropTypeDefaultDescription

The ID of the trigger button. If not provided, an internally generated ID is used -- see MenubarTrigger's use of use_id_or for why this is a typed field rather than left to GlobalAttributes alone (dev-docs/backlog.md row 36).

childrenElementempty

The children of the trigger component.

Plus the global attributes.

The props for the MenubarContent component.

PropTypeDefaultDescription
idStringNone

The id of the content element.

childrenElementempty

The children of the content component.

Plus the global attributes.

MenubarContentRendered Primitive

The menu panel. On the web it is promoted to the top layer via popover="auto", anchored to its own trigger -- the same mechanism DropdownMenuContentRendered uses (dropdown_menu.rs), which see for the general popover/CSS-anchor wiring. Without the popover API it is a plain, always-in-flow div.

auto: each MenubarMenu has exactly the shape DropdownMenu does -- a trigger button plus content anchored to it -- and auto's native light dismiss (Escape, outside pointerdown) is free, spec-correct insurance beside this crate's own DOM-truth dismissal, not a competing mechanism.

Escape is the dismiss layer's MenubarMenu registers (Policy::MENU, which cancels the key so the popover's own close does not also run): APG requires Escape to move focus to this specific menu's own trigger (ctx.focus.set_focus(Some(index))), which native light dismiss has no way to know how to do. There is exactly one trigger for a DropdownMenu, so "return focus to the trigger" can be deferred there; here it cannot.

The close echo of the native toggle and the outside dismissal both act only when this menu is still the one recorded as open. Menubar's effect can move ctx.open_menu straight from Some(this index) to Some(another index) (arrow-key navigation between triggers while a menu is open), and showing the new menu's auto popover natively closes this now-unrelated sibling, firing the toggle callback with false after ctx.open_menu already points at the other menu. An unconditional set_open_menu(None) would then close the menu the user just switched to.

The panel is anchored below its trigger, start-aligned, 8px away (side/align and the gap match the themed CSS's top: 100%; left: 0; margin-top: 0.5rem).

PropTypeDefaultDescription
idStringrequired

The DOM id of the menu's content element.

attributesVec<Attribute>required

Extra HTML attributes for the menu's content element.

childrenElementempty

The menu items.

MenuItemProps Primitive

The props for a plain item in a menu: DropdownMenuItem and DropdownMenuSubItem (crate::dropdown_menu, any T), ContextMenuItem and ContextMenuSubItem (crate::context_menu) and MenubarItem (crate::menubar) (T = String) all take exactly these.

DropdownMenuItem: crate::dropdown_menu::DropdownMenuItem DropdownMenuSubItem: crate::dropdown_menu::DropdownMenuSubItem ContextMenuItem: crate::context_menu::ContextMenuItem ContextMenuSubItem: crate::context_menu::ContextMenuSubItem MenubarItem: crate::menubar::MenubarItem

Also exported as MenubarItemProps.

PropTypeDefaultDescription
valueTrequired

The value of the item, which is passed to the on_select callback when the item is selected.

indexusizeNone

The item's place in keyboard order. Leave it unset: items are ordered as they are created, which is tree order. Set it on every item only when one is inserted between items that are already mounted, or a keyed list reorders them.

disabledboolfalse

Whether the item is disabled. A disabled item cannot be selected and is skipped by roving focus and typeahead. Defaults to false.

text_valueStringNone

Explicit label text used for typeahead search (APG's "Any key that corresponds to a printable character" rule). When not set, falls back to Self::value's own String/&str representation if it has one, else this item is not searchable by typeahead at all -- Select uses the identical fallback for its own generic item value.

on_selectCallback<T>no-op

The callback function that is called when the item is selected. The value of the item is passed as an argument.

variantMenuItemVariantDefault::default()

Whether the item is drawn in the destructive ink -- shadcn's variant="destructive". The role stays menuitem; the item carries data-variant. See MenuItemVariant.

insetboolfalse

Reserves the leading indicator slot without drawing anything -- shadcn's inset -- so a menu that mixes plain and checkable items keeps its labels on one edge. The item carries data-inset="true".

childrenElementempty

The children of the item, which are rendered inside the item element.

Plus the global attributes.

Component-Specific

What is particular to this component.

MenubarCheckboxItem and MenubarRadioGroup + MenubarRadioItem are shadcn's MenubarCheckboxItem/MenubarRadioGroup/MenubarRadioItem. They render role="menuitemcheckbox" / role="menuitemradio" with an always-present aria-checked; radio items sit in a role="group" (name it with aria-label or aria-labelledby). They work in a MenubarContent.

let mut show_status_bar = use_signal(|| false);
let mut position = use_signal(|| "top".to_string());

MenubarContent {
    MenubarCheckboxItem {
        // Controlled: `checked` + `on_checked_change`. Uncontrolled:
        // `default_checked` -- but note the content unmounts when the menu
        // closes, so an uncontrolled item starts over on every open.
        checked: Some(show_status_bar()),
        on_checked_change: move |checked| show_status_bar.set(checked),
        // The menu stays open after a toggle by default (Base UI's
        // `closeOnClick = false`), so several items can be set in one visit.
        // `true` closes it on selection (Radix's `onSelect` behaviour).
        close_on_select: true,
        // A checkbox item has no `value`: set `text_value` to make it a
        // typeahead target.
        text_value: "Status Bar",
        "Status Bar"
    }
    MenubarRadioGroup {
        aria_label: "Panel position",
        value: Some(position()),
        on_value_change: move |value| position.set(value),
        // A radio item's `value` is also its typeahead label.
        MenubarRadioItem { value: "top".to_string(), "Top" }
        MenubarRadioItem { value: "bottom".to_string(), "Bottom" }
    }
}

Click, Enter and Space all select. A disabled item cannot be selected and is skipped by arrow keys and typeahead. Unlike the dropdown and context menus, shadcn's menubar draws the check at the inline start -- same --dx-menu-item-indicator-* slot construction, on the other side. A plain item can reserve the same slot with "data-inset": "true" (shadcn's inset) so a menu that mixes plain and checkable items keeps its labels on one edge. See the checkboxes and radio_group variants.

A menubar never opens a menu from a hover alone -- the first menu always takes a click. Once one is open, though, hovering another trigger switches to it (the native menubar convention). Pass open_on_hover: false to the Menubar to turn that off:

Menubar {
    // Default is `true`.
    open_on_hover: false,
    MenubarMenu { /* ... */ }
}

Moving the pointer across the triggers then does nothing: another menu opens only on click, Enter / Space or the arrow keys. Keyboard behaviour is the same in both modes. See the click_only variant.

Built once in primitives/src/menu_item.rs and shared with the other two menus, these are shadcn's Menubar parts:

MenubarContent {
    MenubarGroup {
        MenubarLabel { "My Account" }
        MenubarItem {
            value: "profile".to_string(),
            // Items take `variant` and `inset`, like shadcn's `variant="destructive"` / `inset`.
            "Profile"
            // A text-only hint pushed to the inline end of the row; it binds no key.
            MenubarShortcut { "⇧⌘P" }
        }
    }
    // A divider between groups: `role="separator"`, not focusable, skipped by arrow keys and typeahead.
    MenubarSeparator {}
    MenubarItem {
        value: "delete".to_string(),
        variant: MenuItemVariant::Destructive,
        "Delete"
    }
}
  • variant (MenuItemVariant::Default or Destructive) paints the item in the theme's destructive text colour with a destructive-tinted highlight. The role stays menuitem and the item carries data-variant.
  • inset reserves the leading indicator slot on an item (or MenubarLabel) that draws none, so a menu that mixes plain and checkable items keeps its labels on one edge. It also exists on the checkbox and radio items. The element carries data-inset="true".
  • MenubarGroup is a role="group" with no behaviour; items inside it stay in the whole menu's keyboard order. Name it with aria-label when it has a visible heading.

See the shortcuts variant.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • MenuCheckboxItemProps: checked with on_checked_change; uncontrolled start value default_checked.
  • MenuRadioGroupProps: value with on_value_change; uncontrolled start value default_value.

The open menu animates in and out over --dx-motion-duration-base with --dx-motion-ease-out / --dx-motion-ease-in, in opacity, scale and translate only (never transform); item highlights use --dx-motion-duration-fast. Retune with those tokens. Reduced motion swaps in --dx-motion-duration-reduced. Nothing loops. See Motion for the tokens, reduced motion and the per-component table.

Menubar accepts a dir: Option<Direction> prop. Its top-level trigger row is always horizontal, so ArrowLeft/ArrowRight between menus always swaps under RTL. See the rtl variant.

Examples

Alternative examples for common configurations.

checkboxes

A View menu mixing checkbox items with plain items, and a Format menu of three checkbox items. Controlled; the menu stays open after a toggle (the default).

radio group

A profile-switching menu and a theme menu, each a radio group with one checked item, controlled and kept open after a choice.

click only

open_on_hover: false: once a menu is open, moving across the other triggers does not switch menus; another menu opens only on click, Enter, Space or the arrow keys.

icons

A media-player menubar whose items each lead with an icon.

shortcuts

Shortcut hints at the end of items, groups split by separators, inset items that line up with checkable ones, and a destructive item. The hints are text only.

Right-to-left layout: the menus and their arrow keys mirror.
