accordion

Install

An accordion component for displaying collapsible content sections.

Basic

The same sections, in the same order, on every component page.

The accordion component is used to display collapsible content panels for presenting information in a limited amount of space. It allows users to expand and collapse sections to view more or less content.

shadcn-dioxus add accordion

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

use dioxus::prelude::*;
use crate::components::icons::ChevronDown;
pub use dioxus_primitives::accordion::AccordionChevron;
use dioxus_primitives::accordion::{
    self, AccordionContentProps, AccordionItemProps, AccordionProps, AccordionTriggerProps,
};
use dioxus_primitives::dioxus_attributes::attributes;
use dioxus_primitives::merge_attributes;

#[component]
pub fn Accordion(props: AccordionProps) -> Element {
    let base = attributes!(div { class: "dx-accordion", "data-dx-root": "", width: "15rem" });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/accordion/style.css") }
        accordion::Accordion {
            attributes: merged,
            ..props
        }
    }
}

#[component]
pub fn AccordionItem(props: AccordionItemProps) -> Element {
    let base = attributes!(div { class: "dx-accordion-item" });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/accordion/style.css") }
        accordion::AccordionItem {
            attributes: merged,
            ..props
        }
    }
}

#[component]
pub fn AccordionTrigger(props: AccordionTriggerProps) -> Element {
    let base = attributes!(button { class: "dx-accordion-trigger" });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    let children = props.children.clone();
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/accordion/style.css") }
        accordion::AccordionTrigger {
            attributes: merged,
            ..props,
            {children}
            ChevronDown {
                class: "dx-accordion-expand-icon",
                size: "16px",
                stroke: "var(--dx-muted-foreground)",
            }
        }
    }
}

#[component]
pub fn AccordionContent(props: AccordionContentProps) -> Element {
    let base = attributes!(div {
        class: "dx-accordion-content",
        style: "--collapsible-content-width: 140px",
    });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    let children = props.children.clone();
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/accordion/style.css") }
        accordion::AccordionContent {
            attributes: merged,
            ..props,
            // This inner wrapper is the direct (and only) child of the
            // animated grid container, so it is what `.dx-accordion-content
            // > *`'s `overflow: hidden; min-height: 0;` targets. It
            // deliberately carries no padding/margin of its own, so its box
            // can shrink all the way to 0 when the grid row collapses.
            // Consumer content -- which is free to put whatever padding it
            // wants on itself, as the demo below does -- lives one level
            // deeper, as a grandchild. Its padding sets no floor on
            // how far the animated box can shrink, because that padding
            // belongs to a *different* box than the one being collapsed --
            // one that `overflow: hidden` on this wrapper clips away
            // entirely once the wrapper itself reaches 0. See the
            // close-animation root-cause comment in style.css.
            div { class: "dx-accordion-content-inner",
                div { class: "dx-accordion-content-body", {children} }
            }
        }
    }
}

// The accordion component must wrap all accordion items.
Accordion {
    // Each accordion item contains both a trigger the expanded contents of the item.
    AccordionItem {
        // The trigger is used to expand or collapse the item.
        AccordionTrigger {}
        // The content that is shown when the item is expanded.
        AccordionContent {}
    }
}

AccordionContent supplies shadcn's Nova spacing itself (text-sm, no top padding, 10px below), so content needs no padding of its own. The trigger is text-sm font-medium with 10px of vertical padding and a 16px chevron in muted-foreground. Content that adds its own bottom padding (for example 1rem) leaves a larger gap than Nova.

AccordionProps Primitive

The props for the Accordion component.

PropTypeDefaultDescription
idStringNone

The id of the accordion root element.

allow_multiple_openboolfalse

Whether multiple accordion items are allowed to be open at once.

Defaults to false.

disabledboolfalse

Set whether the accordion is disabled.

collapsiblebooltrue

Whether the accordion can be fully collapsed.

Setting this to true will allow all accordion items to close. Defaults to true.

horizontalboolfalse

Whether the accordion is horizontal.

Settings this to true will use left/right keybinds for navigation instead of up/down. Defaults to false.

hidden_until_foundboolfalse

Keep every AccordionContent mounted while closed and mark it hidden="until-found", so the browser's find-in-page (Ctrl+F) and #fragment navigation can reach text inside closed items. When they do, the browser reveals the content and the item opens: the item's on_change is called with true, and when allow_multiple_open(Self::allow_multiple_open) is false the other open item closes, exactly as if its trigger had been clicked.

Defaults to false, which unmounts closed content after its close animation, so it costs nothing until opted in; opting in renders every item's content into the server-rendered HTML as well. Opening because of a match is not animated (the browser has already scrolled to the match at full size); the close animation plays as usual, and the content is re-hidden once it finishes.

Browser support: Chrome 102+, Safari 26.2+ (does not scroll to the match) and Firefox 139+ (148+ for a correct scroll target). Engines that do not know until-found treat it as plain hidden: closed content stays unsearchable, as without the prop. Like hidden, closed content is not in the accessibility tree.

Revealing is not blocked by disabled on the accordion or on an item.

chevronAccordionChevronDefault::default()

Which end of every trigger row the expand chevron sits on: AccordionChevron::End (default, after the label) or AccordionChevron::Start (before it). Emitted as data-chevron ("start" / "end") on the root and on every AccordionTrigger, so the theme places and rotates the chevron from one attribute. The primitive draws no chevron itself; the styled component reads this.

default_valueVec<String>empty

The values of the items open initially when the accordion is not controlled (Radix's defaultValue). Single mode (allow_multiple_open false) holds at most one; an item's default_open is applied on top at mount (in single mode the later one wins). See AccordionItemProps::value for what an item's value is.

valueVec<String>None

The values of the open items, to drive the accordion when controlled (Radix's value). While it is Some, the accordion shows exactly these items open and a click only calls on_value_change; it is up to the caller to write the new list back. None (the default) leaves the state to the accordion. Single mode shows a list of more than one value as all open, so pass at most one there.

on_value_changeCallback<Vec<String>>no-op

Called with the new list of open item values after a trigger click or a find-in-page reveal (Radix's onValueChange). Single mode passes a list of at most one value; an empty list means the last open item closed.

childrenElementempty

The children of the accordion, which should contain AccordionItem components.

Plus the global attributes.

default_openboolfalse

Whether this accordion item should be opened by default.

Callback for when the accordion's open/closed state changes.

The new value is provided.

on_trigger_clickCallbackDefault::default()

Callback for when the trigger is clicked.

childrenElementempty

The children of the accordion item.

Plus the global attributes.

Component-Specific

What is particular to this component.

By default opening an item closes the one that was open. Pass allow_multiple_open: true on Accordion (shadcn's multiple) and each item toggles on its own; default_open: true on an AccordionItem starts it open (shadcn's defaultValue). See the multiple variant.

Accordion { allow_multiple_open: true,
    AccordionItem { default_open: true,
        AccordionTrigger { "Notification Settings" }
        AccordionContent { "..." }
    }
    AccordionItem {
        AccordionTrigger { "Privacy & Security" }
        AccordionContent { "..." }
    }
}

Give the Accordion a value (Radix's value) to own the open items yourself: it is the list of open item values, an item is named by its AccordionItem value, and a click on a trigger only calls on_value_change with the new list, so you write it back. Without value the accordion keeps its own state, exactly as before; default_value seeds that state, next to default_open on an item. With allow_multiple_open: false the list holds at most one value, and an empty list means everything is closed. See the controlled variant: two buttons outside the accordion change the signal and the accordion follows.

An item without a value is named by its position as a decimal string ("0", "1", ...), so give items a value as soon as the list can reorder or change.

let mut open = use_signal(|| vec!["shipping".to_string()]);
rsx! {
    Accordion {
        value: Some(open()),
        on_value_change: move |next: Vec<String>| open.set(next),
        AccordionItem { value: Some("shipping".to_string()),
            AccordionTrigger { "Shipping" }
            AccordionContent { "..." }
        }
        AccordionItem { value: Some("returns".to_string()),
            AccordionTrigger { "Returns" }
            AccordionContent { "..." }
        }
    }
}

Controlled, default_open and default_value are ignored, and a find-in-page reveal (hidden_until_found) goes through on_value_change too, so a caller that does not write the value back keeps the item closed. An item's own on_change still follows its open state.

Pass chevron: AccordionChevron::Start on Accordion to put the chevron before the label (default AccordionChevron::End, shadcn's layout). It points right when closed and down when open, instead of down and up. The prop is emitted as data-chevron (start / end) on the root and on every trigger, so a custom trigger can read it from its own element.

A trigger never underlines on hover, open or collapsed. That is a deliberate deviation from shadcn, which underlines every trigger on hover.

Accordion { chevron: AccordionChevron::Start,
    AccordionItem {
        AccordionTrigger { "Installation" }
        AccordionContent { "..." }
    }
}

By default closed items are unmounted after their close animation, so find-in-page (Ctrl+F) cannot see their text and a #fragment link cannot open them. Pass hidden_until_found: true on Accordion to keep every item's content mounted and mark it hidden="until-found" once it is closed. The browser then searches it, and when a match is inside a closed item it reveals the content and the accordion opens that item: on_change is called with true, and with allow_multiple_open: false (the default) the open item closes, exactly as if the trigger had been clicked. See the until_found variant: try Ctrl+F for the word in its hint.

Accordion {
    hidden_until_found: true,
    AccordionItem {
        AccordionTrigger { "Returns" }
        AccordionContent { "Text that Ctrl+F can find while closed" }
    }
}

Opening and closing by trigger animate the height as usual, and the content is re-hidden once the close animation finishes. Opening because of a match is not animated, because the browser has already scrolled to the match at full size. AccordionContent exposes data-closing (only while the close animation runs) and data-revealed (open because of a match) for styling this; key a close animation on data-closing, not on data-closed, which is also how a closed panel looks at rest.

Cost: every item's content is mounted (and, on a server-rendered page, hydrated) while closed, and it is in the server-rendered HTML. That is why it is opt-in.

Browser support

Enginehidden="until-found"beforematch
Chrome / Edge 102+YesYes
Firefox148+ (139 to 147: reveals, may scroll to the wrong place)139+
Safari26.2+, partial: reveals the content but does not scroll to the match26.2+
Older enginesTreated as plain hidden: the content stays closed and unsearchable, exactly as without the propn/a

Nothing breaks where it is unsupported: the content is simply not found by find-in-page, as it is by default.

Accessibility

Closed until-found content is hidden from the accessibility tree exactly like hidden: screen readers do not read it while the item is closed, and the trigger's aria-expanded stays false. Find-in-page is the one way to reach it without activating the trigger; it is exposed as soon as it opens, and aria-expanded follows.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • AccordionProps: value with on_value_change; uncontrolled start value default_value.

A panel's height opens and closes with dx-accordion-open / dx-accordion-close over --dx-motion-duration-slower, and the chevron rotates with the same duration. A panel revealed by find-in-page (hidden_until_found) skips the animation by design, so the browser can scroll to the match inside it. Retune with the token. Reduced motion swaps in --dx-motion-duration-reduced. Nothing loops. See Motion for the tokens, reduced motion and the per-component table.
