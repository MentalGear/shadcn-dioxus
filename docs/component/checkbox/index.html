A togglable checkbox component.

Basic

The same sections, in the same order, on every component page.

The Checkbox component is used to create an accessible checkbox input.

shadcn-dioxus add checkbox

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

use dioxus::prelude::*;
use crate::components::icons::{Check, Minus};
use dioxus_primitives::checkbox::{self, CheckboxProps};
use dioxus_primitives::dioxus_attributes::attributes;
use dioxus_primitives::merge_attributes;

// dev-docs/backlog.md row 32: this stylesheet is
// plain, unhashed `dx-`-prefixed CSS (collision safety comes from
// scripts/check-dx-class-prefix.sh instead of a hash), delivered the same
// way `site/head.rs`'s `GlobalHead` delivers its sheets: an
// `asset!()`-bundled path linked via `document::Link`. Unlike that
// call site this one lives *inside* the themed wrapper itself so a
// `shadcn-dioxus add checkbox`-copied component keeps working with zero
// extra wiring in the consumer's own app -- `asset!()` resolves this path
// from the crate root (manganis-macro's `resolve_path`), and `shadcn-dioxus add`
// preserves this file's `src/components/checkbox/` location verbatim in
// the consumer project (dioxus-cli's `components_root` defaults to
// `<crate>/src/components`), so the path keeps resolving post-copy.
// `document::Link` dedupes by `(href, rel)` (dioxus-document's own doc
// comment on `LinkProps::href`), so re-rendering `Checkbox` many times on
// one page inserts the stylesheet exactly once.
#[component]
pub fn Checkbox(props: CheckboxProps) -> Element {
    let base = attributes!(input { class: "dx-checkbox", "data-dx-root": "" });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/checkbox/style.css") }
        checkbox::Checkbox {
            attributes: merged,
            ..props,
            checkbox::CheckboxIndicator { class: "dx-checkbox-indicator",
                // The primitive mounts these for checked AND indeterminate; CSS shows the
                // glyph that matches the indicator's `data-checked` / `data-indeterminate` (never both).
                Check { class: "dx-checkbox-glyph-check", size: "1rem" }
                Minus { class: "dx-checkbox-glyph-minus", size: "1rem" }
            }
        }
    }
}

// The themed Checkbox renders a button that already contains its own indicator: a check
// for checked and a minus for indeterminate. It takes no children, so there is nothing to
// put inside it.
Checkbox {
    name: "terms",
    default_checked: CheckboxState::Unchecked,
    on_checked_change: move |state: CheckboxState| { /* ... */ },
}

CheckboxProps Primitive

The props for the Checkbox component.

PropTypeDefaultDescription
checkedCheckboxStateNone

The controlled state of the checkbox.

default_checkedCheckboxStateCheckboxState::Unchecked

The default state of the checkbox when it is not controlled.

requiredboolfalse

Whether the checkbox is required in a form.

disabledboolfalse

Whether the checkbox is disabled.

read_onlyboolfalse

Whether the checkbox is read-only: it stays focusable and is announced (aria-readonly), but a click or Space does not change its state, and its value still submits with a form. Distinct from disabled, which removes it from the tab order and from the submission.

nameString""

The name of the checkbox, used in forms.

formStringNone

The id of a <form> the hidden input belongs to (the HTML form attribute), so a control rendered outside its <form> still submits and resets with it. None leaves the input's owner to the DOM ancestor.

valueStringString::from("on")

The value of the checkbox, which can be used in forms.

on_checked_changeCallback<CheckboxState>no-op

Callback that is called when the checked state changes.

childrenElementempty

The children to render inside the checkbox.

Plus the global attributes.

CheckboxIndicator Primitive

CheckboxIndicator

The indicator for the Checkbox component, which visually represents the checkbox state. The children will only be rendered when the checkbox is checked.

This must be used inside a Checkbox component.

Example
use dioxus::prelude::*;
use dioxus_primitives::checkbox::{Checkbox, CheckboxIndicator};
#[component]
fn Demo() -> Element {
    rsx! {
        Checkbox {
            name: "tos-check",
            aria_label: "Demo Checkbox",
            CheckboxIndicator {
                "✅"
            }
        }
    }
}
Styling

The CheckboxIndicator component defines the following data attributes you can use to control styling:

  • data-checked / data-unchecked / data-indeterminate: Exactly one is present: the state of the control.
  • data-checked / data-unchecked / data-indeterminate: Present (empty) in the matching state, absent otherwise.
  • data-disabled: Indicates if the checkbox is disabled. values are true or false.
PropTypeDefaultDescription
childrenElementempty

Shown while the checkbox is checked or indeterminate, such as a check icon.

Plus the global attributes.

BubbleInput Primitive

PropTypeDefaultDescription
checkedCheckboxStaterequired

The checkbox's state, mirrored onto the hidden native input so a form submits it.

default_checkedCheckboxStaterequired

The state the form restores on reset: the checkbox's default state.

on_resetCallback<()>no-op

Called when the owning <form> fires a native reset event, so the component's own (Dioxus-side) checked state can resync -- the browser reset algorithm only restores this input's own checked IDL property from its .defaultChecked (see use_default_checked below); it never touches Checkbox's signal.

Plus the <input> element's attributes.

Component-Specific

What is particular to this component.

Pass CheckboxState::Indeterminate (checked or default_checked) for a "some selected" parent box: it is filled like a checked box and shows a minus instead of the tick, with aria-checked="mixed". A click on an indeterminate box unchecks it (the next state is Unchecked, delivered to on_checked_change); a controlled parent box that wants "select all" instead sets Checked itself in the handler.

Pass form: "form-id".to_string() (the HTML form attribute) and the control's hidden mirror input belongs to that <form> even when it is rendered elsewhere in the page: it submits with it and the form's reset restores it. Leave it out and the nearest ancestor <form> owns it.

read_only: true keeps the checkbox focusable and announced but unchangeable: a click or Space does nothing, the element carries aria-readonly="true" and a data-readonly presence attribute (absent when the checkbox is writable), and its value still submits with a form. It differs from disabled, which leaves the tab order, is not announced as editable and submits nothing. A form reset still restores the default. See the read_only variant.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • CheckboxProps: checked with on_checked_change; uncontrolled start value default_checked.
