dropdown menu

Install

A dropdown menu component for selecting options from a list.

Basic

The same sections, in the same order, on every component page.

The DropdownMenu component is used to create a dropdown menu that can be triggered by a button click. It allows users to select an option from a list of items.

shadcn-dioxus add dropdown_menu

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

/// Themed wrapper for [`dropdown_menu::DropdownMenuSubTrigger`]. Carries
/// both `dx-dropdown-menu-item` (same hover/focus/disabled chrome every
/// plain item gets) and `dx-dropdown-menu-sub-trigger` (the open-state
/// highlight) -- see `style.css`. Appends a `ChevronRight` icon after the
/// caller's own content, the same "submenu, opens to the side" affordance
/// `select/component.rs`'s `SelectTrigger` uses `ChevronDown` for -- a real
/// icon element, not CSS-generated `content:` text, so it never risks
/// becoming part of the trigger's accessible name the way generated text
/// content can (`playwright/oracle/tier1-apg/menu-submenu.spec.ts` matches
/// this trigger by its visible "More tools" name; a decorative icon with no
/// text/title, like every other icon this crate composes this way, cannot
/// change that name).
#[component]
pub fn DropdownMenuSubTrigger(props: DropdownMenuSubTriggerProps) -> Element {
    let base = attributes!(div {
        class: "dx-dropdown-menu-item dx-dropdown-menu-sub-trigger",
        "data-dx-menu-item": "true",
    });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);

    let children = props.children.clone();
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/dropdown_menu/style.css") }
        dropdown_menu::DropdownMenuSubTrigger {
            attributes: merged,
            ..props,
            {children}
            ChevronRight {
                class: "dx-dropdown-menu-item-indicator dx-dropdown-menu-sub-trigger-icon",
                "data-dx-menu-item-indicator": "end",
                size: "16px",
            }
        }
    }
}

/// A non-interactive heading for a group of items -- shadcn's
/// `DropdownMenuLabel`. Pure presentation (the primitive has no label
/// component): give it an `id` and point a [`DropdownMenuRadioGroup`]'s
/// `aria-labelledby` at it so the group is named.
#[component]
pub fn DropdownMenuLabel(
    /// Reserves the leading indicator slot -- shadcn's `inset` -- so the heading
    /// lines up with inset items. Carries `data-inset="true"`.
    #[props(default)]
    inset: bool,
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// The label text.
    children: Element,
) -> Element {
    let base = attributes!(div {
        class: "dx-dropdown-menu-label",
        "data-dx-menu-label": "true",
    });
    let inset_attr = attributes!(div {
        "data-inset": inset.then_some("true"),
    });
    let merged = merge_attributes(vec![base, attributes, inset_attr]);

    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/dropdown_menu/style.css") }
        div { ..merged, {children} }
    }
}

// The dropdown menu component must wrap all dropdown items.
DropdownMenu {
    // The dropdown menu trigger is the button that will display the dropdown menu when clicked.
    DropdownMenuTrigger {
        // The content of the trigger to display inside the button.
        "Open menu"
    }
    // The dropdown menu content contains all the items that will be displayed in the dropdown menu.
    DropdownMenuContent {
        // Each dropdown menu item represents an individual option in the dropdown menu. Arrow keys move through the items in document order.
        DropdownMenuItem {
            // The value of the item which will be passed to the on_select callback when the item is selected.
            value: "open".to_string(),
            on_select: |value: String| {
                // This callback is triggered when the item is selected.
                // The value parameter contains the value of the selected item.
            },
            "Open"
        }
    }
}

DropdownMenuContentRendered Primitive

The menu panel. In the browser arm it is promoted to the top layer via popover="auto" so it escapes clipping and transformed ancestors, the same construction Tooltip/HoverCard/non-modal Popover use (dev-docs/plan.md Phase 4.4), and gets the platform's light dismiss (an outside pointerdown; Escape is the dismiss layer's) beside this crate's own DOM-truth dismissal. Without the popover API it is a plain, always-in-flow div, visible exactly when render() (DropdownMenuContent) mounts it.

menu_root::use_menu_panel drives showPopover()/hidePopover() from open and mirrors the browser's own toggle event (fired on light dismiss, Escape, or any other close) back into set_open, so the Rust signal can never strand the way dev-docs/reference/platform-rationale.md Caveat 1 documents for <dialog>'s one-way showModal()/close() binding. A native close also clears the focus collection and marks the close as caused outside the menu.

The menu is placed at side/align, side_offset px from the trigger (top_layer::use_anchor_position_ fallback). The defaults match the Radix dropdown menu: below the trigger and start-aligned with it, because a menu's items read from the trigger's own leading edge. The content carries no data-side: the engine's [data-side] anchor rules use an 8px gap, so this measured placement is the one authority, and it publishes the resolved data-placed-side.

"Did focus or a press leave the whole widget" is asked of the DOM (DropdownMenu's dismiss layer on the root's id, which covers the trigger and this content, submenus included, since a DropdownMenuSub's content is a DOM descendant of this one): a trigger onblur would answer it from ctx.focus.any_focused(), a Rust-tracked signal a raw external .focus() call never updates.

PropTypeDefaultDescription
idStringrequired

The DOM id of the menu's content element.

sideContentSiderequired

The side of the trigger the menu opens on (DropdownMenuContentProps::side).

alignContentAlignrequired

The menu's alignment along that side (DropdownMenuContentProps::align).

side_offsetu32required

The gap to the trigger in px (DropdownMenuContentProps::side_offset).

attributesVec<Attribute>required

Extra HTML attributes for the menu's content element.

childrenElementempty

The menu items.

Component-Specific

What is particular to this component.

A DropdownMenuContent (or another submenu's own DropdownMenuSubContent) may nest a submenu with DropdownMenuSub/DropdownMenuSubTrigger/ DropdownMenuSubContent/DropdownMenuSubItem, implementing the APG "Menu and Menubar" pattern's submenu contract (ArrowRight/Enter/Space opens and moves focus to the first item; Escape/ArrowLeft closes and returns focus to the sub-trigger; the parent menu stays open). A submenu may hold plain items but not a further nested submenu of its own (one level of nesting).

DropdownMenuContent {
    DropdownMenuSub {
        // The sub-trigger is itself an item of the enclosing menu, in its
        // keyboard order like `DropdownMenuItem`.
        DropdownMenuSubTrigger {
            "More tools"
        }
        // Only rendered while the submenu is open.
        DropdownMenuSubContent {
            DropdownMenuSubItem {
                value: "duplicate".to_string(),
                on_select: |value: String| {
                    // Selecting a sub-item closes the entire menu tree,
                    // not just this submenu.
                },
            }
        }
    }
}

Open on hover, or click only

By default hovering a DropdownMenuSubTrigger opens its submenu after a short delay (100 ms) and leaving it closes the submenu again after a short grace delay, so a diagonal move toward the submenu is not misread as leaving. Pass open_on_hover: false to the DropdownMenuSub for click activation:

DropdownMenuSub {
    // Default is `true`.
    open_on_hover: false,
    DropdownMenuSubTrigger { "Export as" }
    DropdownMenuSubContent { /* ... */ }
}

The submenu then opens only on click, Enter, Space or the open arrow key, and the pointer never opens or closes it: it closes on Escape / the close arrow, an outside click, or focus moving elsewhere. Keyboard behaviour is the same in both modes, and touch never hover-opens. The prop is named after Base UI's Menu.SubmenuTrigger openOnHover (default true); it sits on the Sub rather than the trigger because the trigger and the submenu content share the hover timers. See the click_only_submenu variant.

DropdownMenuCheckboxItem and DropdownMenuRadioGroup + DropdownMenuRadioItem are shadcn's DropdownMenuCheckboxItem/DropdownMenuRadioGroup/DropdownMenuRadioItem. They render role="menuitemcheckbox" / role="menuitemradio" with an always-present aria-checked; radio items sit in a role="group" (name it with aria-label or aria-labelledby). They work in a DropdownMenuContent and in a DropdownMenuSubContent.

let mut show_status_bar = use_signal(|| false);
let mut position = use_signal(|| "top".to_string());

DropdownMenuContent {
    DropdownMenuCheckboxItem {
        // Controlled: `checked` + `on_checked_change`. Uncontrolled:
        // `default_checked` -- but note the content unmounts when the menu
        // closes, so an uncontrolled item starts over on every open.
        checked: Some(show_status_bar()),
        on_checked_change: move |checked| show_status_bar.set(checked),
        // The menu stays open after a toggle by default (Base UI's
        // `closeOnClick = false`), so several items can be set in one visit.
        // `true` closes it on selection (Radix's `onSelect` behaviour).
        close_on_select: true,
        // A checkbox item has no `value`: set `text_value` to make it a
        // typeahead target.
        text_value: "Status Bar",
        "Status Bar"
    }
    DropdownMenuRadioGroup {
        aria_label: "Panel position",
        value: Some(position()),
        on_value_change: move |value| position.set(value),
        // A radio item's `value` is also its typeahead label.
        DropdownMenuRadioItem { value: "top".to_string(), "Top" }
        DropdownMenuRadioItem { value: "bottom".to_string(), "Bottom" }
    }
}

Click, Enter and Space all select. A disabled item cannot be selected and is skipped by arrow keys and typeahead. The check is drawn at the inline end, in a slot the item reserves (the same --dx-menu-item-indicator-* construction as the sub-trigger chevron), so a long label never meets it and an unchecked item does not shift its label. See the checkboxes and radio_group variants.

Built once in primitives/src/menu_item.rs and shared with the other two menus, these are shadcn's DropdownMenu parts:

DropdownMenuContent {
    DropdownMenuGroup {
        DropdownMenuLabel { "My Account" }
        DropdownMenuItem::<String> {
            value: "profile".to_string(),
            // Items take `variant` and `inset`, like shadcn's `variant="destructive"` / `inset`.
            "Profile"
            // A text-only hint pushed to the inline end of the row; it binds no key.
            DropdownMenuShortcut { "⇧⌘P" }
        }
    }
    // A divider between groups: `role="separator"`, not focusable, skipped by arrow keys and typeahead.
    DropdownMenuSeparator {}
    DropdownMenuItem::<String> {
        value: "delete".to_string(),
        variant: MenuItemVariant::Destructive,
        "Delete"
    }
}
  • variant (MenuItemVariant::Default or Destructive) paints the item in the theme's destructive text colour with a destructive-tinted highlight. The role stays menuitem and the item carries data-variant.
  • inset reserves the leading indicator slot on an item (or DropdownMenuLabel) that draws none, so a menu that mixes plain and checkable items keeps its labels on one edge. It also exists on the checkbox and radio items and, where the menu has submenus, on the sub-trigger. The element carries data-inset="true".
  • DropdownMenuGroup is a role="group" with no behaviour; items inside it stay in the whole menu's keyboard order. Name it with aria-label when it has a visible heading.

See the shortcuts and destructive variants.

DropdownMenuContent opens below its trigger, start-aligned with it, 4px away. side (ContentSide::Top, Right, Bottom or Left), align (ContentAlign::Start, Center or End) and side_offset (the gap, in px) move it. A side without room flips to the opposite one, and the side the menu was actually placed on is on the content as data-placed-side. See the placement variant.

The page stays scrollable while a DropdownMenu is open, and the menu stays open while the page scrolls: it is anchored to its trigger, may not be fully in view when it opens, and the user must be able to scroll to it. The menu takes no scroll lock and has no modal prop; outside a press on the page closes it. Only the modal surfaces (Dialog, AlertDialog, Sheet, Drawer, a Popover with is_modal: true) and ContextMenu lock the page.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • DropdownMenuProps: open with on_open_change; uncontrolled start value default_open.
  • MenuSubProps: open with on_open_change; uncontrolled start value default_open.
  • MenuCheckboxItemProps: checked with on_checked_change; uncontrolled start value default_checked.
  • MenuRadioGroupProps: value with on_value_change; uncontrolled start value default_value.

The menu panel fades and scales in over --dx-motion-duration-base (opacity, scale from 0.95 and a 2px translate, never transform, so the anchor's centring survives) and fades out with --dx-motion-ease-in; item highlights use --dx-motion-duration-fast. Retune with those tokens. Reduced motion swaps in --dx-motion-duration-reduced. Nothing loops. See Motion for the tokens, reduced motion and the per-component table.

DropdownMenu accepts a dir: Option<Direction> prop, inherited by every DropdownMenuSub. Under RTL: the submenu open key is ArrowLeft instead of ArrowRight, the close key ArrowRight instead of ArrowLeft (Escape always closes regardless of direction), and each DropdownMenuSubContent opens to the left of its trigger instead of the right. See the rtl variant.

A component that composes this one retunes it by setting one of these custom properties on its own element, never by declaring the property on its own class: two stylesheets declaring one property on one element are decided by which sheet loads last, and that order differs from route to route. The component reads each variable with its own default, so a variable that is not set changes nothing. Custom properties inherit: set one on the exact element, not on an ancestor, or it reaches every nested instance too.
