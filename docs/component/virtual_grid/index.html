virtual grid

Extra
Install

Extra: not in shadcn/ui. A data grid or gallery that renders only the cells in view, rows and columns; shadcn/ui has no virtualized grid.

A grid for large datasets that mounts only the cells in view: a data grid with rows and columns windowed, or a gallery of items wrapping into rows.

Row
1

Active cell: row 1, column 1. Click a cell, then use the arrow keys, Home/End, Ctrl+Home/End and PageUp/PageDown.

shadcn-dioxus add virtual_grid

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

/// Styled wrapper around the primitive `VirtualGrid` (rows and columns windowed).
#[component]
pub fn VirtualGrid(props: VirtualGridProps) -> Element {
    let base = attributes!(div {
        class: "dx-virtual-grid", "data-dx-root": ""
    });
    let merged = merge_attributes(vec![base, props.attributes]);

    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/virtual_grid/style.css") }
        dioxus_primitives::virtual_grid::VirtualGrid {
            row_count: props.row_count,
            column_count: props.column_count,
            row_height: props.row_height,
            column_width: props.column_width,
            render_cell: props.render_cell,
            render_header: props.render_header,
            header_height: props.header_height,
            sticky_first_column: props.sticky_first_column,
            row_buffer: props.row_buffer,
            column_buffer: props.column_buffer,
            dir: props.dir,
            on_active_change: props.on_active_change,
            fade: props.fade,
            attributes: merged,
        }
    }
}

The VirtualGrid component keeps a very large grid cheap by mounting only the cells in view. It comes in three layouts: VirtualGrid, a data grid whose rows AND columns are windowed (with an optional sticky header row and sticky first column), VirtualWrapGrid, a gallery whose items wrap into rows of a fixed column count (only the rows are windowed), and VirtualJustifiedGrid, a photo wall of justified rows (every photo uncropped at its own aspect ratio, rows filling the width edge to edge).

// A data grid: 10,000 rows x 50 columns, a few hundred cells in the DOM.
VirtualGrid {
    row_count: 10_000usize,
    column_count: 50usize,
    // Optional: px per row / column (default 36 / 120).
    row_height: |_row: usize| 36,
    column_width: |column: usize| if column == 0 { 80 } else { 112 },
    // Optional: a header row that sticks to the top, and a first column that sticks to the inline start.
    render_header: |column: usize| rsx! { "Column {column}" },
    sticky_first_column: true,
    render_cell: |(row, column): (usize, usize)| rsx! { "{row}, {column}" },
    "aria-label": "Readings",
    style: "height: 24rem;",
}

// A gallery: 5,000 items in rows of 4, rows measured as they render.
VirtualWrapGrid {
    count: 5_000usize,
    columns: 4usize,
    estimate_row_height: |_row: usize| 140,
    render_item: |index: usize| rsx! { figure { "Photo {index}" } },
    "aria-label": "Photos",
    style: "height: 28rem;",
}

Give the grid a height (or max-height): it is the scroll container. The grid owns its id and role="grid"; every other attribute is spread onto it. Name it with aria-label (or aria-labelledby).

Two models for showing many photos of mixed shapes:

  • Grid (VirtualGrid, VirtualWrapGrid; the default): cells aligned in rows and columns, and the structure never depends on the content. A photo of any aspect is a presentation concern inside a uniform cell: object-fit: contain shows it whole on a mat, cover crops it to fill. Because rows and columns are independent, both axes window independently, aria-colcount is exact and the arrow keys move along straight columns. Pick it for anything tabular, for thumbnails where alignment and predictable scanning matter, and whenever items have no meaningful aspect ratio.
  • Justified (VirtualJustifiedGrid): the gapless, uncropped photo-wall look. Each row takes as many photos as fit at target_row_height and then shrinks to fill the width exactly, so a row's composition depends on the photos' aspect ratios and every tile IS its photo's aspect. There are no columns: ArrowUp/ArrowDown move to the tile of the next row whose horizontal centre is closest. Pick it when the photos themselves are the content and cropping or letterboxing would hurt.
// 20,000 photos; the aspect ratios (width / height) are all the layout needs.
VirtualJustifiedGrid {
    aspects,                       // ReadSignal<Vec<f64>>
    target_row_height: 150.0,      // px a full row is packed toward (default 150)
    gap: 4.0,                      // px between tiles and rows (default 4)
    // Optional: a canvas wider than the grid makes a wall that scrolls both ways.
    canvas_width: Some(4800.0),
    render_tile: |(index, rect): (usize, TileRect)| rsx! {
        // Empty alt (a loading photo paints its alt text in the tile), the name on a wrapper.
        div { role: "img", "aria-label": "Photo {index}", style: "width: 100%; height: 100%;",
            img { src: photo_url(index), alt: "", style: "width: 100%; height: 100%;" }
        }
    },
    "aria-label": "Photos",
    style: "height: 28rem;",
}

Without canvas_width the rows fill the grid's own width, the grid scrolls vertically only and lays the rows out again when it is resized (keeping the row at the top of the viewport in place). With a canvas_width larger than the grid, the rows fill that canvas: the grid scrolls both ways and mounts only the rows that meet the viewport and, within each, only the tiles that meet it horizontally. The full row of a few dozen tiles is never mounted whole. min_tile_width keeps a narrow container from squeezing a portrait photo to a sliver (the row gives up photos to the next one and grows taller). Each tile is placed with inset-inline-start, so in a right-to-left page the wall mirrors (rows start at the right) and ArrowLeft moves to the next photo. The example is the justified variant: a target-row-height slider and a "Wall (both axes)" switch that sets canvas_width to six times the demo's width.

Keyboard: one tab stop; ArrowLeft/ArrowRight move in reading order and continue into the previous/next row, ArrowUp/ArrowDown move to the nearest tile by horizontal centre, Home/End go to the row's ends, Ctrl+Home/Ctrl+End to the first/last photo, PageUp/PageDown a viewport up/down. The active tile stays rendered wherever you scroll. The container is role="grid" with the whole wall's aria-rowcount; every row carries aria-rowindex and every tile its position in its row as aria-colindex. aria-colcount is omitted: rows hold different numbers of tiles, so no column count would be true.

Both use the shared engine of VirtualList's windowed mode, one per axis (see "The shared windowing engine" below); VirtualWrapGrid measures its rows as they render.

In the 10,000 x 50 demo about 300 of the 500,000 cells are in the DOM at any time, wherever you scroll.

The grid follows the WAI-ARIA grid pattern. Exactly one cell is in the tab order (the active cell, tabindex="0"); click a cell or Tab into the grid, then:

KeyMoves to
Arrow keysthe neighbouring cell (stops at the edges)
Home / Endthe first / last cell of the row
Ctrl+Home / Ctrl+Endthe first / last cell of the grid
PageUp / PageDowna viewport of rows up / down, same column

The active cell is always rendered, even when it is far outside the window (after Ctrl+End, or when you scroll away from it): a windowed grid that unmounted it would lose focus and its only tab stop (see "Focus stays mounted" below). Each move scrolls the cell into view just past the sticky header and column. on_active_change reports the active cell.

In right-to-left layouts the grid mirrors: the sticky column sits at the right, and ArrowLeft moves to the next cell (inline end). The direction comes from dir, else the nearest DirectionProvider; the layout itself follows the inherited dir attribute through logical CSS properties.

The container is role="grid" with aria-rowcount and aria-colcount of the whole grid, and every mounted row and cell carries aria-rowindex / aria-colindex, so a screen reader announces where a cell is even though only a window exists. Header cells are role="columnheader"; with sticky_first_column the first column's cells are role="rowheader".

A VirtualGrid cell taller than its row overflows it (rows are not measured). For a grid of a few thousand cells, a plain CSS grid with content-visibility: auto on each row may be the simpler answer: everything stays in the DOM and the browser skips the rows that are off-screen. Find-in-page, the accessibility tree and the server are covered under "Find-in-page and the windowed DOM" below.

VirtualList (windowed mode), VirtualGrid, VirtualWrapGrid and VirtualJustifiedGrid mount only what is in view, on one engine and one DOM bridge (primitives/src/virtual/).

  • Overscan. Items beyond each edge of the viewport are mounted too, so a scroll never shows a blank edge: buffer rows for VirtualList (default 8) and VirtualWrapGrid (default 4), row_buffer (default 6) and column_buffer (default 4) for VirtualGrid, and overscan px (default 320) for VirtualJustifiedGrid. The window is re-centred only once fewer than half of that margin remains, so between half and all of it is always ready beyond each edge, and a steady scroll re-renders about once per half margin rather than once per scroll event.
  • Positions. Sizes are kept in a Fenwick tree: measuring an item and finding the item at a pixel are O(log N), and nothing is copied per measurement. Where items are measured (a list's rows, a wrapping grid's rows) an estimate is used until then; an item that resizes above the viewport adjusts the scroll position so content does not jump, and the scroll canvas keeps its size while a scroll is running.
  • Listeners. One passive scroll listener and one ResizeObserver on the container, plus a resize listener on the window, all removed when the component unmounts. Scrolling costs Rust nothing unless the window moves.

The item that last received focus (a link or button inside a row, or the active cell or tile of a grid) stays mounted when you scroll away from it: it is drawn at its own position outside the window (VirtualList marks it data-virtual-pinned), so focus never falls to the page and Tab or the arrow keys continue from where they were. Moving focus elsewhere releases it, and when a scroll brings the window back to it the same DOM node rejoins the flow without remounting. (VirtualList in content-visibility mode keeps every row in the DOM, so there is nothing to pin.)

None of the virtual components traps the page's scroll: at the top or bottom edge of the container a wheel or touch scroll continues on the page (the block axis keeps overscroll-behavior: auto). A container that also scrolls sideways contains only the inline axis (overscroll-behavior-x: contain), so a swipe at its edge does not trigger the browser's back and forward navigation.

Items outside the window do not exist: the browser's find-in-page and #:~:text= links cannot reach them, the accessibility tree holds only what is mounted (each mounted row or cell announces its position in the whole, with aria-posinset or aria-rowindex), and the server renders none of them or only the active one. The opt-in text_value of a windowed VirtualList keeps every row's plain text in the DOM as a hidden="until-found" placeholder, so find-in-page can match rows that are not mounted (the find_in_page variant); the grids have no such placeholders, because a cell is not a line of text. Where findability matters more than a flat cost, a plain list or CSS grid of a few thousand items with content-visibility: auto keeps everything findable while the browser skips the off-screen work (VirtualList's content-visibility mode is exactly that).

fade: ScrollFade (None by default; Y, X, Both, Top, Bottom, Start, End) puts the matching dx-scroll-fade-* class on the container, which is the element that scrolls, exactly as on ScrollArea. The fade is a CSS scroll-driven mask driven by the container's own scroll offset, so it follows the scrollbar whichever rows or cells are mounted (a windowed list of 20,000 rows or a grid of 500,000 cells fades exactly like a short one), and a container whose content fits has no fade. Both masks all four edges of a container that scrolls on both axes (a VirtualGrid, or a justified wall with a canvas_width), each edge only while there is content past it.

VirtualList { count: 20_000usize, fade: ScrollFade::Y, render_item: .. }
VirtualGrid { row_count: 1_000usize, column_count: 30usize, fade: ScrollFade::Both, render_cell: .. }
  • It needs dx-effects.css linked once at the app root next to the theme (the virtual_list and virtual_grid component.json list it in globalAssets). Without it the prop is inert. See the dx-scroll-fade utility in the ScrollArea docs for the variables that tune depth and reveal distance.
  • The mask covers everything inside the container: a border or background on it fades with the content (put those on a wrapper and set border: none on the container), and so does a VirtualGrid's sticky header, which a top fade dims once you scroll (prefer ScrollFade::Bottom or End with render_header).
  • Examples: the fade variants (a windowed list and a content-visibility list; a wrapping gallery and a two-axis data grid).

Rows are [role=row]; cells carry data-grid-cell="row:column" (the header's is "header:column"), and the sticky header and column carry data-grid-header / data-grid-sticky. Positions and sizes are inline styles; this component's style.css paints borders, the header, the sticky column's background and the focus ring. In VirtualWrapGrid each row is a CSS grid of equal tracks: set column-gap and padding-block-end on [role=row] for the gaps (they are part of the measured row).

The photo_wall demo is a 300 x 300 wall of 90,000 photos on the two-axis VirtualGrid, scrolling on both axes, with a few hundred cells in the DOM wherever you are (the counter under the wall, "N of 90,000 photos rendered", shows how many).

The photos have mixed aspect ratios (portrait 2:3 and 3:4, square, landscape 4:3, 3:2 and 16:9, and 3:1 panoramas), but the grid does not care: its structure, cells aligned in rows and columns of a fixed size, never depends on content. That is why both axes window independently and the keyboard model stays the plain grid one. The shape of a photo is a presentation concern inside its cell: each photo is an <img> filling a cell-sized mat, and CSS object-fit decides the rest. By default (contain) the whole photo is visible, letterboxed on the mat; the switch above the wall changes it to cover (a tight wall, photos cropped). Each photo is a single <img src="data:image/svg+xml,..."> generated from its index, one DOM node per cell instead of the dozen of an inline <svg>, and nothing is fetched.

  • Pan by scrolling or a trackpad on both axes, or by dragging the wall with a mouse or pen (touch keeps its native scroll). A press that does not move stays a click, which opens the photo.
  • Minimap: the small square shows the whole wall and an outlined box for what the grid shows. Press or drag it to move the viewport there (it sets the grid container's scroll position, which the grid already follows).
  • Jump to random photo scrolls a random cell to the middle of the wall and focuses it.
  • Preview: clicking a cell, or Enter/Space on the focused one, opens the photo in a Dialog at its real aspect ratio. The arrow keys, Home/End and PageUp/PageDown are the grid's own.

One script installed with JsListeners reads the scroll position and the mounted cell count (passive scroll listener, MutationObserver, ResizeObserver, all removed with the demo).

VirtualGridProps Primitive

The props for the VirtualGrid component.

PropTypeDefaultDescription
row_countusizerequired

The number of data rows (the header row, if any, is not counted).

column_countusizerequired

The number of columns.

row_heightCallback<usize, u32>None

The height of a data row by index, in px. Defaults to DEFAULT_ROW_HEIGHT (36) for every row. Rows are not measured: a cell taller than its row overflows it.

column_widthCallback<usize, u32>None

The width of a column by index, in px. Defaults to DEFAULT_COLUMN_WIDTH (120) for every column.

render_cellCallback<(usize, usize), Element>required

Renders the content of the cell at (row, column).

render_headerCallback<usize, Element>None

Renders the header of a column. When given, a header row of role="columnheader" cells sticks to the top of the grid while it scrolls.

header_heightu3240

The height of the header row, in px. Ignored without render_header.

sticky_first_columnboolfalse

Keep the first column at the inline start while the grid scrolls horizontally. Its cells are role="rowheader".

row_bufferusize6

How many rows to mount beyond each edge of the viewport (the window is re-centred once fewer than half of them remain).

column_bufferusize4

How many columns to mount beyond each edge of the viewport.

dirDirectionNone

The reading direction for the horizontal arrow keys. Defaults to the nearest DirectionProvider, else left-to-right. Set the matching dir attribute (or inherit one) so the layout flips with it.

on_active_changeCallback<(usize, usize)>None

Called with (row, column) when the active cell changes (by keyboard, click or focus).

fadeScrollFadeDefault::default()

A scroll-edge fade on the container, which is the element that scrolls (the dx-scroll-fade-* classes of dx-effects.css; see ScrollFade). Defaults to ScrollFade::None. It follows the container's own scroll offset, whatever rows or cells are mounted, and a container whose content fits has no fade. The fade is a mask, so it also fades a border or background on the container (put those on a wrapper) and a VirtualGrid's sticky header (prefer ScrollFade::Bottom / ScrollFade::End with render_header); ScrollFade::Both masks all four edges of a two-axis scroller.

Plus the global attributes.

Plus the global attributes.

VirtualJustifiedGridProps Primitive

The props for the VirtualJustifiedGrid component.

PropTypeDefaultDescription
aspectsVec<f64>required

The aspect ratio (width / height) of every item, in order; the item count is its length. Each tile has exactly its item's aspect, so a photo shown in it is never cropped. A zero, negative or non-finite aspect is drawn as a 1:20 sliver.

render_tileCallback<(usize, TileRect), Element>required

Renders item index inside its tile, given the tile's box (see TileRect). The tile is sized and placed already: fill it, e.g. with an img at width: 100%; height: 100%.

target_row_heightf64DEFAULT_TARGET_ROW_HEIGHT

The row height, in px, that rows are packed toward: a full row takes items until they would overflow the width at this height, then shrinks to fill the width exactly, so it is never taller (unless min_tile_width backs it off). Defaults to DEFAULT_TARGET_ROW_HEIGHT (150). The last row keeps this height and may end short.

gapf64DEFAULT_TILE_GAP

The space between tiles and between rows, in px. Defaults to DEFAULT_TILE_GAP (4).

min_tile_widthf640

The narrowest a tile may be squeezed, in px: a row whose narrowest tile would fall below it gives up items to the next row and grows taller (best effort, bounded at three times the target height). 0 (the default) disables it.

canvas_widthf64None

The width the rows fill, in px. None (the default) fills the grid's own width and lays out again when it resizes: the grid scrolls vertically only. A width larger than the grid makes a two-axis wall: the grid scrolls both ways and windows the tiles of each row by their horizontal position too.

overscanf64DEFAULT_OVERSCAN

How far beyond each edge of the viewport tiles are mounted, in px (the window is moved once fewer than half of them remain). Defaults to DEFAULT_OVERSCAN (320).

dirDirectionNone

The reading direction for the horizontal arrow keys. Defaults to the nearest DirectionProvider, else left-to-right. Set the matching dir attribute (or inherit one) so the tiles flip with it.

on_active_changeCallback<usize>None

Called with the item index when the active tile changes (by keyboard, click or focus).

activeSignal<usize>None

The active tile (the grid's one tab stop) as a signal the caller owns, both ways: the grid writes every keyboard, click or focus move into it, and a write from outside moves the active tile there, scrolls it into view and focuses it (a "jump to photo" button, or keeping one selection across a switch between layouts). Without it the grid keeps its own.

fadeScrollFadeDefault::default()

A scroll-edge fade on the container, which is the element that scrolls (the dx-scroll-fade-* classes of dx-effects.css; see ScrollFade). Defaults to ScrollFade::None. It follows the container's own scroll offset, whatever rows or cells are mounted, and a container whose content fits has no fade. The fade is a mask, so it also fades a border or background on the container (put those on a wrapper) and a VirtualGrid's sticky header (prefer ScrollFade::Bottom / ScrollFade::End with render_header); ScrollFade::Both masks all four edges of a two-axis scroller.

Plus the global attributes.
