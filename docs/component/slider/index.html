An accessable slider component.

50%

Basic

The same sections, in the same order, on every component page.

The slider component allows users to select a value from a range by sliding a handle along a track.

shadcn-dioxus add slider

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

use dioxus::prelude::*;
use dioxus_primitives::dioxus_attributes::attributes;
use dioxus_primitives::merge_attributes;
use dioxus_primitives::slider::{self, RangeSliderProps, SliderProps};

#[component]
pub fn Slider(props: SliderProps) -> Element {
    let base = attributes!(div { class: "dx-slider", "data-dx-root": "" });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/slider/style.css") }
        slider::Slider {
            attributes: merged,
            ..props,
            slider::SliderTrack { class: "dx-slider-track",
                slider::SliderRange { class: "dx-slider-range" }
                slider::SliderThumb { class: "dx-slider-thumb" }
            }
        }
    }
}

#[component]
pub fn RangeSlider(props: RangeSliderProps) -> Element {
    let base = attributes!(div { class: "dx-slider", "data-dx-root": "" });
    let merged = merge_attributes(vec![base, props.attributes.clone()]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/slider/style.css") }
        slider::RangeSlider {
            attributes: merged,
            ..props,
            slider::SliderTrack { class: "dx-slider-track",
                slider::SliderRange { class: "dx-slider-range" }
                slider::SliderThumb { class: "dx-slider-thumb", index: 0usize }
                slider::SliderThumb { class: "dx-slider-thumb", index: 1usize }
            }
        }
    }
}

Slider {
    // The starting value. The slider tracks the drag itself; to control it, pass `value` (a signal) and set it in `on_value_change`.
    default_value: 0.0,
    horizontal: true,
    on_value_change: |value: f64| {
        // Handle the change in slider value.
    },
}

For a two-thumb range selector, use RangeSlider:

RangeSlider {
    default_value: 20.0..80.0,
    on_value_change: |value: std::ops::Range<f64>| {
        // value.start and value.end give the two endpoints
    },
}

Component-Specific

What is particular to this component.

Give the slider a name and it submits its value with the nearest <form> (or the one whose id is passed as form: "form-id".to_string()), through a hidden input per thumb: a Slider submits one value under its name, a RangeSlider two under the same name, start first. The value is printed at the step's precision (0.3, not 0.30000000000000004). A disabled slider submits nothing and an empty name (the default) submits nothing. The form's reset restores default_value; for a controlled slider it calls on_value_change with the default, so the owner of the value follows. See the form variant.

form {
    Slider { label: "Volume", name: "volume", default_value: 30.0 }
    RangeSlider { label: "Price", name: "price", default_value: 20.0..80.0 }
}

on_value_change fires on every move of a drag. on_value_commit fires once a change is finished: when the pointer is released after a press that moved a value (a drag, or a click on the track), and on each keyboard step that changes the value (arrow keys, Page Up/Down, Home, End). It receives the value (f64, or the Range<f64> of a RangeSlider). A press that leaves the value where it was, a value set from outside and a form reset do not commit.

RangeSlider takes min_steps_between_thumbs: u32 (default 0, the thumbs may meet). The start thumb stops that many steps short of the end thumb and the end thumb that many steps past the start thumb; the thumbs' aria-valuemin/aria-valuemax follow.

RangeSlider takes thumb_collision: ThumbCollision. Clamp (the default) stops a thumb short of the other one. Push moves the other thumb along, keeping min_steps_between_thumbs steps between them, until it reaches min or max. A pushed thumb stays where it was pushed when the first thumb moves back.

Slider and RangeSlider take thumb_alignment: ThumbAlignment. Center (the default) puts the thumb's centre on its value, so half a thumb hangs past the track at min and max. Edge keeps the thumb inside the track, its edge on the track's end at min and max, and maps the pointer onto the distance the thumb's centre can travel. The thumb's size comes from the --dx-slider-thumb-size custom property (the theme sets it to the thumb's width), so the server-rendered page already draws it inside the track; the pointer mapping uses the thumb's size measured once it is mounted.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • SliderProps: value with on_value_change; uncontrolled start value default_value.
  • RangeSliderProps: value with on_value_change; uncontrolled start value default_value.

Slider/RangeSlider accept a dir: Option<Direction> prop, consulted only when horizontal: true (a vertical slider never mirrors, matching Radix). Under RTL: a click near the left end of the track resolves to a value near max (not min); ArrowLeft increases the value and ArrowRight decreases it (the opposite of LTR); the thumb and the filled range visually anchor to the opposite edge. ArrowUp/ArrowDown are never affected. See the rtl variant.
