sheet

Install

A sheet component as an edge panel that complements the main content

Basic

The same sections, in the same order, on every component page.

The sheet component is a panel that slides in from the edge of the screen. It can be used to display additional content, forms, or navigation menus without leaving the current page.

shadcn-dioxus add sheet

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

use dioxus::prelude::*;
use dioxus_primitives::AsChild;
use crate::components::icons::X;
use dioxus_primitives::dialog::{
    self, DialogCtx, DialogDescriptionProps, DialogTitleProps,
};
use dioxus_primitives::dioxus_attributes::attributes;
use dioxus_primitives::drawer::{use_resolved_edge_side, EdgeSide};
use dioxus_primitives::keyboard_inset::{use_keyboard_panel, KeyboardInset};
use dioxus_primitives::merge_attributes;
use dioxus_primitives::state_attrs;

/// The side a [`Sheet`] slides in from. One type for both edge panels: this is
/// [`EdgeSide`], the same enum `Drawer` takes (`DrawerSide` is its other alias). The
/// default of the enum is `Auto` (bottom below the `md` breakpoint, right at and above
/// it); `Sheet` itself defaults its `side` prop to `Right`, as shadcn's does.
pub type SheetSide = EdgeSide;

/// The props for the [`Sheet`] component: [`dialog::DialogRootProps`] plus a typed `side`.
#[derive(Props, Clone, PartialEq)]
pub struct SheetProps {
    /// The ID of the sheet root element.
    pub id: ReadSignal<Option<String>>,

    /// Whether the sheet is modal. If true, it traps focus within the sheet when open.
    #[props(default = ReadSignal::new(Signal::new(true)))]
    pub is_modal: ReadSignal<bool>,

    /// Whether a modal sheet dims the page behind it with the shared overlay scrim.
    /// Defaults to `true`; see [`dialog::DialogRootProps::overlay`].
    #[props(default = ReadSignal::new(Signal::new(true)))]
    pub overlay: ReadSignal<bool>,

    /// The controlled `open` state of the sheet.
    pub open: ReadSignal<Option<bool>>,

    /// The default `open` state of the sheet if it is not controlled.
    #[props(default)]
    pub default_open: bool,

    /// A callback that is called when the open state changes.
    #[props(default)]
    pub on_open_change: Callback<bool>,

    /// Which edge the sheet slides in from. Defaults to [`SheetSide::Right`]. A raw
    /// `"data-side"` attribute (the untyped spelling, which `Sidebar` uses)
    /// overrides it.
    #[props(default = ReadSignal::new(Signal::new(SheetSide::Right)))]
    pub side: ReadSignal<SheetSide>,

    /// Base UI's `disablePointerDismissal`: when `true`, a press outside the panel and focus
    /// moving outside it do not close the dialog (a modal's backdrop click included), so the
    /// first press on the page of a non-modal dialog only acts on the page. Escape and the
    /// dialog's own close controls still close it. Defaults to `false`.
    #[props(default = ReadSignal::new(Signal::new(false)))]
    pub disable_pointer_dismissal: ReadSignal<bool>,

    /// Where focus lands when the panel opens, as a function of how it was opened
    /// ([`OpenModality`](dioxus_primitives::modality::OpenModality)). An input to the one open-focus policy
    /// (`dxOpenFocus`), not a second path: with none, keyboard and mouse opens focus the first
    /// control and touch and pen opens focus the panel (no software keyboard). A selector that
    /// matches nothing falls back to that default.
    #[props(default)]
    pub initial_focus: Option<dioxus_primitives::modality::FocusTargetFn>,

    /// Where focus goes when the panel closes, as a function of the modality of the close.
    /// Default: the element that held focus when it opened (the trigger for a click open, the
    /// previously focused element for a programmatic one).
    #[props(default)]
    pub final_focus: Option<dioxus_primitives::modality::FocusTargetFn>,

    /// Additional attributes to apply to the sheet panel element.
    #[props(extends = GlobalAttributes)]
    pub attributes: Vec<Attribute>,

    /// The children of the sheet.
    pub children: Element,
}

#[component]
pub fn Sheet(props: SheetProps) -> Element {
    let side = use_resolved_edge_side(props.side);

    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/sheet/style.css") }
        dialog::DialogRoot {
            disable_pointer_dismissal: props.disable_pointer_dismissal,
            class: "dx-sheet-root",
            "data-dx-scrim": "",
            "data-slot": "sheet-root",
            id: props.id,
            is_modal: props.is_modal,
            overlay: props.overlay,
            open: props.open,
            default_open: props.default_open,
            on_open_change: props.on_open_change,
            SheetPanel {
                side: side(),
                initial_focus: props.initial_focus,
                final_focus: props.final_focus,
                attributes: props.attributes,
                {props.children}
            }
        }
    }
}

/// The panel: an edge panel of the theme's recipe (`data-dx-surface="edge"` plus the resolved
/// `data-side`). It is its own component to read the dialog's open state: the panel carries its
/// own `data-open` / `data-closed`, because the recipe's slide is keyed on it and the non-web/non-modal arms
/// of the dialog primitive put none on their content element.
#[component]
fn SheetPanel(
    /// The edge the panel slides in from, already resolved from the sheet's `side`.
    side: SheetSide,
    /// The sheet's `initial_focus`, for the dialog content.
    initial_focus: Option<dioxus_primitives::modality::FocusTargetFn>,
    /// The sheet's `final_focus`, for the dialog content.
    final_focus: Option<dioxus_primitives::modality::FocusTargetFn>,
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// The sheet's content.
    children: Element,
) -> Element {
    let ctx: DialogCtx = use_context();
    // The panel follows the on-screen keyboard (`primitives/src/keyboard_inset.rs`; `style.css`
    // consumes `--dx-keyboard-inset`).
    let panel = use_keyboard_panel(None);
    let content_base = attributes!(div {
        class: "dx-sheet",
        "data-slot": "sheet-content",
        "data-dx-surface": "edge",
        "data-side": side.as_str(),
        ..state_attrs::open(ctx.is_open()),
    });
    let content_attributes = merge_attributes(vec![content_base, attributes]);

    rsx! {
        dialog::DialogContent {
            id: panel.id(),
            class: None,
            initial_focus,
            final_focus,
            attributes: content_attributes,
            {children}
            KeyboardInset { panel }
        }
    }
}

#[component]
pub fn SheetContentClose(#[props(extends = GlobalAttributes)] attributes: Vec<Attribute>) -> Element {
    // axe `button-name` (dev-docs/backlog.md row 34): this button's
    // only content is the `X` icon, with no text and no accessible name --
    // `DialogClose`/`AlertDialogClose` get theirs per call site
    // (`dialog/variants/main/mod.rs`'s `aria_label: "Close"`); it is baked in
    // here because both call sites
    // (`sheet/variants/main/mod.rs`, `sidebar/component.rs`) render this
    // shared wrapper with no children of their own to derive a name from.
    let base = attributes!(button {
        class: "dx-sheet-close",
        aria_label: "Close",
    });
    let attributes = merge_attributes(vec![base, attributes]);

    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/sheet/style.css") }
        SheetClose { attributes,
            // shadcn's close icon is `size-4` (16px) -- style.css's own
            // `.dx-sheet-close` comment has the full rationale for keeping
            // the 24px button box around it as a WCAG 2.5.8 hit target.
            X { size: "16px" }
        }
    }
}

// No `document::Link` here (unlike this file's other exported components):
// `SheetClose` reads `DialogCtx` via `use_context()` below, so it can only
// ever render as a descendant of a `dialog::DialogRoot` -- and in this file
// that context is provided by `Sheet` alone, which already links the sheet
// stylesheet. A context lookup failure would panic before this component
// could render unstyled, so there's no code path where `SheetClose` reaches
// the DOM without `Sheet`'s own `Link` already in the document head. It also
// has no single `rsx!` block both branches share (the `r#as` branch returns
// straight from the caller's own `Callback`), so adding a `Link` here would
// mean wrapping each branch individually -- unlike this file's other parts,
// that's more than a mechanical one-line insertion for a guarantee the
// context dependency already gives for free.
#[component]
pub fn SheetClose(
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// Renders the close control as the element the callback returns, instead of a `<button>`. The
    /// callback gets the close handler and attributes, and the children.
    r#as: Option<Callback<AsChild, Element>>,
    /// The close control's content.
    children: Element,
) -> Element {
    let ctx: DialogCtx = use_context();

    let base = attributes! {
        button {
            onclick: move |_| {
                ctx.set_open(false);
            }
        }
    };
    let merged = merge_attributes(vec![base, attributes]);

    if let Some(dynamic) = r#as {
        dynamic.call(AsChild::new(merged, children))
    } else {
        rsx! {
            button { ..merged, {children} }
        }
    }
}

let mut open = use_signal(|| false);

Sheet {
    // Pair `open` with `on_open_change`: the sheet calls it when the user closes it, so it can close.
    open: open(),
    on_open_change: move |v| open.set(v),
    // Which edge to slide in from. Available sides: Top, Right (default), Bottom, Left.
    side: SheetSide::Right,
    SheetContentClose {}
    SheetHeader {
        SheetTitle { "Edit profile" }
        SheetDescription { "Make changes to your profile here. Click save when you're done." }
    }
    SheetFooter {
        SheetClose { "Close" }
    }
}

Component-Specific

What is particular to this component.

side is a typed prop. SheetSide is an alias of EdgeSide, the one side type the drawer uses too (DrawerSide is its other alias), and the panel is the theme's "Edge panel" recipe in dx-components-theme.css (data-dx-surface="edge" plus the resolved data-side): the <dialog> reset, the per-side inset, size, border and slide are written once for both components. A sheet defaults to Right, as shadcn's does; SheetSide::Auto is available (bottom below the md breakpoint, right at and above it) but not the default. A raw "data-side" attribute is still honoured and overrides the prop (Sidebar passes it).

Sheet follows Nova's panel padding of 0: the header, footer and body carry the inset (16px), not the panel -- so a title sits one header inset from the edge, not two.

The as prop renders a custom element while keeping the close behavior, as Radix's asChild does. The callback gets an AsChild: the attributes (the close onclick included) to spread on the element, and the children to render inside it.

// Default: renders as <button>
SheetClose { "Close" }

// Custom element
SheetClose {
    as: |el: AsChild| rsx! {
        a { href: "#", ..el.attributes, {el.children} }
    },
    "Go back"
}

This component's style.css follows shadcn/ui v4's Sheet (SheetHeader/SheetFooter/SheetTitle/SheetDescription/ SheetPrimitive.Close), translated onto this repo's own design tokens rather than copying Tailwind classes verbatim. There is no SheetOverlay or SheetContent element here: Sheet draws the scrim and the panel itself, and its children are the panel's content.

  • Overlay: fixed inset-0 bg-black/50 in shadcn; here the shared overlay scrim every modal uses. On the web build, .dx-sheet is a real <dialog> (primitives/src/dialog.rs's modal web arm), so the scrim is its native ::backdrop pseudo-element; the non-web (Blitz) arm has no such element, so .dx-sheet-root paints the same scrim for that arm.
  • Content: Nova's .cn-sheet-content: fixed z-50 flex flex-col gap-4 bg-popover text-sm shadow-lg, sliding in from its data-side with transition ease-in-out, a 500ms open / 300ms close duration (this repo's motion scale has no exact 500ms step, so that one value is a literal; 300ms matches --dx-motion-duration-slower exactly). right/left are inset-y-0 h-full w-3/4 border-l|border-r, capped at sm:max-w-sm (384px) only from a 640px viewport up, matching shadcn's own breakpoint-gated cap rather than applying it unconditionally. top/bottom are inset-x-0 h-auto border-b|border-t.
  • Header/Footer/Title/Description: flex flex-col gap-0.5 p-4 / mt-auto flex flex-col gap-2 p-4 / text-foreground text-base font-medium / text-muted-foreground text-sm (Nova's .cn-sheet-*). Tailwind's preflight resets heading sizes, which this repo has no equivalent of, so the title size is an explicit --dx-text-base.
  • Close button: Nova's ghost icon-sm Button at absolute top-3 right-3: a 28px square with min(radius-md, 12px) corners, a 16px icon, a muted hover fill and the Button focus ring, with an aria-label (this repo's equivalent of shadcn's visually-hidden "Close" span).
  • Native <dialog> centering defect (shared with Drawer): Chromium's dialog:modal UA stylesheet ships inset: 0; margin: auto; width/height: fit-content. Overriding only the one edge a given side needs (e.g. right: 0) leaves the UA's own inset: 0 still supplying the opposite edge uncontested, over-constraining the box against a definite width/height -- the UA resolves that by centering the panel into its own auto margins rather than anchoring it (a right/left sheet renders as a floating centered card, and a top/bottom sheet stretches to the full viewport height instead of sizing to its content). The theme avoids it by resetting margin/inset/width/height to a known, non-auto baseline in the theme's shared Edge panel recipe (for Sheet and Drawer alike) and letting each [data-side] rule reopen (set back to auto) exactly the one edge it doesn't pin.

A modal sheet dims the page behind it with the shared overlay scrim: the dialog's own ::backdrop, the same 10% black and 4px blur on every modal overlay. Pass overlay: false to keep the modality (focus trap, inert page, click-outside dismissal) without the dim and the blur; the <dialog> then carries data-dx-overlay="off".

Closing keeps the sheet a modal -- in the top layer, at the same size and place -- until its exit animation has played, and only then closes it. That holds in every browser; no stylesheet needs an engine-specific keep-alive.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • SheetProps: open with on_open_change; uncontrolled start value default_open.

The sheet slides in from its edge over 500 ms and out over --dx-motion-duration-slower; the durations are the --dx-edge-duration-enter/-exit slots' defaults in the theme's Edge panel recipe, and the scrim follows --dx-overlay-duration, --dx-overlay-ease, --dx-overlay-scrim and --dx-overlay-blur. The sheet stays open until its exit settles (at most 1500 ms) and only then closes, so the slide-out is always played. Its keyframes are the shared dx-edge-in-*/dx-edge-out-* pair in the theme, on translate like every other keyframe (no transform, so nothing is on the check-anchored-keyframes.sh allowlist). Reduced motion swaps in --dx-motion-duration-reduced. Nothing loops. See Motion for the tokens, reduced motion and the per-component table.

A component that composes this one retunes it by setting one of these custom properties on its own element, never by declaring the property on its own class: two stylesheets declaring one property on one element are decided by which sheet loads last, and that order differs from route to route. The component reads each variable with its own default, so a variable that is not set changes nothing. Custom properties inherit: set one on the exact element, not on an ancestor, or it reaches every nested instance too.

VariableDefaultPropertyDescription
--dx-sheet-backgroundvar(--dx-popover)background

background of the panel.

--dx-sheet-width75%width

width of a left or right panel. The panel's padding is the edge recipe's own --dx- edge-padding.
