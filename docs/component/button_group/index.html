Install

shadcn-dioxus add button_group

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

use crate::components::separator::Separator;
use dioxus::prelude::*;
use dioxus_primitives::dioxus_attributes::attributes;
use dioxus_primitives::merge_attributes;

/// The enclosing [`ButtonGroup`]'s orientation (`true` = vertical column),
/// published by context so a [`ButtonGroupSeparator`] derives its own
/// orientation from the group instead of being told it.
#[derive(Clone, Copy)]
struct GroupVertical(Signal<bool>);

/// Groups a row (or column) of [`Button`](crate::components::button::Button)s
/// so their borders/radii visually merge into one control, matching the
/// shadcn/ui `ButtonGroup`. Plain layout, `role="group"` -- no ARIA widget
/// pattern and no primitive underneath.
#[component]
pub fn ButtonGroup(
    /// Stacks the buttons in a column (`true`) instead of a row (`false`, the default).
    #[props(default)] orientation_vertical: bool,
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// The buttons and separators in the group.
    children: Element,
) -> Element {
    let base = attributes!(div { class: "dx-button-group", "data-dx-root": "" });
    let mut group_vertical = use_context_provider(|| GroupVertical(Signal::new(orientation_vertical)));
    if *group_vertical.0.peek() != orientation_vertical {
        group_vertical.0.set(orientation_vertical);
    }
    // `role="group"`/`data-orientation` are this wrapper's own required
    // semantics/typed-prop state, not a caller default -- owned-wins.
    let owned = attributes!(div {
        role: "group",
        "data-orientation": if orientation_vertical { "vertical" } else { "horizontal" },
    });
    let merged = merge_attributes(vec![base, attributes, owned]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/button_group/style.css") }
        div { ..merged, {children} }
    }
}

/// A visual divider between two clusters of buttons inside a
/// [`ButtonGroup`] -- e.g. separating a primary action from an overflow
/// menu trigger. Composes the themed [`Separator`]; Nova's
/// `ButtonGroupSeparator` is vertical by default, so here the orientation is
/// not a prop at all but always the group's cross axis (a vertical rule in a
/// row, a horizontal one in a column). A separator therefore can never be the
/// 100%-wide horizontal kind inside a horizontal flex row. Outside any
/// `ButtonGroup` it behaves as in a row group.
#[component]
pub fn ButtonGroupSeparator(
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
) -> Element {
    let base = attributes!(div {
        class: "dx-button-group-separator",
    });
    let merged = merge_attributes(vec![base, attributes]);
    let group_vertical = try_use_context::<GroupVertical>().is_some_and(|g| *g.0.read());

    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/button_group/style.css") }
        Separator {
            // Cross axis of the group: column group -> horizontal rule.
            horizontal: group_vertical,
            decorative: true,
            attributes: merged,
        }
    }
}

/// A static, non-interactive label chip inside a [`ButtonGroup`] -- e.g. a
/// unit ("px", "$") flanking an input-like control.
#[component]
pub fn ButtonGroupText(
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// The label text or unit, such as `px` or `$`.
    children: Element,
) -> Element {
    let base = attributes!(div { class: "dx-button-group-text" });
    let merged = merge_attributes(vec![base, attributes]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/button_group/style.css") }
        div { ..merged, {children} }
    }
}

The Button Group component visually merges a row (or column) of Buttons into one control -- shared borders, and only the outer corners rounded.

ButtonGroup {
    Button { variant: ButtonVariant::Outline, "Archive" }
    Button { variant: ButtonVariant::Outline, "Report" }
    // A visual divider between two clusters of buttons.
    ButtonGroupSeparator {}
    Button { variant: ButtonVariant::Outline, "..." }
}

ButtonGroup joins whatever it holds, not just Button: Input, Select, NativeSelect, and the DropdownMenu and Popover triggers (which sit inside a wrapper <div>) all get flat seams and shared borders. It does this without styling any of them. On each direct child it sets four inheritable custom properties by position, and each joinable control's own stylesheet reads them with its normal radius as the fallback, so a control outside a group is unchanged.

VariableSet onFlattens
--dx-group-radius-start-startnon-first child (horizontal) / non-first child (vertical)block-start, inline-start corner
--dx-group-radius-end-startnon-first child (horizontal) / non-last child (vertical)block-end, inline-start corner
--dx-group-radius-start-endnon-last child (horizontal) / non-first child (vertical)block-start, inline-end corner
--dx-group-radius-end-endnon-last child (horizontal) / non-last child (vertical)block-end, inline-end corner

The names are logical corners, so a right-to-left group mirrors with no extra rule. Overlay content ([popover], dialog, role="dialog" | "menu" | "listbox" | "tooltip") resets the four variables, so a Button or Input inside a popover panel does not inherit its trigger's seam. The 1px overlap between neighbours is a negative margin on the group's own direct child (the wrapper, when there is one).

A control that should join a group reads them in its own stylesheet:

border-start-start-radius: var(--dx-group-radius-start-start, var(--dx-radius-lg));
border-start-end-radius: var(--dx-group-radius-start-end, var(--dx-radius-lg));
border-end-start-radius: var(--dx-group-radius-end-start, var(--dx-radius-lg));
border-end-end-radius: var(--dx-group-radius-end-end, var(--dx-radius-lg));

Examples

Alternative examples for common configurations.

orientation

A vertical group of icon buttons: orientation_vertical stacks them and merges the shared edges.

nested

A group of groups: page numbers in one ButtonGroup, the previous and next arrows in another, side by side.

separator

A ButtonGroupSeparator dividing two buttons.

split

A secondary button plus a chevron button that opens a dropdown menu of related actions.

with input

A text input and a button sharing one group.

dropdown

A button joined to an overflow button that opens a dropdown menu; the trigger joins the group's seam through the --dx-group-radius-* variables.

select

A currency select, an amount input and a button in one group. The select is a NativeSelect so the server-rendered and hydrated widths agree.

popover

A button joined to a chevron PopoverTrigger that opens a popover panel.

RTL

A pagination-style group under right-to-left text direction: the borders and radii mirror, so the first button sits on the right.
