Component

context menu

Install

A context menu component for displaying a list of actions or option after right clicking an area.

right click here

Basic

The context menu component can be used to define a context menu that is displayed when the user right-clicks on an element. It can contain various menu items that the user can interact with.

shadcn-dioxus add context_menu

Also adds the components and crates this one needs. First time in this app? Set up the CLI and your app first.

Copy the component source and CSS into your app. Import the shared theme CSS once near your app root.

/// Themed wrapper for [`context_menu::ContextMenuSubTrigger`]. Carries both

        document::Link { rel: "stylesheet", href: asset!("/src/components/context_menu/style.css") }

}

/// A non-interactive heading for a group of items -- shadcn's
/// `ContextMenuLabel`. Pure presentation (the primitive has no label
/// component): give it an `id` and point a [`ContextMenuRadioGroup`]'s
/// `aria-labelledby` at it so the group is named.
#[component]
pub fn ContextMenuLabel(
    /// Reserves the leading indicator slot -- shadcn's `inset` -- so the heading
    /// lines up with inset items. Carries `data-inset="true"`.
    #[props(default)]
    inset: bool,
    #[props(extends = GlobalAttributes)] attributes: Vec<Attribute>,
    /// The label text.
    children: Element,
) -> Element {
    let base = attributes!(div {
        class: "dx-context-menu-label",
        "data-dx-menu-label": "true",
    });
    let inset_attr = attributes!(div {
        "data-inset": inset.then_some("true"),
    });
    let merged = merge_attributes(vec![base, attributes, inset_attr]);
    rsx! {
        document::Link { rel: "stylesheet", href: asset!("/src/components/context_menu/style.css") }
        div { ..merged, {children} }
    }
}

// The context menu component must wrap all context menu items.
ContextMenu {
    // The context menu trigger is the element that will display the context menu when right-clicked.
    ContextMenuTrigger {
        // The content of the trigger
        "Right-click here"
    }
    // The context menu content contains all the items that will be displayed in the context menu.
    ContextMenuContent {
        // Each context menu item represents an individual action in the context menu. Arrow keys move through the items in document order.
        ContextMenuItem {
            // The value of the item which will be passed to the on_select callback when the item is selected.
            value: "open".to_string(),
            on_select: |value: String| {
                // This callback is triggered when the item is selected.
                // The value parameter contains the value of the selected item.
            },
            "Open"
        }
    }
}

ContextMenuContentRendered Primitive

The menu panel. In the browser arm it is promoted to the top layer via popover="manual", so it escapes clipping and transformed ancestors the same way DropdownMenuContentRendered does (dropdown_menu.rs); without the popover API it is a plain position: fixed div.

The menu opens at a document point (ContextMenuCtx::position, the press's pageX/pageY), with no trigger element to anchor to (anchor-name/position-anchor are never wired up for it). top_layer::use_point_anchor_placement places it with the same script as every anchored overlay (rule P, backlog row 477): the point is a zero-size anchor, the menu is absolute in the top layer and moved by transform, so it stays at that point of the document when the page scrolls, opens upward or leftward when the room below or to the right is short, and is capped to the room left. Until the script takes the panel over it is position: fixed at the press's client point: a focus move into a panel that is not placed yet must not scroll the document to it.

manual (not auto) is also the dismissal decision: auto's native light dismiss (Escape, outside pointerdown) would race this component's own dismiss layer, which implements APG's exact close-and-refocus semantics (Radix's onCloseAutoFocus, interacted_outside distinguishing an outside dismiss from an internal one -- see ContextMenuCtx::interacted_outside's doc). A native light dismiss has no way to tell Rust why it closed, so marking every native close as an outside interaction would silently break use_refocus_on_close_unless's Escape/select refocus. A manual popover is never closed by the platform on its own, so the dismiss layer stays the only dismissal path, and the toggle echo of use_menu_panel only ever repeats a close this crate already made.

idStringrequired

The DOM id of the menu's content element.

attributesVec<Attribute>required

Extra HTML attributes for the menu's content element.

scroll_lock_activeMemo<bool>required

Whether page scrolling is locked while the menu is open. True only for an open modal menu.

childrenElementempty

The menu items.

PropTypeDefaultDescription
valueTrequired

The value of the item, which is passed to the on_select callback when the item is selected.

indexusizeNone

The item's place in keyboard order. Leave it unset: items are ordered as they are created, which is tree order. Set it on every item only when one is inserted between items that are already mounted, or a keyed list reorders them.

disabledboolfalse

Whether the item is disabled. A disabled item cannot be selected and is skipped by roving focus and typeahead. Defaults to false.

text_valueStringNone

Explicit label text used for typeahead search (APG's "Any key that corresponds to a printable character" rule). When not set, falls back to Self::value's own String/&str representation if it has one, else this item is not searchable by typeahead at all -- Select uses the identical fallback for its own generic item value.

on_selectCallback<T>no-op

The callback function that is called when the item is selected. The value of the item is passed as an argument.

variantMenuItemVariantDefault::default()

Whether the item is drawn in the destructive ink -- shadcn's variant="destructive". The role stays menuitem; the item carries data-variant. See MenuItemVariant.

insetboolfalse

Reserves the leading indicator slot without drawing anything -- shadcn's inset -- so a menu that mixes plain and checkable items keeps its labels on one edge. The item carries data-inset="true".

childrenElementempty

The children of the item, which are rendered inside the item element.

Component-Specific

A ContextMenuContent may nest a submenu with ContextMenuSub/ ContextMenuSubTrigger/ContextMenuSubContent/ContextMenuSubItem, the same APG "Menu and Menubar" pattern submenu contract dropdown_menu's DropdownMenuSub implements (ArrowRight/Enter/Space opens and moves focus to the first item; Escape/ArrowLeft closes and returns focus to the sub-trigger; the parent menu stays open). A submenu may hold plain items but not a further nested submenu of its own (one level of nesting).

ContextMenuContent {
    ContextMenuSub {
        // The sub-trigger is itself an item of the enclosing menu, in its
        // keyboard order like `ContextMenuItem`.
        ContextMenuSubTrigger {
            "More tools"
        }
        // Only rendered while the submenu is open.
        ContextMenuSubContent {
            ContextMenuSubItem {
                value: "duplicate".to_string(),
                on_select: |value: String| {
                    // Selecting a sub-item closes the entire menu tree,
                    // not just this submenu.
                },
            }
        }
    }
}

Open on hover, or click only

By default hovering a ContextMenuSubTrigger opens its submenu after a short delay (100 ms) and leaving it closes the submenu again after a short grace delay. Pass open_on_hover: false to the ContextMenuSub for click activation:

ContextMenuSub {
    // Default is `true`.
    open_on_hover: false,
    ContextMenuSubTrigger { "Export as" }
    ContextMenuSubContent { /* ... */ }
}

The submenu then opens only on click, Enter, Space or the open arrow key, and the pointer never opens or closes it. Same semantics, and the same openOnHover naming, as DropdownMenuSub -- see that component's note. See the click_only_submenu variant.

ContextMenuCheckboxItem and ContextMenuRadioGroup + ContextMenuRadioItem are shadcn's ContextMenuCheckboxItem/ContextMenuRadioGroup/ContextMenuRadioItem. They render role="menuitemcheckbox" / role="menuitemradio" with an always-present aria-checked; radio items sit in a role="group" (name it with aria-label or aria-labelledby). They work in a ContextMenuContent and in a ContextMenuSubContent.

let mut show_status_bar = use_signal(|| false);
let mut position = use_signal(|| "top".to_string());

ContextMenuContent {
    ContextMenuCheckboxItem {
        // Controlled: `checked` + `on_checked_change`. Uncontrolled:
        // `default_checked` -- but note the content unmounts when the menu
        // closes, so an uncontrolled item starts over on every open.
        checked: Some(show_status_bar()),
        on_checked_change: move |checked| show_status_bar.set(checked),
        // The menu stays open after a toggle by default (Base UI's
        // `closeOnClick = false`), so several items can be set in one visit.
        // `true` closes it on selection (Radix's `onSelect` behaviour).
        close_on_select: true,
        // A checkbox item has no `value`: set `text_value` to make it a
        // typeahead target.
        text_value: "Status Bar",
        "Status Bar"
    }
    ContextMenuRadioGroup {
        aria_label: "Panel position",
        value: Some(position()),
        on_value_change: move |value| position.set(value),
        // A radio item's `value` is also its typeahead label.
        ContextMenuRadioItem { value: "top".to_string(), "Top" }
        ContextMenuRadioItem { value: "bottom".to_string(), "Bottom" }
    }
}

Click, Enter and Space all select. A disabled item cannot be selected and is skipped by arrow keys and typeahead. The check is drawn at the inline end, in a slot the item reserves (the same --dx-menu-item-indicator-* construction as the sub-trigger chevron), so a long label never meets it and an unchecked item does not shift its label. See the checkboxes and radio_group variants.

Built once in primitives/src/menu_item.rs and shared with the other two menus, these are shadcn's ContextMenu parts:

ContextMenuContent {
    ContextMenuGroup {
        ContextMenuLabel { "My Account" }
        ContextMenuItem {
            value: "profile".to_string(),
            // Items take `variant` and `inset`, like shadcn's `variant="destructive"` / `inset`.
            "Profile"
            // A text-only hint pushed to the inline end of the row; it binds no key.
            ContextMenuShortcut { "⇧⌘P" }
        }
    }
    // A divider between groups: `role="separator"`, not focusable, skipped by arrow keys and typeahead.
    ContextMenuSeparator {}
    ContextMenuItem {
        value: "delete".to_string(),
        variant: MenuItemVariant::Destructive,
        "Delete"
    }
}
  • variant (MenuItemVariant::Default or Destructive) paints the item in the theme's destructive text colour with a destructive-tinted highlight. The role stays menuitem and the item carries data-variant.
  • inset reserves the leading indicator slot on an item (or ContextMenuLabel) that draws none, so a menu that mixes plain and checkable items keeps its labels on one edge. It also exists on the checkbox and radio items and, where the menu has submenus, on the sub-trigger. The element carries data-inset="true".
  • ContextMenuGroup is a role="group" with no behaviour; items inside it stay in the whole menu's keyboard order. Name it with aria-label when it has a visible heading.

See the groups and destructive variants.

An open ContextMenu locks page scrolling (wheel, touch, keyboard and scrollbar), as a native context menu does. The scrollbar keeps its width, so nothing shifts, and the page returns to the position it had when the menu closes. DropdownMenu does not lock; see its note.

Some props here come in controlled pairs. Controlled and uncontrolled state says how they work, and what freezes a component.

  • ContextMenuProps: open with on_open_change; uncontrolled start value default_open.
  • MenuSubProps: open with on_open_change; uncontrolled start value default_open.
  • MenuCheckboxItemProps: checked with on_checked_change; uncontrolled start value default_checked.
  • MenuRadioGroupProps: value with on_value_change; uncontrolled start value default_value.

The menu panel animates in and out over --dx-motion-duration-base with --dx-motion-ease-out / --dx-motion-ease-in, in opacity, scale and translate only (never transform); item highlights use --dx-motion-duration-fast. Retune with those tokens. Reduced motion swaps in --dx-motion-duration-reduced. Nothing loops. See Motion for the tokens, reduced motion and the per-component table.

ContextMenu accepts a dir: Option<Direction> prop, inherited by every ContextMenuSub. Same open/close-key and side flip as DropdownMenu's -- see that component's note. See the rtl variant.
